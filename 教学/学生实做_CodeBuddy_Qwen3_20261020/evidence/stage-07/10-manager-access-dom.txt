判定函数 strictCapability(value)：value === true 才是“允许”。
能力值来自服务端响应；字符串 "true"、数字 1、null、undefined 与缺失字段都不是“允许”。 判定基于字段值本身，与 roles 数组无关。
能力	字段	当前值	判定	对应入口

读取校园数据
	
canRead
	true	允许	GET /api/campus/**；401 与 403 分开处理

控制设备
	
canControl
	false	不据此授权	远端控制与外部通知关闭，服务端恒为 false

维护位置
	
canAdmin
	false	不据此授权	创建校园/楼栋、绑定空间等写入口

查看命令审计
	
canAudit
	false	不据此授权	GET /api/campus/command-audit

处理事件
	
canHandleAlarms
	true	允许	开始/记录/核实/关闭；CAMPUS_MANAGER 仅限本人被分派的事件

分派事件
	
canAssignAlarms
	false	不据此授权	把事件分派给处理人

触发演练场景
	
canRunDemoScenarios
	false	不据此授权	本地 DEMO 演练，仅在演示开启时允许

能力在 api/auth.ts 边界已用 strictCapability 逐项归一化，本页用同一函数再次判定； 403 表示服务端按当前角色拒绝，隐藏按钮不能代替 403；401 表示会话失效，需退出后重新登录。 身份切换时 store 会清空旧 user、capabilities 与设备数据。
