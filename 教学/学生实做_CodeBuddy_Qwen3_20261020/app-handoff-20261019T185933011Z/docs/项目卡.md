# 第04站 Ask 结论（操作者据 CodeBuddy 回答摘录）

校园 id/name → 楼栋 id/name/campusId；来源空间只读 id/name，通过绑定 spaceId/buildingId/floor 关联，campusId由楼栋推导。先建校园，再建楼栋，最后绑定已有来源空间。不存在的楼栋或空间应404并保持旧关系；只有 canAdmin === true 显示保存入口，后端最终鉴权。

# 第05站 Ask 结论（操作者摘录）

按空间查看设备数，点击空间统计回台账；按quality筛出缺失/陈旧点，保留deviceId/tagId以追溯原设备；能源按unit同单位比较，kW不当kWh，不计算电费或节能率。数据取overview实际响应，未知不补零。

# 第06站 Ask 结论（操作者摘录）

历史必须带deviceId、tagId、from、to，毫秒时间范围最多6小时。null在原采样时刻断线，0为有效样本。原始报警只读保留status/level，与本地演练事件并列，不用演练状态替换上游状态。

# 第07站 Ask 结论（操作者摘录）

admin可读取、维护位置、处理事件和看接入状态；manager-a可读取并只处理本人分派事件，不能维护位置或看接入；viewer只读，不能写及查看管理员接入状态。前端能力仅Boolean true授权，roles仅显示，后端最终判定。

# 第08站 Ask 结论（操作者摘录，均为预期规则）

ADMIN触发创建NEW/version1；ADMIN分派后ASSIGNED/version+1；管理员或本人被分派manager开始后IN_PROGRESS/version+1；追加NOTE保持处理中但version+1。业务state与来源sourceState分开。旧expectedVersion返回409，回读后人工重判，不自动重放。B不能办理A的事件。

# 第09站 Ask 结论（操作者摘录）

关闭要求：处理中、人工NOTE、来源已恢复、发生/恢复/核实时刻合法、恢复后服务端核实PASS、非空结论、当前expectedVersion、管理员或本人处理人权限。DEMO_RECOVER/VERIFY_RECOVERY不算NOTE。任何缺项由既有后端拒绝，前端检查只是辅助，不改现有服务端规则或拒绝顺序。

# 第10站 Ask 结论（操作者摘录）

设备负责人A改B后，旧事件assigneeUid保留A；之后新触发事件按当时负责人快照自动分派B。若B无资格则新事件待分派，不回退A。两人读取同一责任version后，先保存者version+1，后保存的旧expectedVersion返回409，不覆盖；回读后人工决定再提交。
