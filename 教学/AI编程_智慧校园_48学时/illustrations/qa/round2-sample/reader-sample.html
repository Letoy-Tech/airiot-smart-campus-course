一 课程定位

课程名称为“AI 编程——以智慧校园平台重建为例”。面向学过一门编程语言、尚无完整项目经验的学生，课内 48 学时。学生使用通义等国内网页聊天工具，以 Qwen3 系列为模型案例，由自己完成文件编辑、命令执行、结果核验和版本提交。

课程要培养的是借助 AI 完成软件工程任务的能力。平台本身不要求接入聊天机器人、训练大模型或部署推理服务。学生要能说清系统解决什么问题、数据从哪里来、业务规则为何这样设计、生成的代码如何验证，以及别人怎样接手。

参考对象是现有智慧校园系统，采用 Vue 3 与 Java Spring Boot 的前后端结构。教学作品保留核心业务和工程约束，学生可自行设计 UI、布局和视觉风格。参考系统不作为全量复制任务，也不以代码相似度评分。

三 48 学时结构

各章按“概念与问题 1 学时、项目实践 2 学时、核验与接力 1 学时”组织，共 12×4=48 学时。具体课次可以拆为两次 2 学时；此处不把学时换算为分钟。安装检查安排在开课准备阶段，第 04 章仍预留环境排障和版本管理时间。

四 必修作品与进阶作品

基础作品必须能在没有 AIRIOT 账号、没有模型 API Key 的环境中完成。数据来自显式标识的教学模拟组件；事件与责任登记写入学生自己的数据库。

**必修业务：**设备列表与筛选、空间映射、最新采集值与一类历史曲线、三角色权限、演练事件闭环、设备责任登记、相关时间线及交付文档。概览由这些数据汇总而来；能源展示仅作为已有电压或功率点的视图，不新增费用计算。原始报警保留只读合同和教师参考组件，其页面扩展及真实接入作为选做，不新增必修作业。

**教师提供的基础：**依赖冻结的工程骨架、认证底层、最小账户数据、模拟数据组件、数据库环境与测试入口。学生需要阅读基础组件的边界，亲自补充校园业务授权和拒绝测试；提供基础并不等于提供全部业务答案。

**进阶选做：**真实 AIRIOT 只读适配、更多图表与页面、复杂查询、自动化持续集成、隔离部署与恢复，以及对网页 AI 与编码工具的比较。进阶不占必修 48 学时，不以付费账号、服务器或硬件作为获得高基础成绩的条件。

通用用户管理后台、复杂权限配置台、完整审计运营台、远端设备控制和外部通知不要求学生从零重建。它们可作为参考组件或后续课程内容。

五 项目推进方式

采用短迭代：每次提出一个可检查的变化，学生先给出自己的理解，再请 AI 提供方案，完成局部代码、运行、评审和提交。网页 AI 不读取本地仓库，学生负责把准确的文件和运行证据提供给它。

建议两人一组，轮换“实现者”和“审查者”，双方都要完成可归属的代码与核验记录。允许独立完成；团队规模不影响必修范围。每位学生保留个人 AI 使用记录并单独答辩。

六 学时负担与降级方法

48 学时的可行性依赖教师先完成并验证脚手架。若要求学生同时从零学习 Java、Vue、SQL、认证框架、部署和 AIRIOT，课程负担会超过当前设计。

课堂落后时，先压缩装饰动画、额外图表、通用后台和进阶接入；保留设备读取、后端授权、事件关闭规则、版本冲突、测试和交接。提供章节检查点供学生定位差异，使用救援检查点须记录使用原因，再独立解释和补做关键改动。不能用整套成品覆盖作业来冒充完成过程。

课后安排以巩固、阅读和整理证据为主。核心评分项目应能在课内完成；若试讲显示需要大量额外编码时间，应缩减功能或增加教师模板，不能把超载静默转移给学生。

本文件规定课程各章使用的共同语义，是教学版待实现的合同基线。原始参考为 现有系统接口合同需原项目。本文没有生成可运行 API，也不修改原系统合同。

通用约定

成功响应使用 {code:0,message,data}；HTTP 状态与业务状态分开。参数无效 400、身份无效 401、权限不足 403、对象不存在 404、版本或状态冲突 409。上游异常由后端转为适当的 502/503，不转成前端登录过期。

读取接口均在认证后的校园角色范围内。学生第一次贯通使用教师准备的教学登录基础；临时调试身份不能成为交付时绕过认证的入口。身份、操作者和系统时间由后端确定，不相信前端提交的 actor 或时间。

所有时间为 epoch 毫秒；布尔权限只有 JSON Boolean true 授权；分页、时间窗和字段类型明确校验。响应不得出现 API Key、token 或密码。

教学版与现有合同的明确差异

source 扩展为 TEACHING_MOCK | AIRIOT，并同步后端 DTO、前端类型和测试。模拟实现返回 TEACHING_MOCK，真实适配返回 AIRIOT。模拟对象另标 simulated:true，二者不可互相替代。其余核心字段和规则尽量保持参考合同语义。

教学历史样本显式扩展为 HistorySample={time:number,value:number|null}。time 是有效的 epoch 毫秒整数；value 是有限数值，或来源明确返回的缺失标记 null。Java 教学 DTO 使用 Double 表达可空值，TypeScript 使用 number | null。现有参考系统的 CampusDtos.Sample 为 double、HistoryResult.samples.value 为 number，不能直接复制为本课程的类型；这属于教学版的明确差异，尚未在教学工程实施。

有时间、无数值的原始样本保留为 null 断点，不算有效测量，也不补零。完全没有返回样本的时刻不创建记录。字符串数值、布尔值及非法时间不冒充合法样本；非有限数值不能写成 JSON 的 NaN 或 Infinity。数据源适配层应拒绝或按冻结的异常规则报告非法输入，不能无说明地转成 null。详细异常条目结构及过滤顺序在资源制作时冻结。

数据源接口建议定义六项读取能力：空间、设备、最新点值、历史、原始报警、接入状态。业务服务依赖端口，不在前端直接请求 AIRIOT。实际 Java 方法签名在脚手架制作时冻结，所有章节随之更新。

空间写入的错误语义也按教学合同统一：格式正确但引用的校园、楼栋或空间不存在，返回 404；空名称或不合法字段返回 400。现有参考 CampusLocationService 对部分不存在引用返回 400，移植为教学版时须连同测试改为上述规则。此差异不修改原平台，也不把名称判空等参数错误改成 404。

状态和并发

事件业务状态为 NEW、ASSIGNED、IN_PROGRESS、CLOSED；来源状态为 ACTIVE、RECOVERED、UNKNOWN，两类状态分别保存。触发场景创建独立 DEMO/LOCAL_DEMO 事件；有有效设备责任人时可以自动进入 ASSIGNED。

关闭需同时满足：处理中；至少一条处置记录；演练来源已经恢复；服务端独立核实 PASS 且核实时间有效；有非空结论；操作者获准；expectedVersion 匹配。已关闭事件不可修改。重新分派未关闭事件回到 ASSIGNED，旧记录保留，新负责人重新开始。

expectedVersion 为非负 JSON 整数，不接受字符串或布尔值。写操作在同一数据库事务中锁定当前记录、核对版本、修改主记录并追加时间线；旧版本返回 409。该参考方案是行锁配合版本检查，不能在讲义中误称纯乐观锁更新。教师也可设计有充分测试的替代方案，但需统一合同和实现解释。

版本字段仅适用于合同规定的事件更新与责任登记。场景触发为空 body 或 {}，创建版本为 1。版本匹配、未关闭且已经恢复的事件再次执行恢复，返回当前详情，不重复增加版本或时间线；关闭后的事件仍禁止修改。

设备责任初始 version 为 0；修改后递增并保存时间线。责任人变更影响未来事件的自动分派，不改写已经生成事件的 assignee。并发冲突和时间线失败回滚需真实数据库证据。

评价什么

评价学生能否把问题变成可验证的软件，以及是否理解并检查 AI 参与的改动。作品可采用不同 UI；大模型品牌、账号付费档位和是否完成 AIRIOT 接入不影响基础评分的公平性。

评分建议

维度 分值 主要评价内容
需求与设计 20 范围和角色清楚；规则可验证；接口、数据和状态一致；决策有依据
核心功能 25 设备、监测、权限、事件、责任和时间线形成可演示业务闭环
测试与交付 20 边界和拒绝场景、真实数据库证据、缺陷回归、他人复现
个人 AI 协作 15 上下文准确；小任务分解；识别错误；核验及接力记录真实
个人理解与答辩 20 能解释代码、预测行为、定位故障并完成小变更
合计 100 前三项可用小组成果，后两项按个人评价

进阶作品在所属维度内体现深度，不另设只有付费或接入真实平台才能获得的分数。做完基础任务并有充分证据，可获得该维度满分。具体分数由任课教师按学校要求确定。

评分尺度与反馈写法

每个维度按“证据是否充分、能否独立解释”判断，不按代码行数或聊天次数累加。下表提供评分锚点，教师可在维度分值内给分；它不是学校的统一等级或及格规定。

维度 证据充分时应看到 部分完成的典型情况 反馈应指出的下一步
需求与设计 20 一条需求可追到合同、任务与验收，范围外功能说明清楚 有图和术语，但找不到对应规则 指出一条缺失的映射并要求补齐
核心功能 25 必修闭环可演示，成功与拒绝行为均符合规则 成功页面可用，但关键失败路径缺失 指明未满足的 AC 编号及最小修复
测试与交付 20 预期独立于实现；数据库证据和他人复现有记录 只有截图或单元测试，结论却覆盖整个系统 缩小结论并补缺少的证据层
个人 AI 协作 15 能展示一项采纳/修订/拒绝建议及人工核验依据 只保存整段回答，不能指出自己如何判断 选一个小改动，对照规则和实际结果说明
个人理解与答辩 20 能追踪数据、预测反例，并在限定范围完成小修改 能背概念，无法定位对应文件或分支 从一个输入沿代码解释到输出，再复核修改

例如，历史页截图有一条曲线只能支持“页面可显示曲线”。若缺少 null 样本表、有效零与断点对照，AC04 仍缺证据；教师应写明缺项，不能仅因页面漂亮判满分，也不能把其余已证明的成绩一并抹去。课内每章提交一份任务单，已有日志以路径引用，不重复制作多套报告。正文的练习用于选讲和自查，不全部叠加为必交作业。

必修验收基线

以下是学生未来必须执行的检查清单，当前文档包没有产生这些运行结果。

编号 验收场景 通过条件 建议证据
AC01 教学数据读取 数量来自实际结果；显示模拟来源；不依赖 AIRIOT 账号 API 返回与页面
AC02 空间映射保存 合法关联持久化，刷新保留；非法关联被拒绝 请求、回读和失败记录
AC03 最新值与质量 有效零、缺失、过期、无效可区分；未知通信状态不当作离线 固定夹具与页面
AC04 历史曲线 时间范围合法；同单位；不补零插值；空、失败、截断有说明 样本表与曲线对照
AC05 角色授权 三角色符合矩阵；隐藏按钮后直接写请求仍被后端拒绝 API 拒绝测试
AC06 本人范围 管理人员不能操作他人事件；失效身份不能继续修改 身份与对象交叉用例
AC07 事件闭环 分派、开始、记录、恢复、核实、关闭均满足规则 刷新后的持久化时间线
AC08 版本冲突 分别检验责任变更和事件 NOTE：两请求携带同一当前版本 n 并发提交，恰有一个成功、一个 409 VERSION_CONFLICT；版本只加一、各自时间线只增加一条 两组真实 MySQL 并发记录；顺序提交旧版本不替代并发
AC09 事务回滚 分别对事件更新与责任变更执行：请求确已更新主行、命中指定时间线故障并因异常回滚；主记录和时间线独立回读均不变 两组各自的关联标识、更新行数、故障命中、事务失败及MySQL前后回读；各组正常对照；400/403/409提前拒绝不算回滚证据
AC10 责任变更 负责人有效；新事件按新责任人分派；旧事件不被偷偷改派 两次责任与事件对照
AC11 前端可靠性 请求失败保留输入；不假报成功；刷新停止及加载状态正确 浏览器操作与网络证据
AC12 他人复现 同学按交付说明在独立环境完成启动与核心流程 复现者签记与问题单

若关键授权、状态规则或回滚失败，核心功能验收记为待修复，不能用 UI 美观或更多功能抵消。教师根据该项实际完成程度评分；不虚构学校统一的“一票否决”政策。

独立预期与避免同源错误

测试预期先来自需求规则和教师固定样例，再让 AI 协助生成测试代码。不能让 AI 根据有缺陷的实现推导同样错误的预期；也不能为了让测试全绿而删掉拒绝或冲突用例。

每组至少呈现一个 AI 建议被修正或被拒绝的实例，说明证据和影响。若确实没有发现错误，可以审查教师准备的缺陷样例，不要求学生伪造一次 AI 失误。

证据等级

文档设计、编译构建、单元测试、真实数据库集成、API 验证、浏览器流程、外部接入是不同层次。报告分别列出执行日期、环境、版本、命令、实际结果和缺口。通过构建不能代替浏览器验收；mock 测试不能代替数据库锁和事务验证；接入状态为 connected 不能代替全部 AIRIOT 业务验收。

证据只收集教学数据和脱敏日志。每位学生使用自己的教学账号，提交中不包含密码、会话 token、真实 API Key 或个人隐私数据。

答辩题示例

  1. 页面把空值显示成 0，会对使用者造成什么误解？指出代码中的对应处理。
  2. 如果只把“关闭事件”按钮隐藏，为什么不能证明查看者没有关闭权限？
  3. 两个管理员同时修改责任人，后端怎样判断冲突？前端遇到 409 后应该怎么做？
  4. 来源恢复和事件关闭为什么分开？指出缺少处置记录时的拒绝条件。
  5. 展示一次 AI 的建议、你的判断和实际测试；若换一个模型，哪些证据仍然有效？
  6. 现场增加一项小筛选条件，说明需要更新哪些合同、代码和测试。

最终交付清单

源代码与锁文件；无真实秘密的配置样例；运行和停止说明；教学数据版本；需求、架构、接口及决策记录；测试与缺陷报告；AI 代表性协作记录；当前交接和已知限制。压缩包和仓库都可作为交付形式，采用哪种形式不影响验收标准。

让学生做业务判断，让重复配置有统一起点

学生学过的语言可能不是 Java 或 JavaScript。课前用变量、条件、函数、数组四个小题了解基础；进入相关章节时再用正文短例解释 JSON、类型、组件和请求。不能把“学过一门语言”理解为已经掌握整个前后端框架，也不另加一门隐形的课后必修课。

开课准备阶段完成工具和资源预检。第 04 章处理已核对环境中的局部排障，不承接全班从零安装所有依赖的工作。若预检未完成，教师先处理资源条件，不能以缺少未提供资源扣学生工程实现分。

章 教师预制或承接材料 学生课内主要修改 本章结束时的最小证据
01 本章短例、离线缺陷回答 修订一份台账需求和一次 AI 反馈 三态判断、采纳/拒绝理由、接力记录
02 范围、角色及任务卡样例 写一个完整故事、反例与相邻小任务 需求—验收—任务对应；其余故事用模板评审
03 全局架构/ER/状态图和读取 JSON 标注一空间两设备响应，说明读取链路与字段 一份读合同；能逐层找到设备名和 null
04 已验证环境、认证、最小读取桩与页面 TODO 接入一次设备读取及显示，观察一次失败并恢复 true/null 设备链路、Network 和局部差异
05 控制器/服务/Mapper 空模板、迁移与测试入口 读取查询、创建校验、本地空间关系校验 正常写入后回读；非法关联和只读身份被拒绝
06 Vue 页面/路由/请求与类型基础 筛选、三态显示、空/失败分支和详情定位 UI 自主设计；结果 ID、三态与清除操作正确
07 可控时钟、单点样本、图表与请求生命周期骨架 质量解释、原始数据映射、断点和结果接收判断 一类曲线对应原始表；零/空、失败和离页可区分
08 认证、四身份、角色恢复工具、可控响应延迟 能力严格布尔、后端授权、旧响应拒收规则 直接越权请求拒绝；跨身份和同身份竞态记录
09 七类动作路由/DTO/事务模板、独立规则夹具 状态、本人范围、关闭条件、版本冲突分支 正常闭环账本；可达反例和规则夹具分开记录

12 既有构建入口、交付清单和筛选变更需求 整理交付、完成有限变更、交叉复现及解释 同伴复现、变更回归和个人答辩记录

第 03 章的 ER、事件状态、版本与事务用于认识后续对象，不要求此时实现或重画全部设计。第 09、11 章再完成对应实现与证据。第 04 章的独立函数三态练习与页面 true/null 观察分开，完整页面三态在第 06 章验证。这样安排降低首次学习负担，不减少最终业务标准。

一章只追踪一个任务单

使用课堂任务单保存本章目标、文件变化、输入、预期与实际。截图、日志和测试输出只引用已有证据路径。每个主要任务遵循“先预测一个输入 → 修改一个局部 → 看实际结果 → 修正或交接”。先走最小成功路径，再验证一个明确的拒绝或异常；后面的用例逐步复用同一基线。

教师展示骨架时应打开学生要修改的真实文件，指出已有部分、TODO、调用入口和检查入口。拟定文件名必须在资源包发布时映射到真实路径。若找不到入口，应停止让 AI 猜路径，由教师修正资源映射表。

两人一组时，在模块二轮换实现与审查，模块三各自解释一个判断和一条证据。共享日志不等于共享理解；个人评分仍按自己的判断、修改和答辩。独立完成者采用同一任务和验收标准。

超时先处理什么

现象 本章处理 保留的关键要求
环境或依赖未就绪 登记资源阻塞，使用纸面/独立短例练习；教师修复资源 不把纸面推演记成实验通过
重复配置占去实践时间 提供经过验证的请求、路由、表单或测试骨架，标明来源 业务规则、学生 TODO 和人工解释仍由学生完成
UI 美化耗时 先使用普通表格与文字状态，再做视觉调整 来源、空值、失败、权限与核心交互
复杂内容同时出现 先完成本章任务卡，再读预告和扩展 后续章节仍按 AC 完成状态、并发和回滚
临近结束还没通过 保存当前差异和失败证据，明确下一检查；使用救援检查点时注明 不拿完整答案覆盖后声称独立完成

课后以整理和自查为主；正文的练习与扩展不全部转成新增必交作业。如果试讲发现必修仍需大量课外编码，应减少重复实现、改进教师模板并重新计时。不能仅修改文档为“4 学时”就宣布负担已验证。

转正式实验前要补齐的四项记录

  1. **入口映射：**每个学生 TODO 对应真实文件、起始检查点、目标检查点和运行入口。
  2. **输入与答案：**固定数据、故障前提、预测结果与教师实测结果分栏；正文示例不直接填入实际结果。
  3. **耗时记录：**每个模块实际用时、卡点和教师介入次数；新手复现与作者自测分开。
  4. **资源恢复：**每组数据和账号怎样恢复到本章起点，恢复只作用于该组；证据保留后再恢复。

Qwen 与网页工具说明

资料内定位展开后选择本次内容
  • 区分产品模型与工具
  • 学生如何开始
  • 一次课堂工具检查
  • 可选接入路线

核对日期：2026-10-18。本课程用网页对话支持软件工程学习，以 Qwen3 为模型案例；工具和型号可变，项目合同、学生理解和运行证据保持稳定。

区分产品模型与工具

名称 含义 课程用法
千问/通义网页 面向用户的聊天产品 学生实际操作入口
Qwen3 阿里 Qwen 团队的通用模型系列 讲解提示、上下文、生成与核验
Qwen3-Coder 面向代码的模型系列 比较能力的进阶例子
Qwen Code 编程工具，能够结合文件与命令工作 仅选学，不是网页主线的前置条件

型号与系列含义参考 Qwen3 官方仓库、Qwen3-Coder 官方仓库 和 Qwen Code 官方说明。不将“使用千问网页”写成“固定使用某个 Qwen3 型号”。

学生如何开始

使用 千问官方网页 或学校选定的其他国内聊天工具，按产品正常流程登录。教师在开课前用学生同等账号条件检查校园网络、代码块复制和常规任务可用性。

实际模型选择、额度、附件和联网功能以学生账号界面为准。记录平台、日期、界面显示的模型名；没有显示就写“未显示”。课程不承诺永久免费、无限额度或每人可选择 Qwen3-Coder，也不要求学生购买 API。

网页 AI 可能无法查看本地文件、运行代码或保持长期上下文。主线始终用“复制上下文 → 生成局部改动 → 本地执行 → 回传真实结果”的方式，并按 协作规范需完整资料包 保存接力记录。

一次课堂工具检查

让学生把一段不含个人信息的简单函数和两个输入发给模型，请其预测结果、指出边界并建议测试；学生在本地运行，对照预测。随后再发一个真实错误，要求模型先说明原因，再提出最小修复。这个练习同时检查账号可用性和学生对“回答不等于执行”的理解。

若遇到限额或网络故障，使用教师预备的离线“模型回答、代码片段、错误日志”继续进行审查与调试，不影响核心目标。学生不能为解决额度问题将同学账号或密钥写进项目。

可选接入路线

后续具备资源时可了解百炼兼容 API、Qwen Code 或本地模型，但需要单独核实访问条件、费用和运行要求。这些路线不应出现在必修实验的隐藏步骤中。百炼官方兼容接口说明 可作为扩展阅读；具体模型标识和端点以当次官方配置为准。

不用模型排行榜替代课堂验证。比较两个模型时，使用相同上下文、任务与独立验收，报告正确性、修复轮次、遗漏和学生理解成本，不凭一次回答给整个模型系列下结论。

待实测的运行约束

  • 目标 Windows/macOS 环境、JDK 与 Node 版本是否统一可用。
