# 测试设计与故障定位

测试是“给定条件和输入，比较实际结果与事先写好的预期”。页面显示、自动测试通过、真实数据库保存分别是不同证据。AI 可以辅助实现测试，学生先决定验证什么、为何这样预期。

练习 A 计入第04课第1步10分钟，B 计入第09课第4步8分钟，C 计入第11课第5步20分钟，不增加课时和课程步骤。

## 六个基本术语

| 术语 | 本课含义 | 不能替代什么 |
| --- | --- | --- |
| 测试用例 | 前提、输入/动作、预期结果、判断依据组成的一次检查 | 只有截图不是完整用例 |
| 断言 assertion | 用代码比较实际和预期，例如 `assert.equal(actual, expected)` | 把预期改成错误结果不是修复 |
| 单元测试 | 隔离检查一个函数/规则，依赖可用测试替身替代 | 不证明真实 MySQL/Redis 或页面已接通 |
| 集成测试 | 检查多个真实组件协作，例如接口写入MySQL后独立读取 | 不能用Mock返回值冒充真实持久化 |
| 端到端检查 | 页面操作经过接口到保存，再回读页面 | 按钮隐藏不能证明后端拒绝越权 |
| 回归测试 | 修复后重跑失败项和相关旧用例，检查没有破坏旧行为 | 一个新测试不能覆盖整步 |

边界值分析挑容易出错的边缘输入，例如合法版本最小值0、负数、非整数、空值。等价类把适用相同规则的输入归类，选代表值并补关键边界。权限还需区分角色和是否本人被分派的对象。

## 练习 A：先写用例，再让 AI 实现（10分钟）

第04课第1步，先用3分钟将[测试记录](templates/测试记录.md)复制或合并到 `docs/测试记录.md`，写合法正数、0、null三条用例，关联 `FR-04`、`NFR-06`，含输入、单位、预期文字和理由，实际结果留“未执行”。用4分钟检查页面对应样本，最后3分钟同伴核对“0并非缺失、刷新时间并非采样时间”，记录差异并修复重查。

下面是用例设计矩阵，不是通过记录。只执行当前已实现内容；其他写“未实现/未执行”，到对应课再查。

| 类别 | 前提与输入/动作 | 可观察预期 | 课/层次 |
| --- | --- | --- | --- |
| 正常 | 功率12.5，单位kW | 显示12.5 kW，保留来源与采样时间 | 04；函数/页面 |
| 边界 | 分别输入0和null | 0 kW与“缺失”不同；null不补0 | 04；函数/页面 |
| 单位 | 功率切到电压 | 数值、标题、单位一起变，不换算电费 | 04；页面 |
| 错误 | 不存在的设备/点位或读请求失败 | 依接口合同返回错误/空结果；页面不造数据 | 05/10；接口/页面 |
| 账号 | 正确和错误密码分别登录 | 前者建会话，后者拒绝，不泄露密码/摘要 | 09；规则/接口 |
| 会话 | 缺令牌、失效令牌、退出后复用旧会话 | 受保护接口401，页面清除旧登录内容 | 09；接口/页面 |
| 权限 | VIEWER直接请求修改空间 | 后端403且数据库不变，不能只看隐藏按钮 | 10；接口/数据库 |
| 对象权限 | MANAGER处理分派给别人事件 | 后端拒绝，事件版本和时间线不变 | 11；规则/接口 |
| 输入边界 | expectedVersion为0、-1、1.5、"1"、null或缺省 | 0先通过类型检查再比业务版本；其余400，不先转整数 | 10/11；输入校验 |
| 版本冲突 | 两标签读同版本，先写成功，另一笔交旧版本 | 后一笔409，不覆盖，不自动重发旧决定 | 10/11；规则/接口/页面 |
| 状态规则 | 未恢复/未核实/缺结论就关闭 | 每项缺失均拒绝，满足全部条件才能关闭 | 11；规则/接口 |
| 失败恢复 | 先读成功，再停本课程后端并重新读取 | 旧结果标旧；恢复可重试，不静默切回mock | 11；端到端 |

第09课第4步，用2分钟为“错误密码”“登录后刷新”“退出后再读受保护接口”写预期，关联 `FR-10`、`UC-04`、`NFR-01`、`NFR-02`，继续写入 `docs/测试记录.md`；用4分钟按正文操作，记录真实HTTP状态和界面变化，不记录口令/token。最后2分钟解释浏览器内存token、Redis会话、MySQL业务记录是不同位置和数据；页面重登不等于数据库丢失。

### C1. 独立 Node 实验（12分钟）

只需Node22，无依赖下载、配置读取或服务启动。错误是**刻意保留的教学错误**，不属于业务成品，不在正常Maven/阅读版构建执行。测试名为 `checks.lab.mjs`，只用显式命令运行，不在教材根执行无路径的 `node --test`。

在**教学包根目录**工具终端运行以下一组。父目录须存在，目标须不存在，且在教材和 `campus-lab` 外；换成自己的已确认位置。

macOS：

```sh
node handbook-v2/engineering/labs/create-testing-lab.mjs "$HOME/course-test-lab-01"
cd "$HOME/course-test-lab-01"
```

Windows PowerShell：

```powershell
node handbook-v2/engineering/labs/create-testing-lab.mjs "$env:USERPROFILE\course-test-lab-01"
Set-Location "$env:USERPROFILE\course-test-lab-01"
```

脚本拒绝覆盖已有目录，失败时选新位置，不删除旧实验。先确认 `node --version` 为22。打开生成的 `README.md`、`checks.lab.mjs`，用2分钟先写正数、0、null的预期，不让AI先改代码。

用3分钟运行并读输出：

```sh
node --test checks.lab.mjs
```

第一轮应有7项测试，“zero is a valid reading”失败。**这只是教材预期，实际数量和退出状态必须自己填写。** 从输出找到失败测试名、`expected`、`actual`、第一处指向本地测试的行号，不只截最后的失败总数。

用3分钟追到 `readings.mjs`：0在真假判断中为假，`if (!value)` 将有效0当缺失。先写根因，再把缺失判断收窄为只匹配null，保留类型和有限数校验，不改错误预期来凑通过。

用2分钟重跑，再新增一个自己设计的有限小数输入断言；最后2分钟重跑全部，填写前后数量、根因、改动行和新用例。仍失败就保留事实，不用skip/删用例，也不把故意错误文件导入业务工程。

### C2. 将同一方法用到 Maven（8分钟）

回到学生 `campus-lab/backend` 的工具终端，确认Java17，按第11课流程执行。没有真实失败时用下方**虚构样例**练读报告，不破坏业务制造错误。

| 系统 | 全量测试 | 定向重跑示例 |
| --- | --- | --- |
| macOS | `sh ./mvnw test` | `sh ./mvnw -Dtest=ReadingRuleTest test` |
| Windows PowerShell | `.\mvnw.cmd test` | `.\mvnw.cmd "-Dtest=ReadingRuleTest" test` |

类名换成自己 `src/test/java` 中存在的失败类，不保证工程叫 `ReadingRuleTest`。定向通过后仍跑全量；没有匹配测试或 `Tests run: 0` 不算通过。

```text
以下是虚构教学样例，不是本组或教师实测：
Tests run: 3, Failures: 1, Errors: 0, Skipped: 0
ReadingRuleTest.zeroMustBePreserved
expected: <0 kW> but was: <缺失>
at edu.campus.ReadingRuleTest.zeroMustBePreserved(ReadingRuleTest.java:24)
BUILD FAILURE
```

前2分钟找测试类/方法、断言预期与实际，并沿堆栈找到自己的测试/业务代码首个相关行号。`Failures`通常为断言不符，`Errors`通常为运行异常；编译/下载依赖失败可能尚未开始测试，不算业务测试失败。

接着2分钟在编辑器打开 `backend/target/surefire-reports/` 中本轮对应类的 `.txt` 或 `TEST-*.xml`，核对修改时间、用例名、失败原因与堆栈。没有新报告先查编译/依赖阶段。只摘录去隐私的必要片段，不提交整个 `target/`。

最后4分钟写“假设 → 最小修复 → 定向重跑 → 全量回归”。有真实失败则修复记录；没有则写“本轮无失败，使用虚构样例练习阅读”，并填真实全量结果。未解决留明确待办，继续遵守正文失败不进入下一项的规则。

两人交换解释：一人讲预期来自哪条需求，一人从报告指出实际差异。测试数量描述运行范围，不直接等于分数。用法可查 [Node 内置测试文档](https://nodejs.org/docs/latest-v22.x/api/test.html)和[Maven Surefire定向测试](https://maven.apache.org/surefire/maven-surefire-plugin/examples/single-test.html)；实验仅使用Node22已有的 `node:test`、`node:assert/strict` 和显式文件运行。
