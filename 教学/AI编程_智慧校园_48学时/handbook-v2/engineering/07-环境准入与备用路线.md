# 环境准入与无 Docker 备用路线

适用 V2.1.1。环境安装放在课前；12 课课堂总计仍为 48 学时，每学时 45 分钟。本节不把教师的电脑测试写成全班验收。先选一条路线，一个工程从第08课到交付保持同一路线。

## 学习准备：先诊断，再补齐

对象为学过一门编程语言、尚缺完整项目经验的学生。不是承诺零编程基础学生在48学时内掌握全部软件工程知识。教师课前给10分钟诊断，不评分；有困难时安排课前辅导或同伴支持：

| 亲自完成的任务 | 可以继续的证据 | 需要补习什么 |
| --- | --- | --- |
| 打开空白工程，找到 HTML 文件，修改并保存一句话 | 指出具体文件与保存后的文字 | 文件、扩展名、目录 |
| 在终端查当前目录，再进入一个子目录并返回 | 能解释当前位置，不把命令粘到AI框 | `pwd`/`Get-Location`、`cd`、路径引号 |
| 从练习JSON指出数组、对象、一个设备id以及`null` | 能区分不存在、未知和数值0 | JSON、类型与空值 |
| 用自己的话解释浏览器向`/api/health`提问 | 能说出请求、响应、状态码、JSON各是什么 | HTTP与API入门 |
| 写出一条“输入→预期结果” | 预期可由同伴观察而不是“应该没问题” | 验收标准与断言 |

学生记录“独立完成／提示后完成／需要辅导”，不填个人密码、密钥或私人电脑截图。第一课检查记录只用5分钟，包含在该课原有时间内。

## 首次启动前的环境核对

从空白包进入 `campus-lab` 根目录，运行（需要已经安装 Node 22）：

```sh
node materials/check-environment.mjs
```

检查 Node 22、Java 17、Git、Docker Server、Compose，以及课程四个端口。第01课只要求 Node/Git 和页面端口；Java 在第07课前补齐，数据库路线在第08课前补齐。`BUSY` 不能证明是谁占用了端口，不可据此杀进程；如果是你已经启动的课程，先按该课程说明停止再做首次准入检查。

Docker 路线按[开课前准备](../00-先准备再开始.md)检查 Client/Server、Windows 虚拟化/WSL、网络和镜像下载。使用 Docker Desktop 前由本人按安装界面处理适用条款和权限，不把“命令已安装”当作引擎已可用。教师应在真实教室电脑预演。

## 备用路线适用条件

无 Docker 路线使用**教师提前装好原生 MySQL 8.4 服务端及命令行客户端与 Redis 7.2+ 的 macOS/Linux 实验机**，推荐 Redis 7.4，与主路线保持一致。工具只依赖 Python 3，建立本工程独立数据目录、随机配置和回环监听端口，不接管系统服务。Redis 7.2 的基本会话指令与本课程兼容，具体本轮已测版本以验证记录为准。

Windows 无法满足 Docker/WSL 条件时，安排已验收的上述实验机；本教材不提供未经验证的 Windows 原生 Redis 安装捷径。教师提前发放实验机使用方式、目录归属和保存规则。若没有这样的机器，**该学生的后六课环境尚未准备完成**，不能靠把 Docker 命令删除来判定可以开课。

原生数据库软件由教师依据发行方安装说明准备，课堂工具不安装软件、不运行全局 `brew services`/`systemctl`，也不连接既有业务数据库。用 `mysqld --version`、`mysql --version`、`redis-server --version` 核对工具；若 PATH 找不到指定版本，由教师记录可执行文件位置。

## 第08课：初始化一次，之后复用

在路径较短的新工程目录执行，例如个人目录下 `course/campus-lab`。路径需满足 Unix socket 的长度限制。先运行：

```sh
node materials/check-environment.mjs --native
python3 materials/native-runtime.py init
```

若正确版本未在 PATH，用教师确认的绝对路径替换下面占位后执行；**不可原样复制占位路径**：

```sh
node materials/check-environment.mjs --native --mysqld /absolute/path/to/mysqld --mysql /absolute/path/to/mysql --redis-server /absolute/path/to/redis-server
python3 materials/native-runtime.py init --mysqld /absolute/path/to/mysqld --mysql /absolute/path/to/mysql --redis-server /absolute/path/to/redis-server
```

工具会在写配置前核对 MySQL 服务端与客户端均为8.4。默认优先寻找服务端同目录的客户端，再查PATH；分离安装或多版本机器用 `--mysql` 指定正确客户端。版本探测最多等待12秒。受管数据目录或其内部出现符号链接时工具拒绝操作，交给教师检查原目录，不删除数据绕过。

默认端口 MySQL `23501`、Redis `23502`，均只监听 `127.0.0.1`。初始化随机生成根目录 `.env`，包括业务数据库密码、Redis密码和本机练习账户初始口令，权限为600；配置和数据在 `.runtime/native/`。已有 `.env` 或 native目录就拒绝重新初始化，避免新口令与旧数据不一致。**本路线不再执行 `node tools/setup-env.mjs`，也不执行任何 Compose 命令。**

然后执行：

```sh
python3 materials/native-runtime.py start
python3 materials/native-runtime.py status
```

首次启动会初始化独立 MySQL 数据、创建 `campus_course` 和只对它有权限的 `campus` 账户；Flyway业务表仍由学生后端创建。备用工具同时启动 Redis，但第09课前不提前实现登录。参考与学生后端需保留以下环境覆盖能力（第08/09课检查）：`DB_URL`、`DB_USER`、`DB_PASSWORD`、`REDIS_PORT`、`REDIS_PASSWORD`、`DEMO_PASSWORD`；Redis主机固定本机回环。默认端口与主路线一致，因此接口和前端不变。

工具不打印口令；在自己的编辑器本机查看 `DEMO_PASSWORD`，手动登录。不要用 `cat .env`、截图或复制全配置来求助。初始化失败时保留目录，由教师检查本课程日志，不删数据重做。

## 课程命令对照

| 场景 | Docker 路线 | 原生备用路线（工程根目录） |
| --- | --- | --- |
| 第08课配置 | `node tools/setup-env.mjs`，仅首次 | `python3 materials/native-runtime.py init`，仅首次 |
| 启动/恢复数据库 | 按该课 `docker compose up -d ...` | `python3 materials/native-runtime.py start` |
| 进程检查 | `docker compose ps` | `python3 materials/native-runtime.py status` |
| 第09课短时会话实验 | `docker compose restart redis` | `python3 materials/native-runtime.py restart-redis` |
| 每次下课停止 | `docker compose stop` | `python3 materials/native-runtime.py stop` |
| 后端、页面 | 教材的 B、A 命令 | 相同，仍须Java17/Node22 |

`status`只证明本目录登记的进程状态，不能代替登录、接口、数据保存与权限检查。操作失败时不自动退回Mock，不关闭权限，不清空MySQL。

## 第12课：新目录交接

1. 使用教材导出工具只导出源码；必须包含 `materials/native-runtime.py`，必须排除 `.env`、`.runtime` 和数据库。原生安装工具本身不放进教学包。
2. 先停止原目录 A/B，再在原目录执行 `python3 materials/native-runtime.py stop`。不停止其他同学或系统服务。
3. 在一个全新短路径目录解压源码，打开该目录。再次检查 Node22/Java17/MySQL8.4/Redis/Python；在该目录运行 `init`，生成它自己的配置和数据，再运行 `start`。同机使用默认端口时，旧课程需先停止。
4. 按教材先B、后A启动；初始口令只从**新目录**本机 `.env` 获取。验证16设备、登录、权限、事件、重启保存及失败恢复。新数据库没有旧练习事件是预期结果；源码交付不是数据库备份。
5. 接手同学填写真实环境、动作和未完成项，再停止新目录 A/B 与 native进程。第二次打开这个交付目录只用 `start`，不重新 `init`。

若教师指定不同端口，首次 `init` 支持 `--mysql-port` 与 `--redis-port`，它把端口写入本机环境覆盖项；学生后端必须读取这些覆盖项。不要为解决冲突修改全局数据库，也不要复制旧 `.runtime` 到新目录。

## 交给教师的环境记录

写明所选路线、操作系统、版本、四项端口是否通过、启动和停止是否成功、登录和重启实验的实际结果、还缺什么；不记录口令、连接秘密或个人机器全盘信息。成功标准是同学在分配的环境能独立重复，不是只有教师电脑能运行。
