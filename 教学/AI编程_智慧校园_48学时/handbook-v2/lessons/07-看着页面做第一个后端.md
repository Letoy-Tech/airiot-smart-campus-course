# 第07课：看着页面，做出第一个后端

前六课已经有了一套能点击的网页。这节课让电脑上再运行一个 Java 程序，让网页可以向它提问。我们先让它回答“我已经启动”，下一课再让它读取设备。

本课4学时，共180分钟。五步建议用时：35、25、40、40、40分钟。

你继续打开自己的 `campus-lab`，不要新建另一套前端。今天还不需要 MySQL 和 Redis。屏幕上的设备仍来自练习文件，演练仍是浏览器演示。

**重新开课，先恢复页面：** 如果上次已关闭 CodeBuddy，重新用“打开文件夹”选择原来的 `campus-lab`。新建 A-页面终端，用 macOS 的 `pwd` 或 Windows PowerShell 的 `Get-Location` 确认当前位置是项目根，在这个窗口运行：

```text
node tools/serve.mjs
```

看到 `http://127.0.0.1:5188` 后，在浏览器打开这个地址，再开始第1步。如果原来的 A 仍在运行且页面可打开，就继续使用它，不再启动第二个。B 在第2步才新建；本课不开数据库，也不用寻找还未生成的 `.env`。

**本课工程训练：** 30分钟，已包含在上述180分钟；编码与运行操作共150分钟。下文每步先做“先想”，其余工程活动穿插在本步编码、检查之后完成，不另外增加课时。文档只写本次最小记录，沿用同一份 `docs` 文件；材料与模板从教材链接读取，工程内没有 `docs` 时先建目录。

**本课提示词用法：** 先读 `materials/约定卡.md` 和当前文件，只改当前步指定范围，保留已完成业务。AI须实际保存文件、简报修改与已执行检查、列出还需学生亲自验证的项目；学生按下文运行并填写事实。常驻服务由学生操作，不因AI回复结束而停掉。补救提示只在对应失败发生时发送。

## 第1步：对着九个菜单，说清楚要保存什么

**本步时间：** 35分钟 = 工程训练10分钟 + 编码/操作25分钟（含AI生成等待、亲自运行与本步业务验收）。

- **解释：** 说明页面不能直连数据库；API计划不是已实现接口。
- **证据：** 在 docs/模型说明.md 保存图，在数据清单标本课实现边界；只记实际结果，不写口令或token。

**现在在哪：** 按上面的恢复动作打开原工程后，终端 A-页面正在运行 `node tools/serve.mjs`；浏览器打开 `http://127.0.0.1:5188`。依次点击九个菜单，特别看看“演练事件”刷新前后有什么变化。

**发给 CodeBuddy：**

```text

在已有整理上补齐我们已经做出的网页。
```

**等 AI 完成并保存：** 等它回复结束，打开新文件。请同伴指着“设备责任”说出“显示什么、修改什么、谁来保存”。看不懂的一行，当场让 AI 改成你能复述的话。

**亲自操作：** 打开第06课已经关闭的本地演练事件，核对它的处置记录和时间线，再刷新，确认仍能读到。回到表格找到该记录的存放位置。关闭的事件不能继续修改，本步只查看，不运行新的终端命令。

**没对上时，只发这段修复提示：**


**下一步：** 你能说清“目前存在浏览器里的数据”和“以后要放进 MySQL 的记录”后，再检查 Java。

## 第2步：准备后端终端，确认它用的是 Java 17

**本步时间：** 25分钟 = 工程训练3分钟 + 编码/操作22分钟（含AI生成等待、亲自运行与本步业务验收）。

- **解释：** 解释wrapper与业务代码不同职责。
- **证据：** 在 docs/后端启动笔记.md 留实际版本、目录与未通过项；只记实际结果，不写口令或token。

**现在在哪：** 新建一个终端，命名为 **B-后端**。当前目录应为 `campus-lab`。A 继续运行，不在 A 中输入新命令。

**发给 CodeBuddy：**

```text
目标：这一步只检查后端准备条件，不创建业务代码。
修改范围：终端准备与公开Maven wrapper。
必要约束：
请检查当前工程有没有 materials/maven-wrapper，并告诉我里面哪些文件要复制到 backend。
```

**等 AI 完成并保存：** 等回复结束。它说“检查完毕”只代表回答完了，接下来还要由你执行下面的命令。

**亲自操作：** 新开的 B 不会自动继承 A 或 C 中临时调整的环境。如果笔记给出了本机已确认安装的 Node 22 临时切换命令，先在 B 执行它；设置 Java 不会同时切换 Node。随后按自己的系统执行下面一组检查。

macOS，工作目录为 `campus-lab`：

```sh
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
export PATH="$JAVA_HOME/bin:$PATH"
java -version
node --version
pwd
```

Linux 实验机：由教师给出本机已安装JDK17的实际根目录，只在新B窗口设置 `JAVA_HOME`，并把它的 `bin` 放在当前 `PATH` 前面。不要原样输入占位路径，也不要使用macOS的 `/usr/libexec/java_home`。然后执行 `java -version`、`node --version`、`pwd`，将实际设置方式记入启动笔记。后续 Linux 的 `cd backend`、`sh ./mvnw test`、`sh ./mvnw spring-boot:run` 与下文macOS的Maven命令相同。

Windows PowerShell，工作目录为 `campus-lab`；以下按课前安装的 Temurin 17 查找：

```powershell
$courseJdks = @(Get-ChildItem "C:\Program Files\Eclipse Adoptium" -Directory | Where-Object Name -Like "jdk-17*")
if ($courseJdks.Count -ne 1) { throw "请老师确认本机JDK17目录后再继续" }
$env:JAVA_HOME = $courseJdks[0].FullName
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
java -version
node --version
Get-Location
```

**应该看见：** Java 主版本是 `17`，Node 主版本是 `22`，当前目录最后一层是 `campus-lab`。若显示两个 JDK 安装目录，先请老师确认用哪个，不随意取第一个。以后新开后端终端，要在新窗口重新设置这两项环境变量。

**如果 Java 已是 17，但 Node 不是 22：** 不继续生成后端，单独发送：

```text
第07课第2步，Java17已通过，但新B终端的node --version显示【实际版本】。
请只读确认本机已安装的Node22位置，给出仅让当前终端使用它的命令，补进启动笔记。
不要改全局默认，不安装软件，不继续创建后端；若本机没有Node22，明确报告缺项。
```

**失败时，只发这段修复提示：**

```text
我还停在Java环境检查。操作系统是【Windows/macOS/Linux】；
java -version显示【版本】，当前目录最后一层是【目录名】。
请只帮助我让当前终端使用已安装的Java17，不改全局设置，不继续创建后端。
```

**下一步：** Java 17 和目录都确认后，生成最小后端。

## 第5步：在网页上看见后端在线，再亲手验证断开

**本步时间：** 40分钟 = 工程训练6分钟 + 编码/操作34分钟（含AI生成等待、亲自运行与本步业务验收）。

- **解释：** 解释失败时不能自动换成模拟成功。
- **证据：** 在 docs/测试记录.md 留实际三阶段证据；只记实际结果，不写口令或token。

**现在在哪：** 回到原来的校园网页标签。A、B 都保持运行。

**发给 CodeBuddy：**

```text
目标：在现有网页顶部增加一个小区域“后端连接”，带“检查连接”按钮。
```
