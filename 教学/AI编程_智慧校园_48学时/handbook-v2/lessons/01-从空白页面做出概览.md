# 第 01 课：从空白页面做出概览

本课 4 学时，共 180 分钟。我们先做一个看得见、点得动的校园管理台。今天结束时，页面有自己的名称、左侧菜单和概览卡片。数据将在下一课加入。

五步建议用时：45、35、25、45、30分钟，共 180 分钟。这是备课建议，并非课堂实测；教师可按实际卡点调整。

课前先完成“开始前的准备”。你的电脑里应有 `campus-lab` 文件夹，里面有公开练习资料 `materials`，以及一个空的 `frontend/index.html`。用 CodeBuddy 的“打开文件夹”打开 **campus-lab 整个文件夹**。不要只打开那一个 HTML 文件。

今天会用到三个地方：CodeBuddy 对话框用来发提示词；CodeBuddy 终端用来运行页面；浏览器用来看结果。下面每一步只发一段提示词。等这一步完成、自己看过结果，再发下一段。

**先记住两个不同的“完成”：** AI 写完文件并回复本步结果，就可以检查页面；终端里的页面服务会一直运行，不需要等它退出。后面看到页面正常后，让终端继续开着。只有教程明确写“重启终端 A”时，才在终端 A 按 `Ctrl+C`。


| 步骤 | 工程训练（分钟） | 编码与验证（分钟） | 合计（分钟） |
| --- | ---: | ---: | ---: |
| 1 | 15 | 30 | 45 |
| 2 | 6 | 29 | 35 |
| 3 | 4 | 21 | 25 |
| 4 | 6 | 39 | 45 |

| 合计 | 36 | 144 | 180 |

**本课工程训练：** 36分钟，已包含在上述180分钟；编码与运行操作共144分钟。下文每步先做“先想”，其余工程活动穿插在本步编码、检查之后完成，不另外增加课时。文档只写本次最小记录，沿用同一份 `docs` 文件；材料与模板从教材链接读取，工程内没有 `docs` 时先建目录。

**本课提示词用法：** 先读 `materials/约定卡.md` 和当前文件，只改当前步指定范围，保留已完成业务。AI须实际保存文件、简报修改与已执行检查、列出还需学生亲自验证的项目；学生按下文运行并填写事实。常驻服务由学生操作，不因AI回复结束而停掉。补救提示只在对应失败发生时发送。

## 第 1 步：让空白文件变成第一张页面

**本步时间：** 45分钟 = 工程训练15分钟 + 编码/操作30分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** 哪些内容可以进入仓库，哪些是运行产物或秘密？
- **亲手做：** 先用5分钟核对[环境准入与学习诊断](../engineering/07-环境准入与备用路线.md)记录，标“独立完成/提示后完成/需辅导”；再用10分钟按[Git实训练习A](../engineering/05-Git协作实训.md)在本步完成初始化、忽略规则、查看差异与首次提交；先初始化，页面验收后再提交，只选择公开文件。
- **解释：** 指着 git status 和提交说明解释本次保存了什么。
- **证据：** 将提交短号和本人检查的忽略项记入 docs/本组实做记录.md；只记实际结果，不写口令或token。

**现在在哪：** CodeBuddy 左边的文件区。展开 `frontend`，点开空的 `index.html`。如果文件不存在，右键 `frontend` 新建文件，名字完整写成 `index.html`。

切到可以修改项目文件的 **Craft** 模式，把下面一整段发到 CodeBuddy：

```prompt
目标：在现有空文件 frontend/index.html 中写一个完整 HTML 页面，页面语言为中文，浏览器标签名和页面大标题都叫“我的校园值班台”。
修改范围：frontend/index.html、tools/serve.mjs。
必要约束：
标题下面显示“第一张页面已经打开”和“教学模拟项目”。先不要加入业务数据。
1. 创建 tools/serve.mjs，使用 Node 22 自带模块，不安装依赖。监听 127.0.0.1:5188，只提供 frontend 目录中的文件；不允许读取隐藏文件、项目根目录、backend 或目录外文件。正确设置 HTML、CSS、JavaScript 的类型。/api/* 转发到 127.0.0.1:8098，保留 /api 路径；后端未启动时返回清楚的服务不可用提示。
2. 可以运行会自行退出的语法检查，不启动常驻服务。
验收：页面显示标题与模拟标记；A由学生启动。
```

**等到什么：** 等 CodeBuddy 的修改结束，并回复保存了 `frontend/index.html`、`tools/serve.mjs`。在左边分别点开这两个文件，确认它们已有内容。若它只在对话中给出了代码而没有保存，回复“请把本步代码实际写入刚才指定的文件并保存”，先完成保存。

**自己运行：**

1. 在 CodeBuddy 打开一个终端，把它命名为 **A-页面**。
2. 看终端当前目录，末尾应是 `campus-lab`。如果不是，先切到这个文件夹。
3. 输入并回车：

   ```sh
   node tools/serve.mjs
   ```

4. 等终端显示本地地址，在浏览器地址栏输入 `http://127.0.0.1:5188`。

**应该看到：** 页面上有“我的校园值班台”“第一张页面已经打开”和“教学模拟项目”。终端 A 还在运行，这是正常现象。

**如果没看到：** 先核对浏览器地址和终端所在目录。然后单独把这一段发给 CodeBuddy，在它后面补上终端第一条错误；没有错误就写“终端没有错误，浏览器显示……”。不要粘贴密码。

```prompt
我在第01课第1步。预期打开本地地址后看到“我的校园值班台”，现在没有看到。我会附上实际现象和第一条错误。请只检查本步的 index.html 和 serve.mjs，修复这个问题并保存，不继续添加功能，也不要替我启动服务。若修改了 serve.mjs，明确提醒我只重启终端 A。
```

如果修改了 `serve.mjs`，到终端 A 按一次 `Ctrl+C`，再运行刚才那条命令。如果只修改了 HTML，在浏览器刷新即可。看到标题后，进入第 2 步。

## 第 2 步：给管理台搭出外框

**本步时间：** 35分钟 = 工程训练6分钟 + 编码/操作29分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** 谁来使用设备页，本课程明确不做哪些事情？
- **亲手做：** 按[需求规格与用例](../engineering/01-需求规格与用例.md)写一个“查看设备”的角色、目标和验收条件，并列出控制设备与对外通知不在范围内。
- **解释：** 向同伴解释九个菜单中哪一个承接这条需求。
- **证据：** 用[需求记录模板](../engineering/templates/需求与用例记录.md)在 docs/需求与用例.md 留一条记录；只记实际结果，不写口令或token。

**现在在哪：** 保持浏览器和终端 A 打开，回到 CodeBuddy 对话框。这一步只安排页面位置。

```prompt
目标：把 frontend/index.html 分成左侧菜单、顶部标题、右侧内容三块。
修改范围：frontend/index.html。
必要约束：
保留“我的校园值班台”和“教学模拟项目”。
左侧从上到下放九个菜单：概览、设备、空间、能源、历史、原始报警、演练事件、设备责任、管理。页面内部名称依次为 dashboard、devices、spaces、energy、history、alarms、cases、owners、admin。
右侧先显示“概览”，下面写“我们将在下一课放入校园设备”。菜单暂时可以还不能切换。
先把本步所需的少量样式写在 index.html 中。文字清楚、按钮容易点，窄屏不让主内容挤到屏幕外。不引入框架、图标库、远程字体或新依赖。
不启动常驻服务。
验收：九菜单齐全，宽窄窗口可读。
```

**等到什么：** 等 AI 回复本步完成，点开 `index.html` 看是否已保存。浏览器刷新一次。

**自己点看：** 从上到下读出九个菜单，找到顶部平台名和右侧“概览”。把浏览器窗口缩窄，再放宽。

**应该看到：** 九个菜单都能读清，主内容没有被侧栏盖住。这一步还没有要求菜单切页，所以现在点击无变化不算错误。

**如果排版挤在一起：** 只发下面的修复提示，并说明是宽窗口还是窄窗口：

```prompt
第01课第2步的外框排版有问题：我将说明哪个区域挡住了哪个区域。请只修复现有 index.html 的布局，保留九个菜单和所有文字，不添加新功能。保存后告诉我应刷新检查哪一处。
```

排版能正常阅读后，进入第 3 步。

## 第 3 步：在概览中放三张卡片

**本步时间：** 25分钟 = 工程训练4分钟 + 编码/操作21分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** “还没读到”与“读到0”分别表示什么？
- **亲手做：** 在刚才的需求记录里写一个未载入场景和预期文字，再核对三张卡片。
- **解释：** 说出为什么不能拿0装作未载入。
- **证据：** 在 docs/需求与用例.md 留下场景与实际显示；只记实际结果，不写口令或token。

**现在在哪：** CodeBuddy 对话框。我们让首页像一个管理台，但还不假装已经读到了设备。

```prompt
目标：在概览页面增加三张卡片：“设备总数”“空间总数”“点位总数”。
修改范围：frontend/index.html。
必要约束：
卡片数值区域目前统一写“尚未载入”，不要写0或随便编一个数字。
卡片下加一块“今天先做什么”，用一句话写“先查看设备，再了解读数，发现问题后登记演练事件”。
页面持续显示“教学模拟项目”。让三张卡片在宽屏并排，窄屏自然换行。不加入图表、不请求后端、不安装依赖。
不启动服务，不做下一步。
验收：三卡均为尚未载入。
```

**等到什么：** 等 AI 保存完成。打开文件看看三张卡片的标题，再回浏览器刷新。

**自己点看：** 读出三个标题；缩窄窗口，观察卡片是否往下排列。

**应该看到：** 三张卡片都写“尚未载入”。这里的“点位”可以理解为设备的一项读数，例如温度计的温度、湿度。下一课我们会让卡片显示真正从练习数据数出来的结果。

**如果出现编造的数字：** 单独发送：

```prompt
第01课第3步尚未加入练习数据，但卡片出现了数字。请把设备、空间、点位三张卡片都恢复为“尚未载入”，保留卡片外观。不要用0代表尚未读取，也不要提前读取数据。
```

卡片正确后，进入第 4 步。

## 第 4 步：把外观和操作分开，让菜单能切换

**本步时间：** 45分钟 = 工程训练6分钟 + 编码/操作39分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** 内容、外观和点击动作各放在哪个文件？
- **亲手做：** 参照[架构与设计取舍](../engineering/02-架构与设计取舍.md)画出 HTML 引用 CSS/JS 的三框图，并手指定位引用行。
- **解释：** 说明菜单切换为何不需要另开九个网页。
- **证据：** 在 docs/模型说明.md 保存三框图或文字箭头；只记实际结果，不写口令或token。

**现在在哪：** CodeBuddy 对话框。这一步会多出两个文件。`styles.css` 管外观；`app.js` 管点击后发生什么。

```prompt
目标：将 index.html 中的样式原样移到 frontend/styles.css，让 HTML 引用它。
修改范围：frontend/index.html、styles.css、app.js。
必要约束：
拆分后外观应保持不变。
1. 创建 frontend/app.js，由 index.html 以 type="module" 引入。九个菜单点击后切换对应内容区域，并突出当前菜单。可以使用 #dashboard、#devices 等地址片段保存当前位置，刷新后仍能回到该菜单。
2. 概览保留现有三张卡片。其他八个菜单各显示自己的中文标题和“这个页面会在后续课程完成”，不要伪装成已经有业务功能。
3. 点击菜单不打开新的网页，不刷新整个浏览器页面。对显示在页面中的文本使用安全的文字写入方式。
不安装框架，不启动服务。完成后告诉我在哪里引用 CSS 和 JavaScript。
验收：切页不整页刷新，刷新保留位置。
```

**等到什么：** 等 AI 保存完成。左侧应能看见 `index.html`、`styles.css`、`app.js` 三个文件。打开 HTML，找到它引用另外两个文件的地方；不要求现在背下写法。

**自己点看：** 刷新浏览器，依次点击“设备”“历史”“概览”。停在“历史”时，再按浏览器刷新。

**应该看到：** 每次只显示当前页面；“历史”有自己的标题，刷新后还在“历史”；回到概览，三张卡片仍在。

**如果点击没有变化：** 先确认 `app.js` 已保存，再单独发：

```prompt
第01课第4步菜单不能正常切换。我将说明点击哪个菜单、页面实际显示什么。请检查 index.html 对 app.js 的引用、菜单对应名称和点击处理，只修复切换问题。不要重写外观，也不要删除现有菜单。保存后告诉我重复哪三个点击检查。
```

菜单切换正确后，进入第 5 步。

## 第 5 步：亲手改一次，留下第一课作品

**本步时间：** 30分钟 = 工程训练5分钟 + 编码/操作25分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** 怎样证明一处改动是自己完成的？
- **亲手做：** 亲手修改平台名，查看 git diff，仅提交本课公开改动。
- **解释：** 不用复述AI答案，指文件解释 HTML、CSS、JavaScript 各负责哪部分。
- **证据：** 在原 notes 笔记补上改动位置、提交短号及未完成项；只记实际结果，不写口令或token。

**现在在哪：** CodeBuddy 文件区。先自己打开 `frontend/index.html`，找到“我的校园值班台”，把平台名称改成你的小组名称，例如“晨光校园值班台”，保存。如果平台名由 `app.js` 统一设置，就在那个文件改。浏览器刷新后，确认改动出现。

然后发送：

```prompt
目标：本步只检查前端，不增加业务功能。
修改范围：当前前端。
必要约束：
学生刚亲手修改了平台名称。请先读取当前文件中的名称，以学生当前选择为准，只检查浏览器标签名与页面大标题是否一致；不要恢复第1步的默认名称“我的校园值班台”。若两处不同而无法确定学生选择，先询问，不自行替学生改名。
平台名称是否一致，九个菜单是否齐全，CSS和JS是否正确引用，首页是否仍保留三张“尚未载入”卡片。
如果发现本课遗漏，做最小修复并保存。不要启动常驻服务，不要继续读取校园数据。
最后用三句话告诉我：HTML负责什么、CSS负责什么、JavaScript负责什么。只报告实际做过的检查。
验收：学生新名称保留，九菜单和三卡正常。
```

**等到什么：** 等 AI 回复检查结果。它说通过以后，你仍然要自己在浏览器检查一次。

**自己点看：** 从“概览”点到“管理”，再回“概览”；将窗口缩窄，确认名称、菜单和卡片仍能看清。

**应该看到：** 自己的平台名、九个能切换的菜单、三张等待数据的卡片。今天没有后端，也没有数据库，这个结果就符合本课目标。

**如果改名后页面不变：** 单独发：

```prompt
第01课第5步我已经保存了平台名称，但浏览器刷新后仍显示旧名称。请查出页面实际使用名称的位置，统一成本项目现在的名称。只修复名称，不重建工程。告诉我需要刷新还是只需重新保存文件。
```

完成后，在 CodeBuddy 左侧 `campus-lab` 根目录上点右键，选“新建文件夹”，输入 `notes`；再在 `notes` 上点右键新建文件，输入 `01-我的第一张页面.md`。写三行：我改了哪个名称；我实际点过哪些菜单；还有什么没成功，然后保存。后面几课的记录继续放在这个文件夹。保存一张自己的浏览器截图，截图留在自己的作业资料中。

**接下来：** 继续上课就让终端 A 保持运行，进入第 02 课。如果今天到此结束，在终端 A 按 `Ctrl+C` 停止页面服务；下次仍在 `campus-lab` 根目录运行 `node tools/serve.mjs`。不要删文件，也不要重新建一个项目。
