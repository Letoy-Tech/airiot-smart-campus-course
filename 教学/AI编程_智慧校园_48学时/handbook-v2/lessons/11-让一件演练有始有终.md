# 第11课：让一件演练有始有终，并留下记录

前六课的演练事件只在浏览器里走流程。今天把同一套按钮接到后端：建立、分派、开始、记事、恢复、核实、关闭。换账号或重开网页后，仍能看到同一件事发生过什么。

本课4学时，共180分钟。六步建议用时：25、30、30、25、45、25分钟。

**重新开课：** 打开原 `campus-lab`，沿用原 `.env`；Docker 路线打开 Desktop并等引擎运行，在 C、项目根执行 `docker compose up -d`、`docker compose ps` 等两服务 `healthy`；原生路线执行 `python3 materials/native-runtime.py start`、`python3 materials/native-runtime.py status`，确认本目录进程运行，不重新init。A 若已停止，在项目根运行 `node tools/serve.mjs`；仍在运行则沿用，不启动第二份。

若旧后端还在运行，先在原 B 按 Ctrl+C。新 B 按[第07课第2步](07-看着页面做第一个后端.md#第2步准备后端终端确认它用的是-java-17)设置本窗口的 Java 17 与已安装的 Node 22，分别执行 `java -version`、`node --version`。B 从项目根进入 `backend`：macOS 用 `cd backend`，Windows PowerShell 用 `Set-Location backend`；若已在该目录不重复进入。编辑 Java 前保持 B 停止，第1步完成后再测试和启动。

每次 Java 修改后，B 中先测试再启动：macOS 用 `sh ./mvnw test`、成功后 `sh ./mvnw spring-boot:run`；Windows PowerShell 用 `.\mvnw.cmd test`、成功后 `.\mvnw.cmd spring-boot:run`。已经运行的 B 先按 Ctrl+C，再执行这两条。A 与本课程MySQL、Redis保持运行。


**环境分支：** 沿用开课前已选路线，详见[环境准入与备用路线](../engineering/07-环境准入与备用路线.md)。只执行自己这一列，不在同一工程混用两套配置。

| 动作 | Docker 路线 | 原生备用路线（已验收的 macOS/Linux 实验机） |
| --- | --- | --- |
| 启动、查看状态 | 本课对应的 `docker compose up -d …`、`docker compose ps` | 项目根 `python3 materials/native-runtime.py start`、`python3 materials/native-runtime.py status` |
| 停止课程数据库 | 本课对应的 `docker compose stop` | 项目根 `python3 materials/native-runtime.py stop` |

原生路线不执行 Compose，不操作系统全局数据库。`status` 仅报告本目录进程，后端连接、登录、写入回读仍按正文亲自验证。Windows 无 Docker 时由教师提供上述已验收实验机；没有可用路线则环境仍未准备完成。

**本课工程训练：** 45分钟，已包含在上述180分钟；编码与运行操作共135分钟。下文每步先做“先想”，其余工程活动穿插在本步编码、检查之后完成，不另外增加课时。文档只写本次最小记录，沿用同一份 `docs` 文件；材料与模板从教材链接读取，工程内没有 `docs` 时先建目录。

**本课提示词用法：** 先读 `materials/约定卡.md` 和当前文件，只改当前步指定范围，保留已完成业务。AI须实际保存文件、简报修改与已执行检查、列出还需学生亲自验证的项目；学生按下文运行并填写事实。常驻服务由学生操作，不因AI回复结束而停掉。补救提示只在对应失败发生时发送。

## 第1步：建立第一件真正保存的演练事件

**本步时间：** 25分钟 = 工程训练4分钟 + 编码/操作21分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** 创建事件、时间线、审计为什么应一起成功或一起失败？
- **亲手做：** 画一个事务框包含三条记录，核对事件id、version与actor来源。
- **解释：** 解释浏览器不能指定审计操作人。
- **证据：** 在 docs/模型说明.md 留事务边界；只记实际结果，不写口令或token。

**现在在哪：** B 已停止。CodeBuddy 打开已有后端和演练事件页面。

**发给 CodeBuddy：**

```text
目标：按materials/约定卡.md新增V4迁移，建立cases、事件时间线与audit所需表。
修改范围：V4、事件创建/查询和现有页面。
必要约束：
保留V1到V3和已有数据。
实现GET /api/cases，返回事件及各自timeline；三个登录角色可以读取。
实现仅ADMIN可用的POST /api/cases，接收deviceId和message。
服务端生成ID、时间、version=1、sourceState=ACTIVE、verified=false；
若已有责任人为manager，自动分派并设ASSIGNED，否则为NEW。
事件、创建时间线和case.create审计在同一事务存入MySQL，
审计的操作人取自后端会话，不由客户端伪造处理人或创建时间。
把现有事件列表和“建立演练”按钮接到接口，成功后独立GET回读；
这部分不再写campus-v2-demo，保留“教学模拟演练”标记。
不读取或修改原始报警，不控制设备，不发送通知。
本步只做创建和列表，不提前实现后续动作，不启动服务。
验收：创建与时间线/审计同事务。
```

**等 AI 完成并保存：** 看见新迁移和原事件页面的修改。之前浏览器里演示的事件不会自动成为数据库记录，不要把两份列表合并。

**亲自操作：** B 执行“测试→启动”。网页刷新后以 `admin` 登录，先为 `d01` 建立一件事件，消息填“本课温度巡查演练”。再为尚未登记责任人的 `d02` 建立一件事件，消息填“本课人工分派演练”。

**应该看见：** 按上一课的操作，`d01` 会自动分派给 `manager`；`d02` 是待分派。若你之前给 `d02` 也登记了责任人，就换一台尚未登记的设备。每件事件有独立 ID、版本1和创建记录。

**失败时，只发这段修复提示：**

```text
我为【设备ID】建立演练后看到【实际状态和负责人】。
请检查后端读取的责任记录、初始状态与GET回读，
不要在前端写死负责人，也不要把旧localStorage事件当作数据库结果。
```

**下一步：** 选择刚建立的“人工分派演练”，接通分派、开始和记事。

## 第2步：分派给 manager，再换人开始处理

**本步时间：** 30分钟 = 工程训练5分钟 + 编码/操作25分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** 同一MANAGER是否能处理别人的事件？
- **亲手做：** 从角色×事件归属×状态中选允许与拒绝各一例，在改动前写出预期。
- **解释：** 解释拒绝应该由哪一层完成。
- **证据：** 在 docs/测试记录.md 留权限、状态、版本证据；只记实际结果，不写口令或token。

**现在在哪：** 在 B 按 Ctrl+C。CodeBuddy 打开现有事件页面，保留刚建立的数据库事件。

**发给 CodeBuddy：**

```text
目标：实现POST /api/cases/{id}/actions中的assign、start、note。
修改范围：事件分派/开始/记事及测试。
必要约束：
每次请求必须带expectedVersion，服务端比较当前版本，成功后加1，
落后则409；主记录、时间线和审计在同一个数据库事务中保存。
assign仅ADMIN，username只允许有效manager，说明非空，状态为ASSIGNED；
start由ADMIN或本事件的manager执行，要求ASSIGNED，变为IN_PROGRESS；
note由ADMIN或本事件的manager执行，要求IN_PROGRESS、说明非空，状态保持。
VIEWER不能修改，其他身份不能替未分派给自己的事件处理。
把原页面的分派、开始、记录按钮逐个接到接口；
每次成功独立GET /api/cases回读，409只刷新并解释，不自动重发。
加入角色拒绝、错误状态和版本冲突测试，不启动服务。
验收：角色、本人分派、状态、版本检查通过。
```

**等 AI 完成并保存：** 在改动中找这三个动作，不要让 AI 一次改造整个项目。

**亲自操作：** B 执行“测试→启动”。浏览器刷新，以 `admin` 登录，打开刚才待分派的事件，选择 `manager`，写“请进行现场巡查”，点击分派。退出并以 `manager` 登录，打开同一事件，点“开始处理”，写“已检查练习点位，继续观察”并保存处置记录。

**应该看见：** 状态从待分派变成已分派，再变成处理中。时间线按顺序列出建立、分派、开始和处置记录；每成功一次版本增加1，负责人仍是 `manager`。

**失败时，只发这段修复提示：**

```text
我以【账号】对事件执行【动作】，实际出现【现象】。
请只检查本动作的角色、当前状态、expectedVersion和独立回读，
不要自动重复提交，不去掉权限或版本检查。
```

**下一步：** 事件进入处理中且已有处置记录后，接通恢复、核实、关闭。

## 第3步：先恢复，再核实，最后写结论关闭

**本步时间：** 30分钟 = 工程训练5分钟 + 编码/操作25分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** 少一个关闭前提时应发生什么？
- **亲手做：** 针对未恢复、未核实、无结论各写一个反例，再检查测试与页面。
- **解释：** 对照第06课状态图解释真实后端实现的条件。
- **证据：** 在 docs/测试记录.md 留三个反例和闭环结果；只记实际结果，不写口令或token。

**现在在哪：** 在 B 按 Ctrl+C。事件数据留在数据库，不会因停止 Java 而消失。

**发给 CodeBuddy：**

```text
目标：继续实现同一个actions接口里的recover、verify、close。
修改范围：事件恢复/核实/关闭及测试。
必要约束：
recover仅ADMIN，表示本地演练来源已恢复，设sourceState=RECOVERED，
不能直接关闭事件，也不声称真实设备已恢复。
verify由ADMIN或本事件的manager执行，服务端重新检查已恢复事实后设verified=true。
close要求IN_PROGRESS、有非空处置记录、RECOVERED、verified=true，
并要求本次note为非空关闭结论，将其存入conclusion，再设CLOSED。
三个动作均检查expectedVersion、成功加1，主记录/时间线/审计一起保存。
关闭后拒绝任何后续修改。不得接受客户端直接提交verified=true来跳过核实。
把现有恢复、核实、关闭三个按钮分别接好，说明缺哪一项条件；
每次成功独立GET回读，不只修改页面文字。
测试每一项关闭条件缺失时都会被后端拒绝。不要启动服务。
验收：关闭条件缺一被拒，关闭后不可改。
```

**等 AI 完成并保存：** 看页面说明是否明确区分“演练来源恢复”“人已核实”“事件关闭”。

**亲自操作：** B 执行“测试→启动”。以 `manager` 登录打开刚才的事件，先看关闭区域，未恢复时应说明还缺什么。退出后以 `admin` 登录同一事件，点击“模拟恢复”（生成界面也可能写“标记来源已恢复”）。再次退出，以 `manager` 登录，点击“核实恢复”（或“核实来源恢复”），输入关闭结论“本次教学演练已核查完成”，最后点击关闭。

**应该看见：** 模拟恢复后仍是处理中；核实后仍需填写结论；最后才是已关闭。刷新整个网页，重新登录，仍能看到同一个已关闭事件、完整时间线与结论。

**失败时，只发这段修复提示：**

```text
我完成【恢复/核实/关闭】后，实际显示【状态、来源状态、核实结果】。
请只修复三个按钮到各自动作的连接与关闭条件；
不要把恢复等同关闭，不让前端直接伪造核实通过。
```

**下一步：** 事件闭环完成后，让管理员看见谁改过什么。

## 第4步：接通审计和接入状态

**本步时间：** 25分钟 = 工程训练5分钟 + 编码/操作20分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** 哪些证据能证明“已做过”，哪些只是配置说明？
- **亲手做：** 任选一条成功操作与审计核对actor/对象/动作/时间，再用viewer检查拒绝。
- **解释：** 说明TEACHING_MOCK和控制关闭对结论的限制。
- **证据：** 在 docs/API核对.md 留状态字段与权限结果；只记实际结果，不写口令或token。

**现在在哪：** 停止 B。CodeBuddy 打开“管理”菜单相关代码。

**发给 CodeBuddy：**

```text
目标：实现仅ADMIN可读的GET /api/audit，返回已实际发生的本课程业务修改记录。
修改范围：审计/接入状态及测试。
必要约束：
空间修改、责任修改、事件创建/动作都应在成功事务中写审计；
记录谁、何时、对哪个对象做了哪个动作，不记录密码、token或完整请求头。
失败操作不能伪装成成功审计。
实现需登录的GET /api/integration，返回：
{source:"TEACHING_MOCK",simulated:true,controlEnabled:false,notificationsEnabled:false}
把原管理菜单的审计和接入说明接到接口，不伪造AIRIOT已连接；
MANAGER/VIEWER访问审计时返回403，页面清除旧审计并显示无权查看。
增加后端角色测试；完成后逐项说明两个接口、管理页接线与角色测试，
不能只回报局部测试结果。不启动服务。
验收：ADMIN可审计，接入状态如实。
```

**等 AI 完成并保存：** 看见管理页保留了角色说明，并增加实际读取的审计。

**亲自操作：** B 执行“测试→启动”。用 `admin` 登录，打开审计，找到刚完成事件的创建、处理与关闭记录。再保存一次空间说明，回来重新读取审计。查看接入状态，最后退出并用 `viewer` 登录管理页。

**应该看见：** 新发生的空间修改多了一条审计；新加审计功能之前发生的历史操作若当时未记录，不需要补造。viewer 看不到管理员刚读出的旧审计。接入仍是教学模拟，控制和通知都关闭。

**失败时，只发这段修复提示：**

```text
我在管理页以【账号】操作【查看审计/切换身份】后看到【现象】。
请只修复审计读取权限、旧内容清理或真实业务写入记录；
不要编造历史操作，不输出密码或会话令牌。
```

**下一步：** 用一次故意失败，确认页面不会把旧内容冒充本次成功。

## 第5步：断开后端，检查失败提示；用测试检查拒绝

**本步时间：** 45分钟 = 工程训练20分钟 + 编码/操作25分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** 测试失败首先能告诉你断言、实际值和哪条业务规则？
- **亲手做：** 完成[测试实训练习C](../engineering/06-测试设计与故障定位.md)：在独立目录生成Node故意失败实验，运行并读首个失败、最小修复后重跑，再把Maven一条报告映射到本课规则；本步骤其余操作按下文检查真实页面。
- **解释：** 向同伴讲一次从失败证据到修复的推理，不把模拟失败当真实系统故障。
- **证据：** 在 docs/测试记录.md 留失败→定位→修复→复测以及一条Maven断言依据；只记实际结果，不写口令或token。

**现在在哪：** 用 `admin` 登录，先成功读取一次事件列表。保持当前标签，不刷新整个网页。

**发给 CodeBuddy：**

```text
目标：检查事件、责任、历史、审计这些已经接通的页面如何处理失败。
修改范围：已接页面失败处理及测试。
必要约束：
统一做到：第一次失败有错误与重试；已有成功数据时标出“上次成功结果”；
401清理身份与受保护内容；403清理无权查看的内容；409回读后由学生重新决定；
切换设备/账号后，较早请求返回不能覆盖新选择。
事件列表应有明确的“重新读取事件”按钮；如果尚未提供，请在本步补上，复用现有加载与失败重试逻辑。
只修复实际缺失的部分。增加针对已经发现问题的测试，不删除或弱化原测试。
不要启动服务。
验收：首次失败/旧快照/401/403/409正确。
```

**等 AI 完成并保存：** 若它修改 Java，按本课固定流程重启 B 并重新登录；只改前端则保存后刷新、重新登录。

**亲自操作：** 事件列表成功出现后，在 B 按 Ctrl+C，再点事件列表的“重新读取事件”按钮。看清提示，再在 B、`backend` 重新运行对应系统启动命令，等启动完成后重试。最后停止 B，运行一次 `sh ./mvnw test`（macOS）或 `.\mvnw.cmd test`（Windows）。

**应该看见：** 停机时旧列表可留下，但明确标成旧结果；恢复后错误消失。测试中包含只读角色写入被拒、旧版本被拒、缺关闭条件被拒。测试结果写实际数量，不把本段“应该看见”抄成已通过。

**失败时，只发这段修复提示：**

```text
后端停止时，我点击【页面和按钮】后看到【现象】。
请只修复这一处失败处理，并给出能复现它的测试；
不通过删除错误提示、自动切换模拟数据或忽略测试来处理。
```

**下一步：** 修好后重新启动 B，最后把九个菜单串起来走一次。

## 第6步：完整走一遍，留下自己的说明
