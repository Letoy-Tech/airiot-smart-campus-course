# 第 04 课：看懂读数，再做能源页

本课 4 学时，共 180 分钟。我们会把设备详情里的读数放到概览和能源页面，让使用者能先发现值得查看的地方，再找到具体设备。

五步建议用时：40、35、35、35、35分钟，共 180 分钟。这是备课建议，并非课堂实测；教师可按实际卡点调整。

继续原来的 `campus-lab`，保留终端 **A-页面**。本课练习数据的采样日期固定在 **2026 年 10 月 20 日**。刷新页面是重新显示这些样本，不代表设备刚刚采集了新数据。

今天只记住三个区别：**0 是一个读数；缺失是没有读数；较旧是有读数但不能当作现在的情况。**

**重新开课：** 打开原 `campus-lab`。若 A 已结束，在项目根的 A-页面运行 `node tools/serve.mjs`，再用上次的同一个浏览器打开 `http://127.0.0.1:5188`。若页面已能打开，就沿用原 A，不重复启动。本课不启动 Java、MySQL 或 Redis。

## 第 1 步：先把设备详情中的读数讲清楚

**本步时间：** 40分钟 = 工程训练10分钟 + 编码/操作30分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** 0、null、stale、invalid 各应显示什么？
- **亲手做：** 完成[测试实训练习A](../engineering/06-测试设计与故障定位.md)：在改代码前亲手写边界用例，再执行本步检查。
- **解释：** 解释一个“值存在但质量差”与一个“没有值”的区别。
- **证据：** 在 docs/测试记录.md 写输入、预期、实际和未通过项；只记实际结果，不写口令或token。

**现在在哪：** CodeBuddy 对话框。我们先整理已有详情，不另建一份数据。

```prompt
目标：读materials/约定卡.md和公开练习JSON，检查现有设备详情的points展示。
修改范围：设备详情读数展示。
必要约束：
每项读数清楚显示点位名、数值、单位、采样时间和质量。把temperature/humidity/power/voltage/status/brightness分别显示为温度/湿度/功率/电压/状态/亮度，同时保留原tagId方便后续查找。
严格保留0，null显示“缺失”；time=null显示“无采样时间”。quality依原始字段展示正常、较旧、缺失、无效，不能按本机今天的日期偷偷重写练习标签。
状态点若为0或1，先显示原始数值，不自行猜0一定表示故障。单位为空时不加一个编造的单位。
页面注明“固定日期的教学样本，刷新不会产生新的采样时间”。保留原设备筛选与详情入口，不启动服务。
验收：0、缺失、质量及原时间可辨。
```

**等到什么：** 等 AI 保存完成，刷新浏览器。

**自己点看：**

1. 在设备页搜索 `d05`，打开详情，找到功率。
2. 搜索 `d03`，打开详情，找到温度。
3. 搜索 `d04`，查看在线状态与读数质量。

**应该看到：** `d05` 的功率是 **0 kW**；`d03` 的温度显示 **缺失**，在线情况为 **未知**；`d04` 是离线设备，练习中的陈旧读数标为 **较旧**。这些情况各有自己的文字。

**如果 0 消失了或缺失变成 0：** 单独发送：

```prompt
第04课第1步的0与缺失显示错了。我将给出设备ID、点位和实际显示。请只修复数值判断：number类型的0必须保留，null显示缺失，不使用“value或0”这样的替代。不改练习数据，也不要重写其他页面。
```

三个样本正确后，进入第 2 步。

## 第 2 步：在概览中指出哪些读数需要留意

**本步时间：** 35分钟 = 工程训练5分钟 + 编码/操作30分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** 统计设备数与统计点位数为什么不同？
- **亲手做：** 手工选择两个点位验证质量分类和异常列表，不把它们当真实故障。
- **解释：** 说明聚合的统计对象与分母。
- **证据：** 在 docs/测试记录.md 记统计对象及核对值；只记实际结果，不写口令或token。

**现在在哪：** CodeBuddy 对话框。概览已经有三张数量卡片，这一步在它们下面加信息。

```prompt
目标：继续现有概览，从getOverview返回的数据计算。
修改范围：概览统计及读数入口。
必要约束：
1. 四个空间分别有多少台设备；四种设备类型分别有多少台设备。
1. points中正常、较旧、缺失、无效各有多少项；这四类是点位数量，不是设备数量。
2. 列出所有非fresh点位，包含设备名称、点位、质量、原采样时间和“查看设备”按钮。没有问题项时明确显示“当前样本没有需留意的读数”。
按钮必须打开现有设备详情并定位实际deviceId。不要复制一个详情页面，不把质量标签直接写成故障结论。
保留三张卡片和教学模拟说明。不启动服务。
验收：统计对象正确，入口定位同设备。
```

**等到什么：** 等 AI 保存完成。刷新浏览器，点击“概览”。

**自己点看：** 找到四种质量的数量，确认加起来是 28；在需留意的列表找到 `d03` 的温度，点“查看设备”。

**应该看到：** 概览中的问题项可以带你到同一台设备的详情；详情里的点位、质量和采样时间与概览一致。概览让你知道哪里要看，详情让你看具体内容。

**如果数量相加不是 28：** 单独发送：

```prompt
第04课第2步正常、较旧、缺失、无效四类点位数量相加不是28。请核对getOverview的points逐项计数，不按设备数计数，也不要把28写死。保留原始质量字段，只修复统计和对应列表。
```

统计和入口正确后，进入第 3 步。

## 第 3 步：能源页先只显示功率

**本步时间：** 35分钟 = 工程训练6分钟 + 编码/操作29分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** 功率与一段时间的耗电量是否同一量？
- **亲手做：** 在[模型记录](../engineering/templates/模型说明记录.md)列 quantity、unit、可比较对象；亲自排除非能源设备。
- **解释：** 向同伴说明缺少时间积分时不能声称kWh、电费或节能率。
- **证据：** 在 docs/模型说明.md 留功率字典与限制；只记实际结果，不写口令或token。

**现在在哪：** CodeBuddy 对话框。先完成一种读数，再做切换。

```prompt
目标：完善现有“能源”页面。
修改范围：能源功率页。
必要约束：
从getOverview中先选category严格等于energy的设备，再为它们找tagId=power且unit=kW的点位。按空间列出这四台能源设备的名称、功率、质量和原采样时间。
0正常显示；null显示缺失。缺少对应点位时显示“没有功率样本”，不要取其他设备或其他点位填补。
标题写“功率 kW”，下方用一句话说明“功率反映当前样本的用电强弱，本页没有累计用电量和电费”。
不把环境、设施、照明设备混入能源，不换算kWh、不编造费用或节能率。
每行保留“查看设备”按钮，打开已有设备详情。不启动服务。
验收：仅能源功率，不推算耗电。
```

**等到什么：** 等 AI 保存完成，浏览器刷新，点击“能源”。

**自己点看：** 数一数能源设备，应是 `d05` 至 `d08` 四台；找到 `d05` 的功率。

**应该看到：** 本页只有四台能源设备；功率单位统一为 **kW**，`d05` 仍显示 **0**。没有温度、湿度、亮度和电费卡片。

**如果出现了温度或不止四台：** 单独发送：

```prompt
第04课第3步能源页混入了其他设备或点位。我将说明多出来的内容。请先严格筛选category===energy，再找power/kW，保留0与null区别。不要只根据点位名称或页面顺序选数据，不改原始练习JSON。
```

四台功率显示正确后，进入第 4 步。

## 第 4 步：加电压切换，数值和单位一起换

**本步时间：** 35分钟 = 工程训练5分钟 + 编码/操作30分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** 换指标时哪些字段必须同时换？
- **亲手做：** 写一个功率→电压的检查清单，逐项检查标题、值、单位、时间、质量。
- **解释：** 解释旧指标值为什么不能暂留到新指标里。
- **证据：** 在 docs/测试记录.md 留切换结果；只记实际结果，不写口令或token。

**现在在哪：** CodeBuddy 对话框。继续刚才的能源页。

```prompt
目标：在能源页增加一个选择框，仅有“功率 kW”和“电压 V”，默认功率。
修改范围：能源指标切换。
必要约束：
选功率用power/kW，选电压用voltage/V。设备范围始终是category===energy的四台。切换时同时更新标题、数值、单位、质量和采样时间，不能留下上一种读数的数值。
保留缺失和0的区别。找不到对应点位显示“没有这项样本”，不拿其他点位替代。
保留现有查看设备入口，不加入总电费、累计电量或自动单位换算。
不启动服务，不提前做历史曲线。
验收：V/kW切换一致，缺项不借值。
```

**等到什么：** 等 AI 保存完成。刷新浏览器，打开能源页。

**自己点看：** 先选功率，记住 `d05` 显示的值；改成电压，核对同一台的单位为 V；再切回功率。

**应该看到：** 四台设备不变，但读数与单位一起变化。切回功率后，`d05` 的 **0 kW** 仍然存在。电压页面不会出现 kW 的旧标题。

**如果只换单位没换数值：** 单独发送：

```prompt
第04课第4步切换到电压后仍显示功率的数值。请只修复选项到tagId、unit、读数集合的对应，切换后重新选择当前点位，不能把旧值换个单位继续显示。保留四台能源设备和查看入口。
```

来回切换正确后，进入第 5 步。

## 第 5 步：把概览、能源和设备台账连起来

**本步时间：** 35分钟 = 工程训练4分钟 + 编码/操作31分钟（含AI生成等待、亲自运行与本步业务验收）。

- **先想：** 从能源入口来到详情，如何确认指标没有走丢？
- **亲手做：** 任选两个设备按原业务验收往返操作并口头报出ID与tagId。
- **解释：** 说明一个跨页用例包含哪些状态。
- **证据：** 在本课 notes 补一条真实跨页证据；只记实际结果，不写口令或token。

**现在在哪：** CodeBuddy 对话框。本步只完成入口衔接，不增加新页面。

```prompt
目标：检查并补齐现有页面之间的入口。
修改范围：概览/能源/设备已有入口。
必要约束：
概览点一个空间，进入现有设备页并只保留该空间筛选；
概览点“能源”类型，进入现有设备页并只保留energy类型筛选；
能源页点任一设备的“查看设备”，打开对应ID的现有详情，不默认第一台。
进入新筛选前清掉无关旧条件；从详情收起时仍保留本次筛选。所有页面继续从data-service读取同一份数据。
不重建页面、不复制表格。不启动服务。
验收：跨页设备与指标一致。
```

**等到什么：** 等 AI 保存完成，刷新浏览器。

**自己点看：** 先在设备页搜索 `d01`；回到概览点“能源”类型，确认现在能看到四台能源设备；再打开能源页，点 `d07` 的“查看设备”。

**应该看到：** 旧的 `d01` 搜索条件不会挡住能源列表；详情确实是 `d07`；回到能源，切换功率和电压仍正常。

**如果入口被旧筛选挡住：** 单独发送：

```prompt
第04课第5步从概览进入设备页后被旧筛选挡住了。请只修复这个跨页入口，在设置本次空间或类型条件前清空无关条件。保留用户在同一设备页内部查看和收起详情时的筛选。
```

完成后，在 `notes/04-读数和能源.md` 写下三句话：0 与缺失有什么不同；采样时间与刷新页面时间有什么不同；本页为什么不能算电费。保存 `d05` 的 0 kW 和 `d03` 的缺失温度两张截图。
