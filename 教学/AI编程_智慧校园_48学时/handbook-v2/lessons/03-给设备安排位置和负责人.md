# 第 03 课：给设备安排位置和负责人

本课 4 学时，共 180 分钟。我们要回答两个简单问题：这台设备在哪栋楼、哪一层？出现问题时由谁处理？

五步建议用时依次为 30、35、35、45、35 分钟，共 180 分钟。这是备课建议，并非课堂实测；教师可按实际卡点调整。

继续打开原来的 `campus-lab`，让终端 **A-页面** 运行。浏览器地址仍是 `http://127.0.0.1:5188`。本课只在自己的浏览器中保存练习内容，还没有数据库。换一台电脑或换一个浏览器，不会自动带上这些记录。

**重新开课：** 打开原 `campus-lab`。若 A 已结束，在项目根的 A-页面运行 `node tools/serve.mjs`，再用上次的同一个浏览器打开 `http://127.0.0.1:5188`。若页面已能打开，就沿用原 A，不重复启动。本课不启动 Java、MySQL 或 Redis。

## 第 1 步：把四个空间做成看得懂的页面

**现在在哪：**CodeBuddy 对话框。发送：

```prompt
继续当前项目，只完成第03课第1步。读取materials/约定卡.md，使用data-service.js的getSpaces和getDevices完善现有“空间”页面。
按原始s1到s4显示四个空间，每个空间展示名称、楼栋building、楼层floor，以及属于它的设备数量。设备按spaceId归属，数量必须计算。
每个空间有“查看设备”按钮，点击后进入现有设备页，并只筛选此spaceId；清空其他旧筛选，保留空间这一项。不要另外复制设备表。
显示“浏览器演示：本课修改只保存在当前浏览器”。先不增加编辑功能。
保留前两课功能，保存文件，不启动服务。
```

**等到什么：**等 AI 保存完成，刷新浏览器，点击“空间”。

**自己点看：**找到四个空间；选择其中一个，记住名称，点“查看设备”。

**应该看到：**进入原来的设备页，空间筛选框显示刚才选中的空间；设备各行的空间名称一致。点“清空筛选”后恢复 16 台。

**如果显示了其他空间的设备：**单独发送：

```prompt
第03课第1步从空间点“查看设备”后筛选不对。我将补上所点空间和实际设备列表。请只检查spaceId的传递与设备页筛选，不用空间名称或数组行号猜ID，不新建第二套设备页面。
```

空间到设备的入口正确后，进入第 2 步。

## 第 2 步：修改一个空间的楼栋和楼层

**现在在哪：**CodeBuddy 对话框。我们先让表单能保存，再在下一步检查刷新后是否保留。

```prompt
只完成第03课第2步。在现有空间页面给每个空间增加“编辑位置”按钮。
打开表单后显示该空间名称，只允许修改building和floor，不修改空间ID、不修改设备ID、不移动设备归属。表单有“保存”和“取消”。
在data-service.js中增加异步saveSpace(id,{building,floor})。两个值去掉首尾空格后必须非空；失败时保留输入并显示清楚的提示。成功后返回更新的空间，页面重新读取getSpaces再展示结果。
将修改先保留在data-service的当前运行数据里，不改mock-data.js原始练习数据。页面标明“浏览器演示”。
保存文件，不启动服务，不做负责人功能。
```

**等到什么：**等 AI 保存完成。浏览器刷新，打开空间页，选择第一张空间卡的“编辑位置”。

**自己点看：**把楼栋改成 `教学楼A`、楼层改成 `2层`，点“保存”。再打开编辑，把楼层内容清空，尝试保存。

**应该看到：**第一次保存后卡片显示新位置；第二次不允许保存，并明确提醒楼层不能为空，表单仍在，原来已经成功保存的位置没有被清空。

**如果空内容也保存成功：**单独发送：

```prompt
第03课第2步空间位置表单允许保存空内容。请同时检查页面和saveSpace：building、floor去空格后不能为空；失败保留本次输入，不覆盖上次成功的位置。只修复这个问题。
```

把表单恢复为有效楼层并保存，进入第 3 步。

## 第 3 步：让刷新后的浏览器记得位置

**现在在哪：**CodeBuddy 对话框。本步用到的 `localStorage` 可以理解为浏览器里的一小块保存位置。它不是 MySQL 数据库。

```prompt
只完成第03课第3步。在data-service.js中给空间演示增加浏览器保存功能。
统一使用localStorage键campus-v2-demo，以一个对象保存演示spaces、owners、cases。现在已有空间修改写入spaces；owners和cases暂时保留为空或保留已有内容，不相互覆盖。
启动时先读取原始mockCampus，再合并已保存的空间位置；getSpaces、getOverview返回同一份当前空间数据的副本。saveSpace成功才保存。JSON损坏或浏览器禁止保存时，显示可理解的错误，不默默清空其他演示记录。
让空间页和设备表的空间信息一起更新；保留“当前浏览器演示，尚未写入数据库”说明。不要新增“清空全部”按钮。
保存文件，不启动服务。
```

**等到什么：**等 AI 保存完成。刷新浏览器后，重新编辑刚才那个空间，保存 `教学楼A / 2层`。

**自己点看：**按浏览器刷新，回到空间页；再点“查看设备”并打开一台设备详情。

**应该看到：**空间卡片仍显示新位置；关联页面展示的是同一空间。把浏览器标签页关闭后重新打开同一地址，位置也仍在。这个结果只证明当前浏览器保存成功。

**如果刷新后恢复旧位置：**单独发送：

```prompt
第03课第3步保存位置成功，但刷新后又变回原值。请检查campus-v2-demo的写入、读取和合并顺序，只修复空间演示保存。不要删除浏览器已有记录，不改原始mock-data，也不要加数据库。
```

位置能保留后，进入第 4 步。

## 第 4 步：给一台设备登记负责人

**现在在哪：**CodeBuddy 对话框。接下来进入第 01 课已经建好的“设备责任”菜单。

```prompt
只完成第03课第4步。完善“设备责任”页面，显示设备编号、名称、当前负责人、备注和“登记”按钮。
增加异步getOwners()和saveOwner(deviceId,{username,note,expectedVersion})。负责人本课固定可选manager，页面写“处理人 manager（课堂角色）”，不要编造真实人员账号。
没有登记时写“尚未登记”，版本视为0。首次保存后version为1，后续保存+1；提交时使用刚读取的版本。如果版本不一致，提示重新读取后再决定，不自动重试。
备注去掉首尾空格后不能为空。保存在campus-v2-demo对象的owners部分，保留已有spaces、cases。
保存成功后重新读取负责人列表再显示；页面持续标明浏览器演示。不要把这里写成真实权限控制。
保留其他页面，保存文件，不启动服务。
```

**等到什么：**等 AI 保存完成，刷新浏览器，点击“设备责任”。

**自己点看：**找到 `d01`，点“登记”，选择处理人 `manager`，备注填写 `日常巡查联系这位处理人`，保存。刷新后再次查看 `d01`。

**应该看到：**`d01` 有负责人和刚才的备注，版本为 1；其他设备仍可显示“尚未登记”；第 3 步修改的空间位置仍在。版本只是这一条记录改过多少次的标记，现在先会看即可。

**如果保存责任后空间修改消失：**单独发送：

```prompt
第03课第4步登记负责人后，前面保存的空间位置消失了。请修复campus-v2-demo对象的局部更新：写owners时保留spaces和cases，写spaces时也保留其他部分。不要通过清空本地记录解决问题。
```

负责人能保存、空间没有丢失后，进入第 5 步。

## 第 5 步：从设备详情找到负责人，再回到空间

**现在在哪：**CodeBuddy 对话框。我们把本课新增的页面接回前两课的入口。

```prompt
只完成第03课第5步。继续已有设备详情，展示本设备当前负责人和备注，未登记时明确写“尚未登记”。
添加“查看责任登记”入口，打开现有设备责任页面并定位本设备；添加“查看所在空间”入口，打开现有空间页面并定位其spaceId。
空间和责任修改后，回到设备详情应重新读取当前内容，不显示旧副本。保留原有设备筛选、在线状态、读数和收起详情。
不用复制新页面，不添加数据库或登录。保存文件，不启动服务。
```

**等到什么：**等 AI 保存完成，浏览器刷新。

**自己点看：**设备页搜索 `d01`，打开详情，查看负责人；点“查看责任登记”，核对仍是 `d01`；回设备详情，点“查看所在空间”，核对空间 ID 一致。

**应该看到：**这三个入口说的是同一台设备、同一个空间、同一条负责人记录。页面没有把设备的显示顺序当成编号。

**如果跳到了别的设备或空间：**单独发送：

```prompt
第03课第5步跨页面跳转定位错了。我将给出出发时的设备ID、目标页面实际ID。请只修复稳定ID的传递和目标页定位，保留原页面，不新建副本，也不按数组序号定位。
```

完成后，在 `notes/03-位置和责任.md` 记录：你修改的空间；你登记责任的设备；刷新后两项是否还在。保存一张 `d01` 详情中显示负责人信息的截图。
