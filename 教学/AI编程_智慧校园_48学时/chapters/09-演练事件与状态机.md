# 第 09 章：演练事件与状态机

状态：`DESIGNED`；4 学时，模块分配为 1＋2＋1。本章是课程设计源稿；实验步骤和结果均待配套教学工程验证。

## 进入条件与学习目标

已完成设备台账、数据质量展示及三角色授权，能解释接口请求和数据库记录的区别。教师须先制作隔离数据库、ADMIN、管理人员 A、管理人员 B、VIEWER 四个身份及本地场景数据，并提供路由、DTO、Mapper、事务与详情页表单骨架。本章学生集中补齐状态门槛、本人范围、版本检查及失败处理，通过同一闭环核验；不要求在两个实践学时从空目录编写全部框架和页面。本章不操作现有学校 DEMO。

完成后，学生能画出合法状态迁移，用后端规则拒绝非法动作；能完成一次演练闭环，并解释为什么“模拟恢复”“核实通过”“关闭事件”是三个动作；能处理旧版本冲突，展示与事件一起保存的时间线。

## 模块一：把业务叙述改写为状态机（1 学时）

以“模拟温度巡查”为例：管理员创建本地事件，指派处理人员，处理人员开始、记录处置，管理员模拟来源恢复，处理人员请求后端核实并关闭。

| 当前状态 | 动作与条件 | 后续状态 |
| --- | --- | --- |
| `NEW` | 管理员指派有效人员 | `ASSIGNED` |
| `ASSIGNED` | 管理员或本人开始处理 | `IN_PROGRESS` |
| `IN_PROGRESS` | 有权处理者追加记录 | 保持原状态 |
| 未关闭 | 管理员重新指派 | `ASSIGNED` |
| `IN_PROGRESS` | 全部关闭门槛满足 | `CLOSED` |
| `CLOSED` | 任意修改请求 | 拒绝 |

来源状态 `ACTIVE/RECOVERED/UNKNOWN` 与处置状态分别保存。`sourceType=DEMO`、`sourceScope=LOCAL_DEMO`、`simulated=true` 必须可见；模拟事件不证明关联设备真的异常，也不进入上游原始报警列表。

小组把关闭规则写成检查表：已有 `NOTE`；当前处理中；来源为本地 DEMO、`sourceState=RECOVERED`、`sourceRawStatus=DEMO_RECOVERED`，恢复时间不早于发生时间；服务端独立核实为 `PASS`、核实时间非空且不早于恢复时间；结论非空；权限和版本正确。不能只检查一个“已恢复”勾选框。

产出：状态图、动作权限表及至少四个反例。

## 模块二：实现一个有记录的处置闭环（2 学时）

接口沿用 `/campus/alarm-cases` 及其 `assign/start/notes/verify-recovery/close` 动作。场景触发和模拟恢复使用 `/campus/demo-alarm-scenarios/{scenario}/trigger`、`/campus/demo-alarm-events/{id}/recover`，后者的 id 是事件 id。

对已有事件的更新携带刚读取的 `expectedVersion`，它是非负 JSON 整数；字符串、浮点数和 Boolean 均返回 400。场景触发为空 body 或 `{}`，不传版本。后端在同一事务内锁定主记录、检查权限/版本/状态、更新版本并插入时间线。版本匹配且未关闭事件的重复恢复是无变更例外：返回当前详情，不增加版本和时间线。操作者与时间取自服务端；客户端不得上传恢复结论。页面按实际响应更新，旧版本返回 HTTP 409 `VERSION_CONFLICT`，状态不合法返回 409 `STATE_CONFLICT`。

最小实验：

1. 管理员触发 `temperature-patrol`，记录事件 id 和初始版本 1；未配置责任人时为 `NEW`。
2. 指派给管理人员 A；A 回读最新详情并开始处理。以 A 的实际身份请求，不能只切换页面角色标签。
3. 尝试直接关闭，应被拒绝；追加一条说明检查方法和发现的 `NOTE`。
4. 恢复前请求核实，应得到 `UNKNOWN`、空核实时间；该动作会记录时间线，随后重新读取版本。
5. 管理员模拟恢复，处置状态仍为 `IN_PROGRESS`；恢复会把核实结果重置为 `PENDING`。
6. A 回读后独立请求核实，取得 `PASS`；填写结论并用最新版本关闭，刷新页面验证持久化。
7. 在另一条事件用过期版本写记录，页面保留输入并回读最新详情，明确让学生重新判断，不自动重放旧请求。

产出：事件服务、详情页和动作表单；脱敏请求/响应及时间线记录。真实数据库回滚和并发的完整验收在第 11 章完成。

## 模块三：用反例审查业务规则（1 学时）

同桌轮换为操作者和审查者：A 尝试处理分派给 B 的事件、查看者直接调用写接口、管理员重新指派处理中事件、已关闭事件再次追加记录。对重新指派，应保留旧记录并回到 `ASSIGNED`，新负责人需要重新开始。

人工检查后端是否真正拒绝越权；检查恢复、核实和关闭是否有各自时间线；检查响应失败时页面是否错误显示成功。产出一份缺陷单，包括复现步骤、预期、实际和修复验证。

## 典型问题、巩固与接力

按钮消失但接口仍可写：检查后端授权。恢复后不能关闭：按时间线定位 `NOTE`、核实结果和版本，不删除门槛。版本连续冲突：检查是否仍使用列表旧对象，以及核实是否已经递增版本。时间线缺动作：检查事务和插入逻辑，不在前端补造记录。

课后独立解释“为什么恢复不能自动关闭”，并补一条非法迁移用例。进阶可绘制时序图或补充关闭条件边界测试，不接入真实控制和外部通知。
