# 第 05 章教师参考：空间引用校验

仅供教师备课和提交预测后的讲评。建议4学时：45分钟理解、90分钟操作、45分钟核验；30人分15组，实践中交换实现者与审查者。每章只有约定检查点由学生填写，框架、其他章节功能和安全基础已预置。

## 关键答案与讲评顺序

教师先打开 `LocationService.validateBinding`，指出控制器、权限、输入校验、事务和参数化 Mapper 已完成。学生只补 C05；创建校园与楼栋是通过现有页面理解写入链路，不另要求从零实现这些接口。

```java
if (provider.spaces().items().stream().noneMatch(s -> s.id().equals(spaceId))
        || mapper.building(buildingId) == null) {
    throw ApiFailure.missing();
}
```

空间来自 Provider，楼栋来自本地库，两侧都要存在。先以管理员创建校园，再使用实际返回的 campusId 创建楼栋，以返回 buildingId 绑定 teaching_space_01；floor 可为 null。GET locations 与 spaces 应一致，重启同库后仍保留。合法名称“  北区  ”写入后为“北区”；重复名称按实际409处理，不覆盖。

非法空间、非法楼栋分两次测，其他条件均合法，预期404并且无绑定变化。VIEWER使用自己的有效CSRF会话发送完全合法写请求，预期403；缺CSRF的403不能单独证明角色判断。

## 常见故障与课堂替代

404先核对真实ID，不猜名称；500先由教师检查组库迁移与权限；重复名称改用明确组号或读取既有记录，禁止重置他组数据。

数据库临时不可用时，用已脱敏请求/回读进行关联预测；登记AC02未实测。可从ch05救援副本恢复，仅保留本人的C05差异。

## 课后题参考答案


**练习一：**某设备 `online=null`，同学为了页面整齐改成 `false`。请写出失真的含义。

答案要点：未知通信状态被改成明确离线，后续巡查可能产生错误结论；DTO 保留 `null`，页面显示“未知”。仅改显示文案不能修复已经丢失的语义。

**练习二：**空间绑定的写响应成功，但紧接着的 GET 超时，是否应再次执行创建校园？

答案要点：不能据此判定原操作失败。写入提交与回读网络结果是两个事实，应先重新读取并核对标识；创建操作没有本章保证的自动重放机制。

**练习三：**为什么不能只用外键验证 `spaceId`？

答案要点：空间来自数据端口，不一定存在于同一个数据库。服务先检查来源空间，本地外键或关联校验负责楼栋与校园；两种检查覆盖不同边界。
