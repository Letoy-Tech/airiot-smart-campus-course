## 进入本章与共同命令

使用教师发放的 `student-chapters/ch12/` 独立目录，保留上一章作品，不覆盖历史。每章起点只留当前任务块，其他章实现由教师预置；不得把预置代码写成本人从零实现。课前按[启动说明](01-跨平台启动.md)核对Node22.21.1、JDK17、JAVA_HOME与锁文件；第05章起采用教师分组MySQL，按[数据库交接单](02-教师数据库交接单.md)落实本组配置和迁移，密码不进入网页AI或Git。

以下命令在当前章节工程根目录执行，Windows/macOS相同。前端依赖尚未安装时先运行`npm --prefix frontend ci`（PowerShell可用`npm.cmd`）。

```text
node tools/course.mjs doctor
node tools/course.mjs init
```

未补块前需要的页面/响应观察使用教师投影或脱敏样例，个人实际记录在补块后重做。在模块一先预测、补C12并做针对性回归；模块二再执行`node tools/course.mjs check`和`node tools/course.mjs build`，不要先要求未补C12的起点通过。build含Java普通测试，前端单元检查由check执行。教师显式执行本组授权迁移后，在两个终端分别启动`node tools/course.mjs backend-db`与`node tools/course.mjs frontend`；浏览器进入`http://127.0.0.1:5178/#cases`。后端first-chain入口只供第04章，不能用它的501或两设备结果验收本章完整业务。不要重复启动占用8091/5178的进程。

每份新副本先按启动说明建立一次[学生Git基线](01-跨平台启动.md#学生副本的-git-基线每个新章节一次)，不重新初始化已有本人仓库。每份新副本均须执行`node tools/course.mjs init`初始化本机账号（与Git初始化不同）；登录使用该副本本机生成的密码，组数据库仍保存角色/启用状态。不要混用上章密码或为修登录删除旧库身份。修改Java后停止本组后端、重新build并启动；修改前端通常由Vite更新，但失败快照实验保持页面不刷新、不靠热更新造故障。未补本章任务时，对应检查失败属于起点；填好后运行：

```text
node tools/course.mjs check
```

`check`包含的普通测试不自动等于MySQL集成通过；数据库实际检查另按第11章执行。真实结果填写本章任务单，文中“预期”不当作已发生的记录。

## 教师课前准备：可执行的分页演示数据

这是**待教师实际执行并记录**的课堂准备说明，本次修订没有向数据库写入。使用单独的空白分页演示库，不共用第09—11章学生历史库。按[数据库交接单](02-教师数据库交接单.md)另配授权 schema、迁移和本机配置，再以完整模式启动；不得通过清空旧库凑数据。不是空库时，请教师另供独立库。以下由教师在参考工程或已经补好 C12 的副本操作，不要求学生在未补块时准备数据。

1. 登录 `admin`，在 `#cases` 的 Network 查看 `GET /api/campus/alarm-cases?limit=10&skip=0`：必须业务成功且 `data.total=0`。在责任页面/读取 `GET /api/campus/device-owners/teaching_env_01`，确认 `ownerUid=null`，否则新事件可能自动分派；不要靠修改既有责任或清库补救，改用独立初始库。
2. 读取 `GET /api/campus/alarm-cases/handlers`，确认实际候选含 `uid="manager-a"`（显示名“管理人员 A”）且当前有处理资格。这里用实际教学账号，不把场景规格中的逻辑键 `teaching_manager_a` 发给接口。没有该候选则先由教师修复本演示库账户状态。
3. 在事件页选择“温度巡查”，逐次点击“触发本地演练”14次；每次等成功并回读后再点下一次。实际写接口是 `POST /api/campus/demo-alarm-scenarios/temperature-patrol/trigger`，请求体 `{}`。记下14个不同的返回ID，逐条确认 `state=NEW`，最终总数14。一次请求失败或结果不确定时先回读，不自动重发造成多条。
4. 在这14条中任选两条，分别打开详情、读取当前版本、选择“管理人员 A”、填写非空分派说明并分派。对应 `POST /api/campus/alarm-cases/{实际id}/assign`，字段为 `assigneeUid:"manager-a"`、非空 `note`、该条刚读取的 `expectedVersion`。成功后独立回读为 `ASSIGNED`；不要点击“开始处理”，其他12条保持 NEW。Cookie/CSRF由既有页面处理，记录中不保存令牌。
5. 再读列表验证：不带state时 `total=14`；`state=NEW` 时12；`state=ASSIGNED` 时2；`state=IN_PROGRESS` 时0。每次均为 `limit=10&skip=0`。保留教师准备日期、库代号、14个ID和脱敏回读，实验期间暂停他人写入；预期数量不写死到前端。

页面每页10条。后端先筛选再计数/分页，排序为 `createdAt DESC, id DESC`；创建时刻相同时由ID决定稳定次序，不假定触发顺序等于列表顺序。`fixtures/pagination-scenarios.json` 的4条/limit=2是独立API边界规格，未自动建库、未执行，不能当作本页面已经具备的夹具。课前数据不齐时记录阻塞，使用教师观察记录完成预测；个人浏览器验证仍待补做。

### 模块一：记录起点、补 C12 与针对性回归（1学时）

1. 前10分钟检查本人Git起点和文件清单，记录基线A：其他章节功能由教师预置，本章C12未完成。写出“当前页skip>0再换状态”的预期，保留起点的预期失败。
2. 接着20分钟只补 `course.ts` 的C12 `changeCaseState`，复用已有合法状态校验，令state变化时skip=0；不重写事件接口，不改数据库。运行 `npm --prefix frontend run test:unit -- --run src/tests/course-domain.test.ts src/tests/workflow-views.test.ts`，核对相关断言。
3. 最后15分钟核对针对性单元/组件结果，并对教师分页演示逐项预测：①“全部”第二页切到 ASSIGNED，请求skip=0并显示2条；②切到 IN_PROGRESS，成功空结果；③切到 NEW 的第二页后刷新，保留NEW但首个请求skip=0；④未知state回到默认值、不发送非法状态。教师投影只记观察；本人的实际浏览器请求在模块二完整构建启动后重做，不把旧skip导致的空页当没有事件。形成含C12修改和针对性测试结果的基线B，浏览器未执行项单列。

### 模块二：交付基线 B、交叉复现与第一轮展示（2学时）

4. 前15分钟补README的版本、Node/JDK、数据库交接、初始化/迁移/启动/停止和测试入口；在B上运行check与build、保存结果并打包。只放无秘密源码、锁文件和配置说明，`.private`、Cookie、密码、真实学校数据不打包。构建成功不等于数据库和浏览器业务验收。
5. 接着30分钟由同伴在独立目录或另一台已预检机器按README复现B：锁定依赖、本副本init、教师分配的独立schema和迁移、完整启动、角色读取、一条事件或责任关键路径及一个对应拒绝。在已由教师准备分页数据的独立演示库重做步骤3的实际请求，C12重验筛选/刷新/分页，其他章节引用已有真实证据，不在30分钟内重做整套平台验收。教师课前备好依赖与隔离库；未完成项记补做，不冒充通过。
6. 最后45分钟前9组各5分钟展示及个人问答，其他组按验收表观察。每组两人都要解释一个判断，不只由一人演示。

### 模块三：其余答辩与个人交付（1学时）

7. 前30分钟后6组各5分钟展示；最后15分钟每人回答退出题：输入怎样进入代码、为何拒绝一个反例、一次AI建议取舍、仍未覆盖的证据。伙伴不能代答。
8. 交付源码与锁文件、迁移、无秘密配置说明、版本、需求/合同决策、分层测试与缺陷、AI代表记录、HANDOFF。不把node_modules/target/dist的偶然副本作为源码；若另交构建产物须标版本、哈希与用途。
9. Windows物理设备、课堂时间或真实AIRIOT未测即保留未测；作者参考代码验证与本人课堂验收分别记录。公网部署、设备控制、通知均非必修。起点A有已知缺口，不是已通过的回退版本；救援参考须标明教师提供，不能删除或覆盖数据库来恢复代码。

## 验收与停点

| 验收 | 可见依据 |
| --- | --- |
| AC11变更 | 筛选/刷新skip归零、合法state恢复、竞态和失败语义 |
| AC12复现 | 接手者、独立目录/库、实际命令与核心结果，缺口单列 |
| 交付完整 | 锁文件/迁移/无秘密配置/版本/证据/HANDOFF可定位 |
| 个人答辩 | 独立解释一个分支、一个失败与一次AI判断 |

常见故障：作者电脑能跑但新目录失败先查漏锁文件/迁移/配置来源；错误空页查skip；旧代码回退不等于旧数据恢复，不能用覆盖数据库“修复”交付。
