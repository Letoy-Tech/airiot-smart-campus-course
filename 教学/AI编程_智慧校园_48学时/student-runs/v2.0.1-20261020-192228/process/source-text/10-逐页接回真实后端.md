# 第10课：把空间、读数、历史和责任逐页接回后端

这节课沿用前六课已经做好的页面。先让后台准备页面要用的数据，再逐页替换取数方法。每接好一页，就亲手点一遍。

本课4学时，共180分钟。五步建议用时：35、40、35、35、35分钟。

**重新开课：** 用 CodeBuddy 打开原 `campus-lab`，保留已有 `.env`，不重新生成密码。先打开 Docker Desktop并等引擎运行。C 在项目根执行 `docker compose up -d`，用 `docker compose ps` 等 MySQL、Redis 都 `healthy`。A 若已停止，在项目根执行 `node tools/serve.mjs`；若仍运行就沿用，不重复启动。

有旧后端在运行时，先在原 B 按 Ctrl+C。新 B 按[第07课第2步](07-看着页面做第一个后端.md#第2步准备后端终端确认它用的是-java-17)设置本窗口的 Java 17，执行 `java -version` 确认。B 从根目录进入 `backend`：macOS 用 `cd backend`，Windows PowerShell 用 `Set-Location backend`；已经在 `backend` 不重复进入。B 先保持停止，第1步改完后再启动。

本课每次修改 Java 后，都在 B、`campus-lab/backend` 使用同一组命令：macOS 先 `sh ./mvnw test`，成功再 `sh ./mvnw spring-boot:run`；Windows PowerShell 先 `.\mvnw.cmd test`，成功再 `.\mvnw.cmd spring-boot:run`。后端运行后才回网页登录。只改前端时保存、刷新、重新登录即可。

## 第1步：把公开练习读数放进数据库

**现在在哪：** B 停止，CodeBuddy 打开 `materials/mock-campus.json` 与已有后端。

**发给 CodeBuddy：**

```text
请按materials/约定卡.md增加V3迁移，建立points、history、alarms、owners所需表。
把公开mock-campus.json中的28个点、历史样本与原始报警放进MySQL；
owners初始为空。保留已存在的空间、设备和账号，不改V1/V2，不删表。
实现需登录的GET /api/overview，data为{spaces,devices,points,history,alarms}；
从数据库读取，字段与前端已有模拟数据约定一致。
历史按时间排序，null保留为空缺，0保留为有效读数，unit与点位一致。
不生成不存在的实时数据，不使用电脑当前时间冒充采样时间。
给null、0与单位保持添加针对性测试。不要修改前端，不启动服务。
```

**等 AI 完成并保存：** 找到新增 `V3`，确认数据来自公开练习文件；旧迁移和账号未被覆盖。

**亲自操作：** 在 B 按本课开头对应系统执行“测试→启动”。校园网页用 `admin` 登录，然后检查“后端连接”仍成功。

**应该看见：** 后端能启动，迁移完成。前端尚未替换的菜单仍是浏览器演示；本步只是准备了它们需要的真实接口。

**失败时，只发这段修复提示：**

```text
新增V3后，测试或启动出现【不含私密信息的错误】。
请只检查本次新增表、公开数据导入和overview读取；
不要修改已执行的迁移，不删除旧数据，不把null改为0绕过失败。
```

**下一步：** 后端启动正常后，先接概览、能源两页。

## 第2步：接通概览和能源，保留每个数值的含义

**现在在哪：** A、B、数据库都在运行。CodeBuddy 打开 `frontend/data-service.js`，同时查看概览与能源页面代码。

**发给 CodeBuddy：**

```text
请把现有概览和能源页接到需登录的GET /api/overview，沿用内存token。
只替换数据来源，保留原有菜单、卡片、筛选与点击跳到设备详情的动作。
概览使用接口实际数量；能源只取category=energy的设备，
可选点仅power与voltage，单位分别kW和V，不能混入环境temperature/humidity。
null显示“暂无读数”，0显示0；陈旧和异常质量继续给出提示。
页面标明“本机后端保存的教学模拟数据”和原采样时间。
刷新失败保留旧成功快照并标出失败，不自动回退mock。
不计算kWh、电费或节能率，不启动服务。
```

**等 AI 完成并保存：** 保存后刷新网页并重新登录。前端刷新需要重登是第09课的内存令牌设计。

**亲自操作：**

1. 打开概览，核对4个空间、16台设备。
2. 点击一张卡片，进入对应筛选的设备列表；点击设备确认详情一致。
3. 打开能源，选择功率，再切换电压。分别检查单位与选项。
4. 找到练习数据中的零值与缺测值，确认显示不同。

**应该看见：** 能源页只有4台能源设备；功率不是电量。切到电压后不能仍保留标着 kW 的旧图或旧数值。

**失败时，只发这段修复提示：**

```text
我在能源页选择【功率/电压】后看到【错误现象】。
请对照完整16台混合目录，仅修复能源类别过滤、点位选择或单位同步，
不要删掉其他类别练习数据，也不要把错误值直接隐藏成0。
```

**下一步：** 概览和能源正确后，再接历史与原始报警。

## 第3步：让历史入口带对设备，让原始报警保持只读

**现在在哪：** CodeBuddy 打开历史、原始报警和设备详情相关前端代码，B 保持运行。

**发给 CodeBuddy：**

```text
请把现有历史页与原始报警页接到GET /api/overview里的history和alarms。
保留现有图表和列表。设备详情的“查看历史”必须把当前deviceId与tagId带到历史页；
在能源页每台设备旁新增“查看当前指标历史”按钮，
按钮带当前能源deviceId与当前选择的tagId；功率切成电压后，入口也跟着切换。
切换设备/指标时清除不匹配的旧曲线，只显示新选择对应的单位和采样时间。
历史中的null画断点，0画真实零；没有样本时说“这段时间暂无样本”。
原始报警只读，不增加关闭、恢复、删除按钮，不把报警混进本地演练事件；
每条报警保留或增加“查看设备”入口，带该报警deviceId进入已有设备详情。
所有API失败明确提示，不能静默回退浏览器模拟。
不要启动服务。
```

**等 AI 完成并保存：** 保存、刷新并重新登录，然后用原来的菜单检查。

**亲自操作：** 从设备详情点“查看历史”，记住设备 ID 和指标；在历史页核对同一 ID 与单位。再在能源页选择电压，点击一台设备旁的“查看当前指标历史”，核对同一设备与单位 V。最后打开原始报警，点击一条报警的“查看设备”，核对它打开的是该报警对应的设备详情。

**应该看见：** 页面之间传递的是同一台设备；缺测没有被连成假读数；原始报警只有查看操作，来源仍为教学模拟。

**失败时，只发这段修复提示：**

```text
我从【设备详情/能源】的【设备ID和指标】进入历史，
页面却显示【实际设备或指标】。
请只修复入口传参、当前选择和旧图清理，不新建另一套历史页，不改原始数据。
```

**下一步：** 读取路径通了，再保存第一个真实页面修改。

## 第4步：让空间修改真正保存，刷新还能看见

**现在在哪：** 先在 B 按 Ctrl+C。A 与容器保持运行。

**发给 CodeBuddy：**

```text
请实现GET /api/spaces和PUT /api/spaces/{id}。
读取允许三个已登录角色；修改仅ADMIN，接收building和floor，
检查空间存在、字段非空与长度合理，使用参数绑定SQL。
在后端判断角色，不能相信请求中的role或前端按钮状态。
把已有空间页面接到这些接口，移除这部分localStorage写入；
保存成功后独立GET回读，再更新页面与概览中的空间信息。
其他角色能看但不能提交；403清理当前无权编辑的内容并说明原因。
新增后端测试证明VIEWER不能修改，ADMIN可以合法修改。
不要修改责任和事件功能，不启动服务。
```

**等 AI 完成并保存：** 查看空间页面仍是原来的页面；操作范围只扩大到后端保存。

**亲自操作：** B 按本课开头的“测试→启动”。浏览器刷新后用 `admin` 登录，选空间 `s1`，把楼栋改为“教学楼 A”、楼层改为“1层”，点保存。刷新整个网页，重新登录，再查看 `s1`。退出后以 `viewer` 登录，查看同一个空间。

**应该看见：** 重新登录后仍能读到刚保存的空间信息。viewer 只能看。后端测试中直接用只读角色发修改请求会被拒绝；仅看到按钮隐藏还不能证明这一点。

**失败时，只发这段修复提示：**

```text
空间保存后，我刷新并重新登录，实际显示【结果】。
请检查PUT是否真正写入MySQL，以及成功后是否独立GET回读；
不要继续写localStorage，不要仅修改页面文字制造保存成功。
```

**下一步：** 空间真实保存后，登记责任人，为下一课自动分派事件作准备。

## 第5步：把设备责任交给管理人员，并处理旧版本

**现在在哪：** 停止 B，CodeBuddy 打开已有“设备责任”页面。

**发给 CodeBuddy：**

```text
请实现GET /api/owners和仅ADMIN可用的PUT /api/owners/{deviceId}。
提交username:"manager"、非空note、expectedVersion。
没有记录时当前version为0；成功写入后version加1；
若提交版本落后，返回409，不覆盖新记录。
把现有责任页接到接口。点保存前使用最近读到的version；
成功后独立GET回读；409时读取新记录并提示学生重新决定，不能自动重发。
责任列表允许已登录用户查看。记录保存在MySQL，不再保存在localStorage。
测试无权修改、合法修改、旧版本冲突。不要启动服务。
```

**等 AI 完成并保存：** 看完修改文件，再运行 B 的“测试→启动”。

**亲自操作：** 浏览器重新登录 `admin`，为 `d01` 登记责任人 `manager`，填写“负责本课演练巡查”并保存。记下显示的版本，再刷新、重新登录，核对责任仍在。

接着新开第二个校园网页标签，在两个标签都登录 `admin` 并打开 `d01` 的责任编辑。先在第一个标签改说明并保存；第二个标签保持旧版本，改一段不同说明再保存。

**应该看见：** 第二次旧版本提交收到“记录已更新，请重新查看”的提示，而不是覆盖第一标签的新说明。重新查看后由你决定是否再保存。两个标签分别登录，因为令牌只在各自页面内存中。

**失败时，只发这段修复提示：**

```text
两个标签编辑同一责任记录时，第二个旧版本提交得到【结果】。
请只修复后端版本比较与前端409处理，
不要自动重试旧决定，不关闭版本检查，不把测试改成接受覆盖。
```

**下一步：** 在数据进度表标明：设备、空间、概览、能源、历史、原始报警、责任已接后端；事件、审计留待下一课。下课停 A、B，在 C、项目根执行 `docker compose stop`。
