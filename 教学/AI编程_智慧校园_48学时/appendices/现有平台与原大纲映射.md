# 现有平台与原大纲映射

## 参考材料

课程参考 [系统 README](../../../system/README.md)、[接口合同](../../../system/docs/api-contract.md) 和 [智能软件工程教材大纲 通用版](../../智能软件工程教材大纲_通用版.docx)。前两者提供现有业务与工程边界；原通用大纲提供软件生命周期知识结构。原文件保持不变。

原通用大纲采用八章、可替换案例的组织方式。本课程把贯穿案例具体化为智慧校园，并将构造阶段按可交付业务拆成多个实践章节，形成 12 章、48 学时。项目计划在早期开展，配置、风险、评审和复盘贯穿后续实践。

## 八章知识与十二章实践的关系

| 原通用版主题 | 本课程落点 | 取舍 |
| --- | --- | --- |
| 软件工程基础与智能化开发范式 | 01、02 | 保留生命周期、人机责任和可行性，减少理论罗列 |
| 需求工程与 AI 辅助分析 | 02、03 | 用真实角色、事件规则和验收追踪落地 |
| 软件设计与 AI 辅助设计 | 03、05、09 | 用分层、数据端口、ER 图及状态机承载 |
| 软件构造与 AI 协同编程 | 04—10 | 分成连续业务增量，逐次运行和提交 |
| 软件测试与质量保障 | 每章核验、11 | 保留独立预期、拒绝、并发和回滚 |
| 项目管理与人机协同 | 02及全程接力 | 任务分解、版本、变更、风险和个人责任 |
| 软件交付运维与诊断 | 11、12 | 以本地/隔离交付和故障定位为必修 |
| 软件维护演化与工程决策 | 12及 AIRIOT 选做 | 小变更、适配替换、回归及决策记录 |

## 参考时应注意的版本差异

现有部分早期产品说明仍描述模拟控制；学校展示版本已关闭控制。课程以当前接口合同和本课程明确边界为准，基础版始终禁用远端控制。课程审计主要是事件及责任时间线，不把原模拟开关审计接口当作全部业务日志。

现有工程中 AIRIOT 来源类型和直接依赖关系需要在教学工程重新抽象。历史测试夹具及验收 JSON 可辅助教师理解，不当作学生运行结果，也不改写成新的通过报告。
