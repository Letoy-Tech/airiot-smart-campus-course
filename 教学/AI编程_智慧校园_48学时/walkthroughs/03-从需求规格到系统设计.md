# 03 从需求规格到系统设计

这一段结束时，你会有四份文件，能告诉下一位开发者：页面长什么样、记录哪些数据、页面怎样索取或提交数据、先做哪项任务。**这一段只做设计，不安装数据库，不启动服务，也不让 AI 一次生成整个平台。**

下面的 AI 回答均为编者编写的教学示例，不是通义的实际运行记录，也不是已经开发成功的页面。你的网页回答可以措辞不同，但业务规则必须与上一阶段一致。

本篇说“07、08、09、10”时，指桌面 `docs` 里文件名开头的编号，**不是左侧同编号的课程篇章**。例如“08的七步”指 `08-页面与流程.md` 中的演练流程，不是第08篇登录权限。下面先做四份文字设计，不把申请单或样例代码贴进浏览器地址栏、控制台或终端执行。

1. 打开桌面的 `campus-ai-lab` 文件夹，再打开 `docs`。确认有 `03-项目任务书.md` 和 `07-需求规格.md`。没有文件时，先回上一段完成；不要让 AI 猜测缺失需求。

```text
下面会分两条消息给你03-项目任务书.md和07-需求规格.md全文。
请先只确认收到，不改需求、不生成代码。等我说“开始页面设计”再工作。
```

3. 回本教程点“保存AI回答”→“打开已有 .md 文件”，选03任务书，点“复制当前全文”；马上切到AI，在正文前写完整文件名并粘贴发送。发出后才回工具打开07需求规格，复制并作为下一条发送。不要先复制完两份再粘贴，那样剪贴板里只剩07。
4. 第二份发送后，在聊天中确认两条正文都在，再核对：最小可用版本（MVP）是设备目录、模拟点值、本地演练处置；AIRIOT只读接入选做。教师提供数据库与认证基础，页面外观（UI）可以自己设计。AI提前写设计时，先发“材料还未发完，请停止设计，只确认收到”，补齐材料后再发第一步任务。
5. 每一步核对后，复制最终完整正文，点保存工具文字框后先全选再粘贴，选择该步固定文件名，核对标题，下载并移到 `桌面/campus-ai-lab/docs/`；用工具重新打开验证。纠偏后让AI输出完整合并版，不自己拼接片段。已有同名文件时按00保留旧稿，不让新稿留在下载目录而继续读取旧稿。

### 2. 对照并保存一份完整样例

````markdown

所有页面显示当前登录人和角色，提供退出。查看者没有写操作入口；
隐藏按钮只改善体验，服务器仍须检查权限。

## 设备目录文字草图

| teaching_env_01    | 在线 | 查看点值 |
| teaching_energy_01 | 未知 | 查看点值 |

## 读取反馈
| 情形 | 页面反馈 |
| --- | --- |
| 首次请求未结束 | 正在读取，不先显示“0台设备” |
| 成功返回空目录 | 目录暂无设备 |
| 有设备但筛选无匹配 | 暂无匹配设备，可以清除筛选 |
| 首次读取失败 | 读取失败及重试入口，不伪装空目录 |
| 已有结果，再次读取失败 | 保留旧结果，明确“刷新失败，显示上次结果” |

online=true显示在线；false显示离线；null显示未知。
value=0显示0及单位；value=null显示“暂无数据”，不填0。
质量与采样时刻另列，不用通信在线推断读数新鲜。

选择空间、从本地清单选择该楼栋→填楼层“2层”→保存→重新读取
locations与spaces核对关系。重启并重新登录后仍应存在。
查看者不能保存；不存在的空间/楼栋被拒绝，拒绝后原关系不变。
这些名字是课堂例子，不能当作学校真实地点。

## 一次演练如何完成
以下是待验证流程，E1是说明用名字，真实ID由服务器生成。
| 步骤 | 谁来做、点什么 | 应看到什么 |
| --- | --- | --- |
| 1 | 管理员触发“温度巡查” | 本地演练E1；来源ACTIVE；无负责人时处置NEW |
| 2 | 管理员选择管理人员A，写分派说明 | ASSIGNED，负责人A，新增分派时间线 |
| 3 | A打开本人事件，写说明后开始 | IN_PROGRESS，新增开始时间线 |
| 4 | A追加“已完成本地演练检查”的处理记录 | 状态不变，新增NOTE |

sourceRawStatus=DEMO_RECOVERED、恢复时刻不早于发生时刻、服务端

让人重新判断；不自动再次提交。409是冲突回信编号，第三步再解释。
已关闭事件不能继续修改。
管理人员B不能处理分派给A的事件；查看者只能阅读。
````

### 2. 保存 `09-数据字典.md`

````markdown
# 数据字典

本文件解释MVP用到的信息，不是建表脚本；字段须与教师完整接口一致。
以下值是设计样例，不能当作实际请求结果或真实硬件读数。
string是文字，number是数字，boolean是true或false，null是未知或缺失。

## 设备R01：页面上“是哪一台”
| 字段 | 含义与类型 | 空值/样例 | 提供者 |
| --- | --- | --- | --- |
| id | 稳定编号，string | 非空；teaching_env_01 | 教学数据源 |
| name | 显示名称，string | 非空；采用源数据名称，不拿名称当编号 | 教学数据源 |
| category | 分类，string | environment/energy/facility/lighting | 教学数据源 |
| spaceId、spaceName | 空间编号、名称，string或null | null显示未提供，不编造楼层 | 教学数据源 |
| online | 通信状态，boolean或null | true在线；false离线；null未知 | 教学数据源 |
| simulated | 是否模拟，boolean | 本教学集为true | 教学数据源 |
| tags | 本设备采集点清单，数组 | 每项含id/name/unit | 教学数据源 |

两台设备的通信样例：teaching_env_01为true；teaching_energy_01为null。

## 位置R02：把来源空间登记到本地楼栋
| 对象 | 字段与类型 | 关系及提供者 |
| --- | --- | --- |
| 校园 | id、name为string | 管理员填name，后端生成id |
| 楼栋 | id、campusId、name为string | campusId必须指向已存在校园 |
| 绑定 | spaceId、buildingId为string；floor为string或null | 两侧编号必须存在；管理员填写，后端校验和保存 |

一个校园有多栋楼，一栋楼可绑定多个来源空间；按spaceId保存当前绑定。
来源空间不是本地新建的硬件对象，绑定不能修改它的原始目录。

## 采集点R04：同一台设备的一项读数
| 字段 | 含义与类型 | 空值/样例 | 提供者 |
| --- | --- | --- | --- |
| deviceId | 所属设备编号，string | teaching_energy_01 | 教学数据源 |
| tagId | 采集点编号，string | power；须在该设备tags中存在 | 教学数据源 |
| value | 读数，number或null | 0是有效零；null是没有读数 | 教学数据源 |
| unit | 单位，string | power使用kW；不写成kWh | 教学数据源 |
| time | 采样时刻，number或null | 毫秒；缺失不伪造 | 教学数据源 |
| quality | 质量，string | fresh/stale/missing/invalid | 后端按合同计算 |

两种独立设计输入：power=0时显示“0 kW”；power=null时显示“暂无数据”。
它们不是同一时刻真的返回了两个值。质量按顺序判断：非空非法类型/时间→invalid；缺失→missing；未来
超过5000毫秒→invalid；过去超过60000毫秒→stale；其余fresh。
恰好5000或60000仍在边界内；前端显示后端质量，不自行重算。
读取响应的observedAt是观察时刻。本课程监测用固定教学时钟，
业务动作时间由服务器生成，两者不混为电脑当前时间。
overview的source=TEACHING_MOCK表示数据来源；simulated=true表示模拟属性。

## 演练事件R03：一次本地处置
| 字段 | 含义与类型 | 空值/样例 | 提供者 |
| --- | --- | --- | --- |
| id、deviceId | 事件编号、关联设备编号，string | 事件ID由服务端产生 | 后端 |
| message | 演练说明，string | 明写“本地演练，非实际设备异常” | 后端场景 |
| sourceType、sourceScope | 来源类型/范围，string | DEMO / LOCAL_DEMO | 后端 |
| simulated | 模拟属性，boolean | true | 后端 |
| assigneeUid | 事件负责人编号，string或null | manager-a；null为未分派 | 管理员分派，后端校验 |
| state | 处置状态，string | NEW/ASSIGNED/IN_PROGRESS/CLOSED | 后端按动作改变 |
| sourceState | 来源状态，string | ACTIVE/RECOVERED/UNKNOWN | 后端 |
| sourceRawStatus | 来源原始状态，string | 有效演练恢复要求DEMO_RECOVERED | 后端 |
| occurredAt | 发生时刻，number | 毫秒，非空 | 后端 |
| sourceRecoveredAt | 恢复时刻，number或null | 未恢复为null | 后端 |
| sourceVerifiedAt | 核实时刻，number或null | 尚未有效核实可为空 | 后端 |
| sourceCheckOutcome | 核实结果，string | PENDING/PASS/UNKNOWN | 后端 |
| disposition | 关闭结论，string或null | 未关闭可空；提交关闭须非空 | 处理者填写，后端校验 |
| version | 记录版本，整数 | 创建为1；有效修改后递增 | 后端 |

设计样例E1：设备teaching_env_01，负责人manager-a，state=IN_PROGRESS，
sourceState=ACTIVE，version=3，disposition=null；因此现在不能关闭。
E1只是讲解名字，程序不得把它当作真实返回ID。
关闭时还须已有NOTE、恢复时刻不早于发生时刻、核实为PASS且核实时刻
不早于恢复时刻。不能只检查“恢复了”。

## 时间线：谁在什么时候做了什么
| 字段 | 含义与类型 | 约定 |
| --- | --- | --- |
| caseId | 所属事件，string | 指向同一事件id |
````
