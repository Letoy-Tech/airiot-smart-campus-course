# 智慧校园学校展示说明

版本：`REL_20261005-0151-SCHOOL-DEMO`，2026-10-05已部署到现有城大服务器。入口：[校园展示 Demo](https://demo.example.invalid/campus-demo/)。远端 API、正常 HTTPS、管理员实际桌面与390px视口、备份隔离恢复已完成验证。

本展示用于说明校园设备监测、责任分工和事件处置流程。MG → BE → AIRIOT 读取当前 4 个模拟空间、16 台模拟设备和 28 个采集点；图表展示实际接口返回的模拟对象读数与原始历史。本地 DEMO 事件独立生成，不是设备实时触发的报警。

## 账号与讲解顺序

学校查看使用 `DEMO_campus_viewer`。维护人员讲解操作使用管理员账号；账号名称及用途如下，密码不写入本文。

| 账号 | 用途 |
| --- | --- |
| `DEMO_campus_admin` | 设备责任人配置、事件指派及完整演示流程 |
| `DEMO_campus_manager` | 处理分配给自己的事件 |
| `DEMO_campus_manager_other` | 展示另一管理人员的权限边界 |
| `DEMO_campus_viewer` | 学校只读查看监控、责任人及事件时间线 |

学校只读账户已单独保存在 [受限查看者文件](../.private/campus-demo-school-viewer.json)，其中包含网址和登录信息，文件权限 `0600`。维护人员的四个专用 DEMO 账号保存在 `system/.private/campus-demo-accounts.json`（0600）；给学校只分享查看者账户，不把管理账户、token 或机器凭据粘贴进讲解资料。

建议先用只读账号，按以下顺序讲解：

1. **运行概览**：查看温湿度趋势、采集质量、同单位空间对比，再从空间与设备矩阵进入设备列表。解释读数来源、采样时间及缺失/过期提示。
2. **设备责任人**：说明每台设备可以明确到负责人，责任变更保留记录；只读账号可查看，管理员才能配置。
3. **已关闭 DEMO 事件**：打开详情，按时间线说明指派、开始处理、处置记录、演示来源恢复、独立核实和关闭结论。分别查看“来源状态”和“处置状态”，两者各自独立。

## 管理员现场演示

切换到管理员账号，在运营事件页面选择温度巡查、设备通信巡查或照明巡查场景。可以先完整演示一种，其余场景按学校关注点补充。

1. **触发 DEMO 场景**。每次触发创建新事件和新 ID，保留以前的事件及审计，不覆盖历史。页面明确标识本地演示，关联设备不因此产生实际异常。
2. **确认负责人**。已配置有效设备责任人时自动分派；未自动分派时，先选择可处理人员并填写指派说明。
3. **开始处理**，填写开始巡查的说明。
4. **保存处置记录（NOTE）**，例如“已完成本次演示巡查，等待演示来源恢复核实”。
5. **模拟来源恢复**。此按钮只改变本地 DEMO 来源，不操作上游报警、采集数据或设备开关。来源恢复后，处置仍保持处理中。
6. **独立核实恢复**。只有核实本地 DEMO 来源恢复成功，才满足关闭的来源门槛；这一步不是物理设备恢复证明。
7. **填写关闭结论并关闭**，回读详情及完整时间线。系统要求已有处置记录和恢复核实，已关闭历史不能再修改。

校园管理人员只能处理分配给自己的事件；不能重新指派负责人、触发场景或模拟来源恢复。另一个管理人员和只读账号不能代替本人处理。操作遇到版本冲突时，刷新核对最新状态后重试，系统不会覆盖他人刚保存的记录。

本地 DEMO 案例不修改 AIRIOT 报警或遥测，不启用设备控制，不发送外部通知。原始 AIRIOT 报警列表与本地 DEMO 事件分别展示；空报警列表不能证明真实报警机制通过验收。当前能源为 V/kW，不展示未经接入的 kWh、费用或节能率。

本展示不代表真实校园已完成设备接入、物理控制、报警发生/恢复、实体手机使用或运营试点验收。学校可用它讨论真实空间、设备清单、值班责任及下一阶段试点范围。

部署隔离、版本发布、备份、恢复验证及回退操作见[学校展示 Demo 部署与恢复](campus-demo-deployment.md)。单实例后端更新时有过短暂502，界面保留旧数据并提示错误，最终刷新与后续流程正常；发布校验回退及复核记录保留。浏览器仅实际登录管理员，查看者界面另在本地验证、所有账户在公网API验证；390px为Chrome视口仿真，学校外网及实体手机尚未实测。
