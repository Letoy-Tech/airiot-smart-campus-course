# 智慧校园 MG

Vue 3 + TypeScript + Pinia + Vite 管理前端。采集业务通过 BE 访问独立 AIRIOT 模拟项目，演练事件与设备责任记录由 BE 独立持久化，运行界面不含业务 mock 或远端应用秘密。

2026-10-05 学校展示 DEMO 已上线，版本 `REL_20261005-0151-SCHOOL-DEMO`，入口：[学校展示 DEMO](https://demo.example.invalid/campus-demo/)。远端API、管理员实际桌面及390px仿真、原始趋势/空间钻取与事件闭环已验证。全部设备仍为模拟设备，本轮不代表真实校园运营或硬件验收；2026-10-04 为此前本地可视化交付。

## 本地运行

要求 Node `^20.19.0 || >=22.12.0`。本目录已有锁文件；首次安装使用 `npm ci`。

```sh
npm run dev -- --host 127.0.0.1 --port 5173
```

默认 `/api` 代理到 `http://localhost:8001`，并去除 `/api` 前缀。先按 system 后端运行说明启动 BE。浏览器打开 `http://127.0.0.1:5173`，使用 BE 分配的管理账户登录。不要把 AIRIOT AppKey、AppSecret 或 token 设置为 `VITE_*`，这些变量会进入前端产物。

需要改变浏览器请求地址时可配置 `VITE_API_BASE_URL`，它仅是 BE 地址。本地开发继续使用上述根路径与 `/api` 代理；学校 DEMO 使用以下独立子路径构建配置。

## 学校 DEMO 子路径构建

在本目录执行：

```sh
npm run type-check
VITE_API_BASE_URL=/campus-demo/api npm run build-only -- --base=/campus-demo/
```

先完成类型检查，再直接调用 Vite 的 `build-only`。不要使用 `npm run build -- --base=/campus-demo/`，该脚本经过 `run-p`，不能可靠将参数传给 Vite。`dist/` 是当前配置生成的前端产物；生成产物不等于远端发布成功。

远端通过 `/campus-demo/` 提供静态文件，`/campus-demo/api` 反向代理至专属 BE；Vue Router history 的 base 与 fallback 必须使用同一前缀。例如运营深链接为 `/campus-demo/campus/operations`，事件详情为 `/campus-demo/campus/alarm-cases/:id`。部署、独立 MySQL/Redis、备份及回退见 [部署与恢复说明](../docs/campus-demo-deployment.md)。

远端学校 DEMO 全面关闭实体及远端模拟开关控制，关闭外部通知；演练恢复仅修改本地 DEMO 来源。展示账户在远端初始化时独立生成，仅保存于 [受限账户文件](../.private/campus-demo-accounts.json)，不在 README 或前端产物中复制秘密。

## 业务入口

- 界面：浅色 / 深色主题（顶栏切换，圆形揭幕过渡）、⌘K / Ctrl+K 快速跳转页面与设备、全屏展示、可折叠侧栏。KPI 环形卡片、设备拓扑图、空间热力、表盘与迷你趋势均只绘制真实读数，轮询指示器显示距下次读取的倒计时。
- 演示运营：学校三步讲解路径、三个本地演练场景、事件队列及本页处置状态分布。事件明确标注 DEMO 来源，与 AIRIOT 原始报警分开。
- 事件详情：责任分派、开始处理、处置记录、模拟来源恢复、独立恢复核实和关闭结论，展示实际持久化时间线及版本。
- 设备责任人：按设备、空间或责任人查询台账；管理员登记责任人并保留变更记录，事件创建可按有效设备责任人自动分派。
- 校园概览：真实环境趋势、采集质量分布、六种同单位空间指标比较、设备类型分布与可钻取空间矩阵，保留实际数/预期数和来源时间。
- 空间与楼栋：远端空间和 BE 本地校园、楼栋、楼层映射，管理员可保存映射。
- 设备台账与详情：卡片巡查/表格切换，搜索与类型、空间、通信三态筛选；点值可直接切换原始历史，支持显示/隐藏设备曲线和展开样本表。窄屏默认收起设备分布图，展开后仍可查看。模拟状态操作入口取决于 BE 控制能力，学校 DEMO 全面关闭。
- 能源点位：四设备功率/电压比较与多序列原始历史；不生成 kWh、费用或节能率。
- 报警记录：保留上游原始枚举，只读查询。
- 管理员：机器接入能力、模拟命令审计，沿用用户、角色、组织及访问规则管理。

MG 在进入业务页前严格读取 BE capabilities，只有 Boolean `true` 才授予能力；缺失、字符串或数字标志不授权。最终权限由 BE 强制执行。学校 DEMO 的角色范围：

| 角色 | 读取业务 | 处置事件 | 分派、触发/恢复演练 | 登记设备责任人 |
| --- | --- | --- | --- | --- |
| 管理员 | 可以 | 全部事件 | 可以 | 可以 |
| 校园管理人员 | 可以 | 仅本人已分派事件 | 不可以 | 不可以 |
| 只读查看者 | 可以 | 不可以 | 不可以 | 不可以 |

事件流程为待分派 → 待处理 → 处理中 → 已关闭。关闭前必须已有处置记录、模拟来源恢复、独立恢复核实通过，并填写关闭结论；已关闭事件不可修改。所有演练和责任写入携带 `expectedVersion`，409 后回读新版本并保留输入，失败不清空表单；只有版本和目标状态回读确认才显示成功。

2026-10-04 旧本地验收曾对8个既有设施/照明对象进行模拟字段操作，提交严格 Boolean、理由与 expectedState，并要求 BE 写后回读一致。该历史验证与授权不代表远端学校 DEMO 开放设备控制。

## 数据状态

概览、设备、能源每15秒静默刷新，原始报警与演练队列每30秒刷新；请求不重叠，离开页面停止轮询。演练筛选切换使用已提交范围，事件详情不轮询重置表单。加载、缺失、无效、过期、部分问题与上游失败均显式呈现。刷新失败保留同范围的上次成功数据及其时间，未取得值不显示为零或关闭。历史不补零、不插值，不把空报警当机制验收成功。

历史默认15分钟，可切换1小时或6小时；最多4台并发，独立于最新值轮询，手动刷新更新查询快照。取消离页或旧筛选查询；部分刷新失败逐设备保留旧历史，以虚线和原查询时间标明。接口截断明确提示，末条样本显示实际时间，不代表当前值；原始样本表展开时才渲染。
