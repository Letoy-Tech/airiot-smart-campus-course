# 48 学时实施分工

本表把图文正文收敛为课堂可执行的任务顺序。每章仍是 1 学时理解与示范、2 学时局部实践、1 学时核验与接力。实际分钟数待学校课时制度确定；当前尚未经过课堂计时验证。教师资源列表示必须事先制作并验证的材料，不表示这些材料已经交付。

## 让学生做业务判断，让重复配置有统一起点

学生学过的语言可能不是 Java 或 JavaScript。课前用变量、条件、函数、数组四个小题了解基础；进入相关章节时再用正文短例解释 JSON、类型、组件和请求。不能把“学过一门语言”理解为已经掌握整个前后端框架，也不另加一门隐形的课后必修课。

开课准备阶段完成工具和资源预检。第 04 章处理已核对环境中的局部排障，不承接全班从零安装所有依赖的工作。若预检未完成，教师先处理资源条件，不能以缺少未提供资源扣学生工程实现分。

| 章 | 教师预制或承接材料 | 学生课内主要修改 | 本章结束时的最小证据 |
| --- | --- | --- | --- |
| 01 | 本章短例、离线缺陷回答 | 修订一份台账需求和一次 AI 反馈 | 三态判断、采纳/拒绝理由、接力记录 |
| 02 | 范围、角色及任务卡样例 | 写一个完整故事、反例与相邻小任务 | 需求—验收—任务对应；其余故事用模板评审 |
| 03 | 全局架构/ER/状态图和读取 JSON | 标注一空间两设备响应，说明读取链路与字段 | 一份读合同；能逐层找到设备名和 null |
| 04 | 已验证环境、认证、最小读取桩与页面 TODO | 接入一次设备读取及显示，观察一次失败并恢复 | true/null 设备链路、Network 和局部差异 |
| 05 | 控制器/服务/Mapper 空模板、迁移与测试入口 | 读取查询、创建校验、本地空间关系校验 | 正常写入后回读；非法关联和只读身份被拒绝 |
| 06 | Vue 页面/路由/请求与类型基础 | 筛选、三态显示、空/失败分支和详情定位 | UI 自主设计；结果 ID、三态与清除操作正确 |
| 07 | 可控时钟、单点样本、图表与请求生命周期骨架 | 质量解释、原始数据映射、断点和结果接收判断 | 一类曲线对应原始表；零/空、失败和离页可区分 |
| 08 | 认证、四身份、角色恢复工具、可控响应延迟 | 能力严格布尔、后端授权、旧响应拒收规则 | 直接越权请求拒绝；跨身份和同身份竞态记录 |
| 09 | 七类动作路由/DTO/事务模板、独立规则夹具 | 状态、本人范围、关闭条件、版本冲突分支 | 正常闭环账本；可达反例和规则夹具分开记录 |
| 10 | 责任表初始行、持久化与时间线模板 | 责任人资格、版本检查、未来自动分派判断 | E1 不暗改派、E2 按新负责人分派及历史 |
| 11 | 真 MySQL、双请求屏障、指定故障注入模板 | 填测试前提/断言，定位并修复一个缺陷 | 两类并发、事务回滚因果记录及回归结果 |
| 12 | 既有构建入口、交付清单和筛选变更需求 | 整理交付、完成有限变更、交叉复现及解释 | 同伴复现、变更回归和个人答辩记录 |

第 03 章的 ER、事件状态、版本与事务用于认识后续对象，不要求此时实现或重画全部设计。第 09、11 章再完成对应实现与证据。第 04 章的独立函数三态练习与页面 true/null 观察分开，完整页面三态在第 06 章验证。这样安排降低首次学习负担，不减少最终业务标准。

## 一章只追踪一个任务单

使用[课堂任务单](../templates/课堂任务单.md)保存本章目标、文件变化、输入、预期与实际。截图、日志和测试输出只引用已有证据路径。每个主要任务遵循“先预测一个输入 → 修改一个局部 → 看实际结果 → 修正或交接”。先走最小成功路径，再验证一个明确的拒绝或异常；后面的用例逐步复用同一基线。

教师展示骨架时应打开学生要修改的真实文件，指出已有部分、TODO、调用入口和检查入口。拟定文件名必须在资源包发布时映射到真实路径。若找不到入口，应停止让 AI 猜路径，由教师修正资源映射表。

两人一组时，在模块二轮换实现与审查，模块三各自解释一个判断和一条证据。共享日志不等于共享理解；个人评分仍按自己的判断、修改和答辩。独立完成者采用同一任务和验收标准。

## 超时先处理什么

| 现象 | 本章处理 | 保留的关键要求 |
| --- | --- | --- |
| 环境或依赖未就绪 | 登记资源阻塞，使用纸面/独立短例练习；教师修复资源 | 不把纸面推演记成实验通过 |
| 重复配置占去实践时间 | 提供经过验证的请求、路由、表单或测试骨架，标明来源 | 业务规则、学生 TODO 和人工解释仍由学生完成 |
| UI 美化耗时 | 先使用普通表格与文字状态，再做视觉调整 | 来源、空值、失败、权限与核心交互 |
| 复杂内容同时出现 | 先完成本章任务卡，再读预告和扩展 | 后续章节仍按 AC 完成状态、并发和回滚 |
| 临近结束还没通过 | 保存当前差异和失败证据，明确下一检查；使用救援检查点时注明 | 不拿完整答案覆盖后声称独立完成 |

课后以整理和自查为主；正文的练习与扩展不全部转成新增必交作业。如果试讲发现必修仍需大量课外编码，应减少重复实现、改进教师模板并重新计时。不能仅修改文档为“4 学时”就宣布负担已验证。

## 转正式实验前要补齐的四项记录

1. **入口映射：**每个学生 TODO 对应真实文件、起始检查点、目标检查点和运行入口。
2. **输入与答案：**固定数据、故障前提、预测结果与教师实测结果分栏；正文示例不直接填入实际结果。
3. **耗时记录：**每个模块实际用时、卡点和教师介入次数；新手复现与作者自测分开。
4. **资源恢复：**每组数据和账号怎样恢复到本章起点，恢复只作用于该组；证据保留后再恢复。

这些记录完成前，当前版本仍是经第二轮审校的教材稿。配套代码、实验验证和教案转换分别推进，不能互相替代。
