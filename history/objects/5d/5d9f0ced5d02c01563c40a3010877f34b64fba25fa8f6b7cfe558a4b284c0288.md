# 考核与验收

## 评价什么

评价学生能否把问题变成可验证的软件，以及是否理解并检查 AI 参与的改动。作品可采用不同 UI；大模型品牌、账号付费档位和是否完成 AIRIOT 接入不影响基础评分的公平性。

## 评分建议

| 维度 | 分值 | 主要评价内容 |
| --- | ---: | --- |
| 需求与设计 | 20 | 范围和角色清楚；规则可验证；接口、数据和状态一致；决策有依据 |
| 核心功能 | 25 | 设备、监测、权限、事件、责任和时间线形成可演示业务闭环 |
| 测试与交付 | 20 | 边界和拒绝场景、真实数据库证据、缺陷回归、他人复现 |
| 个人 AI 协作 | 15 | 上下文准确；小任务分解；识别错误；核验及接力记录真实 |
| 个人理解与答辩 | 20 | 能解释代码、预测行为、定位故障并完成小变更 |
| 合计 | 100 | 前三项可用小组成果，后两项按个人评价 |

进阶作品在所属维度内体现深度，不另设只有付费或接入真实平台才能获得的分数。做完基础任务并有充分证据，可获得该维度满分。具体分数由任课教师按学校要求确定。

## 必修验收基线

以下是学生未来必须执行的检查清单，当前文档包没有产生这些运行结果。

| 编号 | 验收场景 | 通过条件 | 建议证据 |
| --- | --- | --- | --- |
| AC01 | 教学数据读取 | 数量来自实际结果；显示模拟来源；不依赖 AIRIOT 账号 | API 返回与页面 |
| AC02 | 空间映射保存 | 合法关联持久化，刷新保留；非法关联被拒绝 | 请求、回读和失败记录 |
| AC03 | 最新值与质量 | 有效零、缺失、过期、无效可区分；未知通信状态不当作离线 | 固定夹具与页面 |
| AC04 | 历史曲线 | 时间范围合法；同单位；不补零插值；空、失败、截断有说明 | 样本表与曲线对照 |
| AC05 | 角色授权 | 三角色符合矩阵；隐藏按钮后直接写请求仍被后端拒绝 | API 拒绝测试 |
| AC06 | 本人范围 | 管理人员不能操作他人事件；失效身份不能继续修改 | 身份与对象交叉用例 |
| AC07 | 事件闭环 | 分派、开始、记录、恢复、核实、关闭均满足规则 | 刷新后的持久化时间线 |
| AC08 | 版本冲突 | 两请求携带读取时相同的当前版本 n 并发提交，恰有一个成功，另一个 409；无重复时间线 | 真实 MySQL 并发记录 |
| AC09 | 事务回滚 | 时间线插入失败时主记录也不变 | 真实 MySQL 前后查询 |
| AC10 | 责任变更 | 负责人有效；新事件按新责任人分派；旧事件不被偷偷改派 | 两次责任与事件对照 |
| AC11 | 前端可靠性 | 请求失败保留输入；不假报成功；刷新停止及加载状态正确 | 浏览器操作与网络证据 |
| AC12 | 他人复现 | 同学按交付说明在独立环境完成启动与核心流程 | 复现者签记与问题单 |

若关键授权、状态规则或回滚失败，核心功能验收记为待修复，不能用 UI 美观或更多功能抵消。教师根据该项实际完成程度评分；不虚构学校统一的“一票否决”政策。

## 独立预期与避免同源错误

测试预期先来自需求规则和教师固定样例，再让 AI 协助生成测试代码。不能让 AI 根据有缺陷的实现推导同样错误的预期；也不能为了让测试全绿而删掉拒绝或冲突用例。

每组至少呈现一个 AI 建议被修正或被拒绝的实例，说明证据和影响。若确实没有发现错误，可以审查教师准备的缺陷样例，不要求学生伪造一次 AI 失误。

## 证据等级

文档设计、编译构建、单元测试、真实数据库集成、API 验证、浏览器流程、外部接入是不同层次。报告分别列出执行日期、环境、版本、命令、实际结果和缺口。通过构建不能代替浏览器验收；mock 测试不能代替数据库锁和事务验证；接入状态为 connected 不能代替全部 AIRIOT 业务验收。

证据只收集教学数据和脱敏日志。每位学生使用自己的教学账号，提交中不包含密码、会话 token、真实 API Key 或个人隐私数据。

## 答辩题示例

1. 页面把空值显示成 0，会对使用者造成什么误解？指出代码中的对应处理。
2. 如果只把“关闭事件”按钮隐藏，为什么不能证明查看者没有关闭权限？
3. 两个管理员同时修改责任人，后端怎样判断冲突？前端遇到 409 后应该怎么做？
4. 来源恢复和事件关闭为什么分开？指出缺少处置记录时的拒绝条件。
5. 展示一次 AI 的建议、你的判断和实际测试；若换一个模型，哪些证据仍然有效？
6. 现场增加一项小筛选条件，说明需要更新哪些合同、代码和测试。

## 最终交付清单

源代码与锁文件；无真实秘密的配置样例；运行和停止说明；教学数据版本；需求、架构、接口及决策记录；测试与缺陷报告；AI 代表性协作记录；当前交接和已知限制。压缩包和仓库都可作为交付形式，采用哪种形式不影响验收标准。
