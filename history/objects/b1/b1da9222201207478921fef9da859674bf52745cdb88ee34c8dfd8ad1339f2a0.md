首次准备只将本章尚未编辑的参考标记块置为 TODO，意思是“这一小块留给你做”；保留前章成果。已经准备过本章时，`.lesson-state.json` 会让工具保留现在的代码，不要删除它强行重做。若首次准备提示块已修改或无法匹配，停止准备，保留提示找教师确认，不能下载另一整包覆盖。

## 第2步：把两个准确的源文件交给 AI

Windows 按 Ctrl+P，macOS 按 Command+P，输入 `frontend/src/domain/course.ts`，回车。用 Ctrl+F／Command+F 搜索 `STUDENT_TODO_C08_BEGIN`，应看到 `strictCapability` 函数。准备后的块内通常是：

```ts
  void value
  return false
```

它暂时让所有能力都关闭，所以这时页面提示无读取权限并不证明账号坏了。不要修改数据库角色来“修好”这个 TODO。


回 VS Code，点进 `course.ts` 编辑区，Ctrl+A、Ctrl+C（macOS 用 Command），切回网页，先写文件路径再粘贴发送。接着 Ctrl+P 打开 `frontend/src/api/auth.ts`，同样全选复制，作为第二条消息发送。本步只复制，不改 `auth.ts`。

预期 AI 能指出 `getCapabilities` 把 `canRead`、`canAdmin` 等值分别传给该函数。所谓“严格”就是值和类型都要相符；文字“true”不是布尔值 true。把自己的七项预测表写到 `ch08.md`。若 AI 建议 `Boolean(value)`，追问：

## 第3步：只替换一小块，先看测试再看页面

在 `course.ts` 中保留 BEGIN、END 注释及函数括号，只选中它们之间的 `void value` 和 `return false`，替换为：

```ts
  return value === true
```

保存后，这个函数应完整呈现为：

```ts
export function strictCapability(value: unknown): boolean {
  // STUDENT_TODO_C08_BEGIN：只有 JSON Boolean true 可以开启能力。
  return value === true
  // STUDENT_TODO_C08_END
}
```

不要把整个 `course.ts` 换成这个函数，否则会丢掉前面的筛选代码。按 Ctrl+S／Command+S。前端终端仍在 `app`，依次执行：


Windows 的 PowerShell 若阻止 `npm.ps1`，把前两条开头的 `npm` 换成 `npm.cmd`，其他不变。第一条应通过名称含 `C08 仅 Boolean true 授权` 的测试；其他被筛选跳过的用例不算失败。第二条应正常结束且无类型错误。第三条保持运行，等待出现 `127.0.0.1:5178`。

本段没改 Java，已有 `backend-db` 后端可以继续运行；若之前已停止，另一个 `app` 终端执行 `node tools/course.mjs backend-db`。不要运行第04段的 `backend`，也不要另开第二个5178服务。

## 第4步：实际登录两个身份，比较同一页面

打开 `http://127.0.0.1:5178/#locations`。教师提供的本机账号密码只在本机查看和输入；如第04段已教过，可在 VS Code 本地打开 `.private/accounts.json` 找对应密码，随后关闭该文件。**不全选复制给 AI，不把密码框拍进截图。**

1. 若当前已登录，点右上角 **“退出 / 切换身份”**。等看到 **“教学账号登录”**；若显示“重新确认退出”，先完成退出，不能假定身份已切换。
2. 在“教学账号”填 `viewer`，在“密码”填本组对应密码，点 **“登录并查看设备”**。
3. 点顶部 **“设备台账”**，确认有实际设备；再点 **“空间归属”**。应能读取已有映射，下方出现 **“当前身份只读。校区、楼栋和空间映射由管理员维护。”**，没有“保存校区”表单。
4. 点“退出 / 切换身份”，用 `admin` 登录，再点“空间归属”。应看到 **“1. 新建校区”**、**“校区名称”**及 **“保存校区”**。先不保存，下一步做同条件对照。

本步无代码修改，记录两个身份看到的入口；不要只凭按钮有无就写“授权已验证”。给 AI 的核对任务是：

```text
我已按顺序退出、登录viewer、看设备台账和空间归属，再退出、登录admin。
请用两列列出各身份预期可见内容，并说明这只是页面入口证据，下一步还要
用查看者自己的合法会话直接提交请求。不要建议修改浏览器存储伪造角色。
```

若账号登录失败，记录页面文字及登录请求的状态码；不要发送登录请求体。可问：“相同账号在本机返回401，我只提供状态和脱敏错误，请先区分密码错误与身份失效，不要求密码或Cookie。”

## 第5步：按钮被隐藏后，服务器是否真的拒绝

这一步只写本组教学库，不能在学校真实平台执行。先退出admin，重新登录viewer，留在 `#locations`。

1. 保留教程标签，切到地址以 `http://127.0.0.1:5178/` 开头的**课程应用标签**。在应用空白处右键 **“检查”**，选择 **“Console／控制台”**；看不到时点开发者工具上方 `»`。点击控制台底部 `>` 后的空白输入行，不是顶部“Filter／筛选”框，也不是网页AI输入框。
2. 回[第05段第5步](05-后端空间与设备接口.md)，复制从 `async function courseWrite` 到最后 `}` 的整段定义，**不复制三个反引号**。切回应用控制台，Windows用Ctrl+V、macOS用Command+V粘贴，按一次Enter。若浏览器禁止粘贴，保留防护提示，请教师带着手工输入，不关闭防护。出现 `undefined` 只是函数定义完成，尚未执行本步写请求。
3. 在新的 `>` 输入行输入 `typeof courseWrite`，按Enter；应得到 `"function"`。若是 `"undefined"`，检查标签地址、是否刷新或换过标签，再重新定义。切换身份后也重新做这项检查；函数沿用**当前**登录身份，不记住上次的viewer或admin。它只向本机教学接口发请求，内部携带防伪标记，不打印秘密。
4. 确认右上显示查看者后，整段复制下面代码到同一控制台的新输入行，按一次Enter。它先读取原有校区，提交一次合法格式的创建请求，再读取结果；不会输出Cookie或密码。

```js
var checkName08 = '第08课权限对照-' + Date.now();
var before08 = await fetch('/api/campus/locations', {credentials:'same-origin'}).then(r=>r.json());
var denied08 = await courseWrite('/api/campus/locations/campuses', 'POST', {name:checkName08});
var after08 = await fetch('/api/campus/locations', {credentials:'same-origin'}).then(r=>r.json());
console.log({name:checkName08, status:denied08.status, message:denied08.message,
  bothReadsSucceeded:before08.code===0 && after08.code===0,
  unchanged:JSON.stringify(before08.data)===JSON.stringify(after08.data)});
```

应看到读取成功、写入 `403 / ACCESS_DENIED`、`unchanged:true`。若是401、CSRF相关错误或网络失败，先排查会话，不能当角色拒绝通过。若本组其他人同时写库，前后不同也要先核对是哪次操作，不能强行填写true。

结果是可展开对象时，点左边小三角，读 `name/status/message/bothReadsSucceeded/unchanged`；只复制这些业务字段到 `evidence/ch08.md`，按Ctrl+S／Command+S。`courseWrite is not defined` 表示函数没有定义，不算403。若没有明确结果，停止，不再运行整段；先由管理员只读“刷新映射 → 所属校区”下拉，核对刚才的名称是否已存在，不因没有输出而重复创建。

5. 将输出的 `name` 完整保存到账本，再退出并登录admin。从账本复制这个名称到“空间归属 → 校区名称”，点一次 **“保存校区”**。不要重新运行生成 `checkName08` 的代码，它会生成另一名称，失去同请求体对照。应显示“服务端已确认保存。”再点 **“刷新映射”**，打开 **“2. 新建楼栋 → 所属校区”** 下拉，应看到该名称。这里只确认重新读取的校区目录，不保存楼栋；未绑定空间的校区不会出现在上方映射表中，不因此重复创建。

本步无源代码改动。将查看者响应、前后不变、管理员回读三项记入 `ch08.md`。若失败，给 AI 发：

```text
我在127.0.0.1:5178、viewer自己的登录会话使用courseWrite创建校区，
预期403/ACCESS_DENIED且locations不变。下一条只给status/message与
前后业务数据，不给凭据。请区分角色拒绝、会话/CSRF问题、名称重复和网络失败；
先指出证据缺什么，不修改后端Access，不把任何403都算授权通过。
```

## 第6步：看懂“旧响应晚到”与保存交接

“旧响应”像前一个人的信迟到：即使收到，也不能放进现在登录者的页面。教师已经写好隔离逻辑，本步只阅读和测试，不让 AI 重写。

```text
只解释刚收到的两个文件，不改代码。把sessionEpoch说成“身份轮次”，
```
