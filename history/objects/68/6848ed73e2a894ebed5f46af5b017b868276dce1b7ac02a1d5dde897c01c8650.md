# 第04章 · 两处修改，验证一次完整读取

本单对应原正文的4学时（1+2+1），不自行换算分钟。教师先在参考工程完成安装和预检，再生成学生工作目录；学生课内修改两个任务块。安装依赖与账号初始化安排课前，不把所有环境下载算进模块二。

## 起点和停点

起点：`student-workspace/`已含前后端、登录基础、固定夹具与两处待填任务。第一条链路使用一空间、两设备，数据来自后端读文件，而非浏览器硬编码数组。学生电脑不连接数据库。

停点：登录成功；两设备显示“在线/未知”；屏蔽设备GET后显示失败并保留已有快照；取消屏蔽后重新读取；提交一份脱敏证据与局部Git提交。第06章才验收完整页面三态和自主筛选。

## 模块一：预测与基线（1学时）

1. 按启动说明检查工具、目录和两个端口，保存自己的版本输出。不要抄教师验证记录。
2. 阅读`fixtures/selectors.json`与`fixtures/catalog.json`，预测`teaching_env_01`和`teaching_energy_01`的online值及显示文字。
3. 在自己的学生目录按正文步骤初始化Git；先检查`.gitignore`，本地密码、target、dist、node_modules均不提交。记录当前两个TODO尚未完成。
4. 浏览器登录后应看到TODO-A待完成信息。此时认证与接口可能已正常，缺的是学生解包任务；先看Network，再判断错误层次。

## 模块二：完成两个任务（2学时）

| 文件与标记 | 教师已经提供 | 你要完成 | 验收反例 |
| --- | --- | --- | --- |
| `frontend/src/api/campus.ts` / STUDENT_TODO_A | HTTP、JSON对象与成功响应字段校验 | 业务code非零时报错；成功返回同一批items/observedAt | code非零不能返回正常空数组 |
| `frontend/src/views/FirstDeviceRead.vue` / STUDENT_TODO_B | 页面、会话、刷新、失败保留旧快照 | 严格区分true/false/null的onlineLabel | null不能显示离线；字符串不是合法输入 |

本轮把成功/失败/迟到响应处理收进教师框架，学生重点解释它为何保留旧快照，并验证行为；不要求在第04章从零实现竞态控制。教师参考页面附有筛选供后续演示，第04章不把筛选改写计入必交任务。

网页AI提示：

```text
我正在做第04章，前后端和登录框架已提供。你不能访问我的本机。
只改我粘贴的一个STUDENT_TODO块，不重写框架或安装新依赖。
请先说明输入、输出和一个失败反例，再给最小修改。
合同：online只能true/false/null；业务code必须为0才可读取data。
当前文件和类型：[粘贴相应函数与必要类型，不粘贴账号文件]
执行结果：[我实际运行的结果；尚未执行则明确说明]
```

一次只处理一个块。A填好后若标签仍显示“待完成TODO-B”，这是B尚未完成，不修改后端数据去掩盖。两块完成后从工程根目录运行：

```text
node tools/course.mjs check
node tools/course.mjs build
```

在已启动前后端的页面重新读取。Network应看到`/api/campus/devices`，响应包含`code:0`、`data.items`和`data.observedAt`。**本资源的Vite保留/api前缀，后端入口同样包含/api；不再移除前缀。** 不把教材早期示意的rewrite直接复制过来。

保持已成功读取的页面不刷新。在Chromium开发者工具中打开命令菜单（Windows Ctrl+Shift+P；macOS Command+Shift+P），搜索Show Network request blocking，打开请求屏蔽面板并启用；新增匹配`*127.0.0.1:5178/api/campus/devices*`的屏蔽规则。只屏蔽设备GET，不屏蔽登录/空间。点击页面“重新读取”，应出现网络失败并保留旧记录和最后成功时间。取消规则后再次点击，确认恢复。浏览器界面名称以教师预检为准；不要改源码、刷新页面或重启服务来替代这个同会话失败实验。

本包evidence仅说明作者的指定macOS工具链测试。Windows实机、学生独立操作、数据库实验与课堂时间没有自动被覆盖。未填任务时前端任务测试失败是预期；参考版本全通过也不代表学生版本已完成。
