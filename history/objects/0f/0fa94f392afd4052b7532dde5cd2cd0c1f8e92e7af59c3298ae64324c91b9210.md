# 约定卡：给 CodeBuddy 阅读的工程说明

每步提示词让 CodeBuddy 先读这张卡，用来保持前后章节的文件、数据和接口一致。学生不必先背这张卡。

## 主线

共 12 次课，每次 4 学时，每学时 45 分钟。
01 空白页到概览；02 设备台账与详情；03 空间与责任登记；04 读数与能源；
05 历史和只读报警；06 演练事件、角色演示、完整前端串联；
07 对着页面列数据并生成最小 Java 后端；08 MySQL 保存设备并接通设备页；
09 Redis 登录会话、三个角色并接回前端；10 接通空间、责任、读数、历史；
11 接通事件闭环、审计与失败处理；12 新目录启动与交付。

每小步：现在在哪 → 发一段提示词 → 等 AI 完成并保存 → 学生亲自运行/点击 → 可见结果 → 失败时单独发送修复提示 → 下一步。
AI 负责生成、修改文件，可以运行会退出的检查；不要替学生启动常驻服务。
“等 AI 回复完”与“终端里的服务继续运行”是两件事。只有写明重启时才在该服务终端按 Ctrl+C。

## 同一工程

项目根名 campus-lab，CodeBuddy 始终打开这一层。
前端：frontend/index.html（学生起点为空）、styles.css、app.js、data-service.js、mock-data.js。
materials/mock-campus.json 为公开练习数据；materials/约定卡.md 是给 AI 读的约定。
materials/maven-wrapper/ 只提供 Maven 启动工具，07 复制到 backend；无业务成品。
tools/serve.mjs：Node 22，127.0.0.1:5188，只公开 frontend，/api/* 转发到 127.0.0.1:8098，原样保留 /api；禁止公开项目根、.env、backend。
第一课由 AI 生成 serve.mjs。终端 A 在根目录 node tools/serve.mjs，浏览器 http://127.0.0.1:5188。
终端 B 在 backend：macOS `sh ./mvnw spring-boot:run`；Windows PowerShell `.\mvnw.cmd spring-boot:run`。
第三个临时终端在根目录执行 Docker Compose / 配置命令。终端标题由学生命名 A-页面、B-后端、C-工具。
修改 HTML/CSS/JS 后保存并刷新页面；修改 Java 后，只重启 B。改变 serve.mjs 才重启 A。
第07课最小健康接口不依赖数据库；第08课才加入数据库依赖和配置。第09课才加入 Redis。

## 数据与页面

九个菜单：概览 dashboard、设备 devices、空间 spaces、能源 energy、历史 history、原始报警 alarms、演练事件 cases、设备责任 owners、管理 admin（角色说明、审计、接入状态）。
四空间 s1–s4；16设备 d01–d16，environment/energy/facility/lighting 四类各4。
练习 JSON：spaces, devices, points, history, alarms；所有条目仅为 TEACHING_MOCK。
Space {id,name,building,floor}。
Device {id,name,category,spaceId,online:boolean|null,simulated:true}。
Point {deviceId,tagId,value:number|null,unit,time:number|null,quality:fresh|stale|missing|invalid}。
History {deviceId,tagId,unit,samples:[{time,value:number|null}]}。
Alarm {id,deviceId,message,status,level,time,simulated:true}；只能查看，不能操作。
28点：环境每台temperature/humidity，能源power/voltage，设施status，照明status/brightness。
保持未知 null、真实0、失效提示。kW是功率，V是电压，不计算kWh或费用。禁止实际设备控制和外部通知。
前6课 localStorage 键 campus-v2-demo 保存空间、责任、事件；角色切换仅是演示。第08起真实读取逐项替换；未接通部分继续显示“浏览器演示”，不混称已经存数据库。

## 后端与响应

Java17、Spring Boot3.4.2、Maven。JdbcTemplate、MySQL8.4、Flyway；第09加 Spring Data Redis、spring-security-crypto。
服务 127.0.0.1:8098；仅本地教学。响应 {code:0,message:"ok",data:...}；失败用对应HTTP状态+非0code+可读message。
GET /api/health 公开返回 data.status="UP"。08 GET /api/devices 可先公开；09起除health/login外全需登录。
POST /api/login {username,password} → {token,user:{username,role}}；令牌随机生成，Redis中campus:v2:session:前缀，TTL1800秒；浏览器只存内存，刷新重新登录。
Authorization: Bearer <token>；POST /api/logout 删除当前会话；GET /api/me → {username,role}。
会话身份和登录响应中的username取自MySQL查到的账号记录，不使用用户输入的大小写形式作为权限身份。
登录3账户：admin/manager/viewer；角色ADMIN/MANAGER/VIEWER；仅本地练习，初始口令由本机配置生成，不在提示词里抄写。MySQL BCrypt存密码，登录响应不返回哈希。
GET /api/devices → 数组；GET /api/overview → {spaces,devices,points,history,alarms}（先各页复用此读数集合）；
GET /api/spaces → 数组；PUT /api/spaces/{id} {building,floor} 仅ADMIN。
GET /api/owners → [{deviceId,username,note,version}]；PUT /api/owners/{deviceId} {username:"manager",note,expectedVersion} 仅ADMIN，无记录version=0。
版本字段（version 与 expectedVersion）在 JSON 里必须是非负整数字面量：不接受小数（0.5、1.0）、数字字符串（"0"）、布尔、null、缺省或超出 int 范围的数，违反一律400且不写库；合法但落后的整数409，由学生重新读取后决定，不自动重发。后续事件动作的 expectedVersion 同此规则。
GET /api/cases → 数组；POST /api/cases {deviceId,message} 仅ADMIN，自动使用已登记责任人；
POST /api/cases/{id}/actions {action,expectedVersion,note?,username?}；
GET /api/audit → 数组仅ADMIN；GET /api/integration → {source:"TEACHING_MOCK",simulated:true,controlEnabled:false,notificationsEnabled:false}。
每个案例 {id,deviceId,message,state,assignee,sourceState,verified,note,conclusion,version,timeline:[]}。
state NEW/ASSIGNED/IN_PROGRESS/CLOSED，sourceState ACTIVE/RECOVERED；创建version1。
action assign（ADMIN，username=manager）,start,note,recover（ADMIN）,verify,close。
MANAGER只处置自己已分派的事件，VIEWER只读。每写必须expectedVersion匹配，成功+1；冲突409，刷新后由学生重新决定，不自动重试。
关闭前须IN_PROGRESS、非空处置记录、来源RECOVERED、独立verify=true、非空关闭结论；关闭后不可写。
MySQL保存devices/spaces/points/history/alarms/users/owners/cases/audit。Redis只保存短时登录，不代替MySQL。
课堂可通过只管理本课程容器的 `docker compose restart redis` 演示重新登录，MySQL业务记录仍在。

## 配置与交付

根 compose.yaml 只定义本课程 mysql8.4 和 redis7.4；mysql127.0.0.1:23501，redis127.0.0.1:23502。
project name campus-v2；专属命名卷，不用外部卷。使用 .env 中DB_PASSWORD、MYSQL_ROOT_PASSWORD、REDIS_PASSWORD、DEMO_PASSWORD。
setup-env.mjs（08由AI生成）用crypto随机生成本地.env，已有则拒绝覆盖；.env.example只有说明占位。不要打印口令。
Spring import optional:file:../.env[.properties]，配置占位${DB_PASSWORD}等；数据库campus_course，用户campus。
README新目录顺序：安装前提→生成.env→docker compose up -d→等待healthy→B后端→A前端→本机.env查看DEMO_PASSWORD并手动填登录→逐项检查→停止A/B→docker compose stop。
不使用 down -v，不删数据来修启动问题。换目录若同名容器在运行，先按README停止自己的旧服务，端口冲突不杀未知进程。同机新目录每条Compose命令使用 `docker compose -p campus-v2-handoff ...`，确保新.env对应新的专属卷。再次打开同一个交付目录，沿用原.env和同一项目名；不得重新随机口令后连接旧卷。
交付工具按白名单打包：frontend、backend/src、pom、Maven wrapper及隐藏.mvn、tools、materials、docs、compose.yaml、根.env.example、.gitignore、README。所有层级排除.env及.env.*变体（仅保留根.env.example）、.private/.runtime/node_modules/target/日志和个人数据。源路径和输出路径的每级父目录都拒绝符号链接。
学生起点包绝不包含参考业务代码；教师参考独立目录。所有验证均标明作者参考验证或学生实做，不能相互冒充。Docker/Windows未经实际运行则明示。
