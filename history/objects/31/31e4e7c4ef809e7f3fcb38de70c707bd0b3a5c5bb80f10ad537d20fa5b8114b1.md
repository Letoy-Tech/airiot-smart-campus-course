# 第04章 开发环境、版本控制与首次贯通

状态：`DESIGNED`。课内 4 学时，按 1＋2＋1 分配。本章依赖的教学脚手架尚待制作；下列命令是未来课堂操作规范，本轮文档工作未执行安装、启动、数据库初始化或测试。

## 进入条件与学习目标

已有第03章合同。教师须事先制作并在干净环境验证独立教学工程 `campus-ai-course/`，含 `frontend/`、`backend/`、`docs/`、`fixtures/`、`evidence/`、锁定依赖、Maven Wrapper、专属数据库说明及最小读接口桩。该拟定目录当前不随文档包交付。

学生完成后能核对工具链、区分源码与构建产物；能用 Git 保存一次可回退的小改动；能解释浏览器到后端的数据路径；能依据网络请求和日志定位首次贯通失败发生在哪一层。

## 模块一：环境清单与版本控制（1 学时）

工具链包括编辑器、Git、Java 17、教师冻结的 Node/npm 和 MySQL 环境。参考前端要求 Node `^20.19.0 || >=22.12.0`，实际课程只选定并验证其中一个版本。教师须在制作阶段明确是否保留 Redis；学生不自行猜测或移除认证依赖。

学生先运行只读版本检查，记录输出与工作目录；版本不符先定位 PATH 和安装说明，不连续重装。Git 用于记录变化，首次提交前检查 `.gitignore`，排除账户配置、数据库数据目录、`node_modules/`、`target/`、`dist/`。已有修改先查看差异，不用 reset/clean 掩盖问题。

产出：环境核对表、源码目录说明和干净基线提交。

## 模块二：让一次请求穿过前后端（2 学时）

教师待制作的最小桩采用第03章合同，包含一空间两模拟设备，`GET /campus/devices` 返回 `{code:0,message,data:{items,observedAt}}`。桩只服务首次贯通；第05章再完成空间设备业务分层与完整接口，第06章再形成正式台账 UI。

在独立教学工程内，按教师已验证的启动说明先启动专属数据库与后端，再启动前端。启动前核对端口；占用时查明进程或使用教师规定的备用端口，不停止未知服务。不能直接启动原平台的运行脚本或连接学校数据库。

首次页面只需显示设备名称、在线三态、模拟标记和查询观察时间 observedAt。观察浏览器 Network：请求地址、状态码、响应 JSON；再检查后端日志，确认请求确实到达后端。前端本地 `/api` 代理转发到后端并去掉前缀，浏览器不直接访问数据库或 AIRIOT。

主动制造一个安全失败：在教学前端临时将请求路径改为不存在的路径。页面应显示失败信息，不能保留“加载成功”假象；恢复正确路径并重新检查。只修改当前实验文件，用 Git diff 审查后形成小提交。

产出：两设备最小页面、一次成功和一次错误请求的脱敏证据，以及恢复后的提交记录。

## 模块三：复现与问题报告（1 学时）

同组另一名学生仅据说明完成一次启动检查，不依赖原操作者口头补充。记录必须包含前置版本、工作目录、命令、关键输出和访问地址；“我这里可以”不是复现说明。

为错误报告写四项：希望发生什么、实际发生什么、最小复现步骤、已取得的证据。先判断是工具链、依赖、端口、后端启动、代理还是合同解析问题，再向 AI 提问；每轮只改一个主要变量，便于知道为何恢复。

产出：可复现操作记录和一个已定位问题案例。未真正执行的步骤保持待执行状态。

## 最小实验步骤与命令条件

下面仅在教师已交付并验证的独立教学工程中执行；不要在本课程文档目录或原平台目录照抄启动命令。安装依赖与启动方式以教师冻结版 README 为准。

```sh
# 任意目录：只读核对，保存实际输出
git --version
java -version
node --version
npm --version

# 进入独立教学工程后：先确认当前位置与改动
pwd
git status --short
git diff
```

1. 核对工具版本、工程路径和专属数据库，完成基线提交。
2. 按教师说明安装锁定依赖；前端仅在含 `package-lock.json` 的目录使用 `npm ci`。
3. 按经过验证的 README 启动专属后端和前端，记录各自地址，不自行套用原系统端口。
4. 在浏览器检查 `/campus/devices` 经代理的请求，核对响应内两条设备记录与可空字段。
5. 修改为错误路径，记录失败；恢复后再读一次接口。
6. 审查差异，只提交本实验涉及文件，记下提交标识与尚未完成的业务。

## 典型错误及定位

- 页面为空但 HTTP 200：检查是否取错 `data.items` 层级，再检查控制台错误。
- 接口返回 HTML：核对代理前缀和目标，可能请求落到了前端页面回退。
- 后端启动失败：先看首个有效错误，分别检查 Java 版本、数据库连接和端口；不要贴完整秘密配置。
- Git 出现大量文件：检查忽略规则与工作目录，勿直接提交依赖或构建目录。
