1. 安装并打开 CodeBuddy 独立 IDE

打开官方安装说明，下载与你系统和处理器对应的安装包。macOS 安装到“应用程序”；Windows 运行安装程序。启动 CodeBuddy，按登录页完成你自己的登录。扫码或验证码在软件中完成，不发给同学或AI。

本教材使用独立 IDE。打开工程后，在 AI 对话区选择 Craft（Agent），它可以修改工程文件；Ask 主要用来提问。入口和文字可能随版本改变，找不到时先让老师对照官方 IDE 使用说明。

模型列表中选择本账号可用、支持编程的模型即可；若已能用 DeepSeek，就继续使用。课程不要求先接百炼、自带 Qwen Key 或购买额外服务。CodeBuddy登录、模型额度和百炼API账户是不同的准备事项；登录其中一个不代表另一个已配置好。模型报额度不足或不可用时，先处理账号/模型选择，不能把它当作代码错误反复重写工程。

2. 安装 Node 22，确认终端找得到

从 Node.js 官方下载页面在页面顶部版本下拉框选择 22.x，再选本机系统和处理器，下载对应的安装包，按安装向导完成。课程统一22，避免同班同学因版本不同得到不同现象。安装后关闭再打开 CodeBuddy，让新终端读到更新后的环境。

在 CodeBuddy 顶部菜单选择“终端 → 新建终端”。终端是输入命令的地方，与AI对话框分开。在底部终端输入一行并按回车：

node --version

看到 v22. 开头就通过。若提示找不到命令，先重开 CodeBuddy 再试；仍失败，请老师检查安装位置和 PATH。不要把“node --version”发给 AI 后把它的回答当成自己的检查结果。

3. 解压空白起点，只打开这一层

解压随课提供的 学生空白起点 V2.0.1.zip。解压后应有一个名为 campus-lab 的文件夹，把它放到自己方便找到的位置，例如 Windows 的 C:\course\campus-lab，或 macOS 的个人目录下 course/campus-lab。

在 CodeBuddy 选择“文件 → 打开文件夹”，选中 campus-lab。左侧文件树应能看到：

campus-lab/

  materials/

    maven-wrapper/             ← 第07课才用的Maven启动工具
  README.md

如果打开后左边只有一个 campus-lab 子文件夹，说明多打开了一层；重新打开内层。如果看到完整后端业务、完整网页或教师验证记录，说明拿错了包，请换“学生空白起点”。

点击 frontend/index.html。编辑区没有内容是正常的。不用先复制教师参考成品，第01课会带你写出第一个标题。

4. 学会这一套动作，后面每一步都一样

  1. 在教材找到当前步骤的“发给 CodeBuddy”代码框，复制整段到 AI 对话框。带【方括号】的补救提示词，只在失败时使用，并换成你实际看到的现象。
  2. 等这一轮回复结束。期间不要再发下一步。遇到文件改动确认，查看路径是当前 campus-lab 的本步文件后保留改动；若软件已直接写入文件，不再找一个不存在的“应用”按钮。
  3. 在编辑器里确认目标文件出现，使用“文件 → 全部保存”。AI说完成后，仍需你自己运行或点击。
  4. 教材写“在终端运行”时，把命令粘贴到 底部终端；写“打开地址”时，把地址粘贴到 浏览器地址栏。提示词、终端命令和网址各有位置。
  5. 对照“应该看见”亲自操作。通过才进入下一步；失败就只发当前步骤的修复提示，修完后重做同一个检查。

AI写的文件可能与你同学不完全一样。课程以按钮和数据的行为为准。它如果突然重新生成整套工程，先检查是否发了过大的提示词，让它保留已经做好的文件，只处理当前小步。

5. 分清“AI完成”和“程序在运行”

对话很长时，CodeBuddy可能显示“Chat history summarized”（对话已摘要）。摘要后的回复有时只完成本步的一部分，例如只报告两个测试，却没有接好原页面。仍按本步的接口、页面和亲自操作逐项核对；发现遗漏就把当前步骤和具体缺项反馈给它，要求继续完成。不要把局部测试、任务清单勾选或一句“完成”当作整步通过，也不要为此重新解压工程、覆盖配置或删除数据库。

给终端命名时，在终端列表的标签上点右键，选择“重命名”，输入 A-页面。如果版本没有重命名入口，可以用终端旁的标签编号记录A/B/C，不影响命令。新建窗口用终端栏的“+”。

确认当前位置：macOS输入 pwd，Windows PowerShell输入 Get-Location。若不在工程根，在终端输入 cd，空格后加带引号的完整目录，例如Windows cd "C:\course\campus-lab"；macOS可输入 cd 后把Finder中的campus-lab文件夹拖进终端，再按回车。目录最后一层应是campus-lab。教材写“工作目录为backend”时再进入backend，不要每次都重复cd backend。

第一课只用 A。第七课才新建 B，第八课才需要 C。不要在正在跑服务的终端粘贴下一条普通命令。 教材明确写“重启 A/B”时，才在对应终端按 Ctrl+C，等提示符回来后再运行启动命令。Windows 询问是否终止批处理时，确认结束自己的这个进程。

6. 第07课前：安装 Java 17

从 Eclipse Temurin 官方页面选择17、JDK和本机架构。安装后重开 CodeBuddy。新终端输入 java -version，应显示17；若电脑原来已有Java21，不卸载原版本，第07课会教你只让当前终端使用17。

macOS 可先执行 /usr/libexec/java_home -V 查看已安装的JDK。Windows 在安装器中启用 JAVA_HOME/PATH 选项；如果同时有多个17版本，让老师记录本次使用的那个安装目录。不要让AI猜一个不存在的目录。

7. 第08课前：安装并启动 Docker Desktop

根据Docker官方安装入口安装本机对应的 Docker Desktop，它包含本课使用的 Compose。Windows 按官方 Windows 安装要求完成 WSL 2 等前提，遇到需要系统管理员权限或重启时先完成安装，再回来上课；不要在课上不断重复失败的启动命令。

打开 Docker Desktop，等界面显示引擎在运行。CodeBuddy 的新终端逐行运行：

docker version
docker compose version

第一条应同时显示 Client 和 Server；只有 Client 不够。第二条应显示 Compose 版本。这里还不启动数据库，第08课才让AI在本工程生成配置并启动本课程容器。教室网络可能影响镜像下载，教师应提前在教室实际检查下载能力。
