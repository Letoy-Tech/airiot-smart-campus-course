打开 `frontend/src/domain/course.ts`，查找 `STUDENT_TODO_C12_BEGIN`。本章实际起点如下：

```typescript
export function changeCaseState(state: string): { state: CaseState | ''; skip: number } {
  // STUDENT_TODO_C12_BEGIN：每次改变 state 都从第一页查询，包括清空筛选。
  void state
  return { state: '', skip: 0 }

```

`state`是事件筛选条件；空文字 `''` 代表全部状态。`skip` 是跳过多少条：每页10条时，第一页0，第二页10。`void state` 在这里仅表示占位代码暂不使用传入值。**这个起点会丢掉用户选择的状态，不是已经正确筛选、只是页码错了。**

先不修改，运行一次针对性测试：


如果本章以前已完成，重复准备后代码和测试仍可能正确；下面的起点代码与失败仅供理解，不要改回占位来伪造“修复前失败”。如果提示找不到测试文件，先检查终端是否在 `app`。如果失败来自其他章TODO，回到对应章补完；不要将所有失败都归为分页任务，更不要删测试。

### 2. 按五次操作，记录请求与页面两种结果

按第11篇方法打开 Network，点Fetch/XHR，在过滤框输入 `alarm-cases`。列表请求与详情请求会同时出现；选择没有事件ID、带 `limit/skip` 参数的列表请求。在“Payload / 载荷”或 Headers 的 Query String Parameters 看参数，再到Response看 `data.total` 与 `data.items`。

先把“负责范围”设为“当前可读全部”，“每页”选“10条”，“事件状态”选“全部状态”。没有管理员写权限也不影响这轮读取。

| 你实际点什么 | 列表请求应怎样 | 页面及响应应怎样 |
| --- | --- | --- |
| 全部状态 → 点击下一页 | limit=10，skip=10，不带state | 总数14，第二页4条 |
| 在第二页改“事件状态”为已分派 | state=ASSIGNED，skip=0 | 总数2，第一页2条；不能显示“当前筛选没有事件” |
| 改为处理中 | state=IN_PROGRESS，skip=0 | code=0、total=0、items=[]；页面明确当前筛选没有事件 |
| 改为待分派 → 下一页 → 刷新浏览器 | 刷新前NEW/skip=10；刷新后首个列表请求NEW/skip=0 | 刷新前第二页2条；刷新后仍选待分派，第一页10条、总数12 |
| 地址栏输入 http://127.0.0.1:5178/#cases?state=malformed 再按回车 | 首个列表请求skip=0，不带非法state | 默认全部状态，按真实响应显示14条总数 |

第四行说的是**浏览器刷新**（Windows `Ctrl+R`、macOS `Command+R`），不是页面里的“刷新列表”按钮。后者会重读当前页，这两个动作不要混为一谈。

清空状态也要回到第一页。列表排序是 `createdAt DESC, id DESC`；不要求你看到的第一个ID正好是最后点击触发的ID。请求参数顺序不同不构成错误，字段和值相同即可。

遇到以下情况这样处理：

- 选已分派后请求没有state：查看C12是否保存、是否仍返回空文字，别修改数据库。
- 请求正确，但总数不是2：先核对教师演示库、负责范围、他人是否又写入，不在前端硬编码数量。
- 状态正确却带skip=10：核对本次 `next.skip` 与页面调用；保存Network片段给AI，不用删除分页按钮回避问题。
- 401：重新登录；403：请教师核对当前角色；500/超时：保留错误，先确认服务，不重复触发事件。

把五行的实际参数、实际总数和实际条数写到 `evidence/ch12.md`。截图只截列表和参数区，不截密码、Cookie或CSRF。

## 第五步：生成没有秘密的交付目录，再压缩

先检查本人 `docs`、`evidence` 中没有口令、Cookie、CSRF、连接密码；不要放整段浏览器请求头。教师历史PASS若用于判读，应明确来源并与本人结果分开，不能作为个人通过证据。

在 `app` 根目录运行：

```text
node tools/hand-in.mjs
```

工具会在 `app` 同级生成 `app-handoff-日期时间/`，不是覆盖你正在编辑的工程。里面的源码直接在目录根；工程内的学生 `docs`、`evidence` 和 `.lesson-state.json` 一并交付，接手者重复prepare也不会重挖已经准备过的章节。外层 `campus-ai-lab/docs` 的需求设计资料复制为 `project-docs/`。接手者再次交付时，优先保留工程根已有的 `project-docs`，不依赖原作者电脑上的外层目录。工具不自动压缩。

白名单会排除 `.private`、`.git`、`.lesson-backups`、`node_modules`、`target`、`dist`、私密 `.env`、HAR及log，并检查待交文字是否出现已知本机口令；无秘密的 `.env.example` 可以保留。学生起点不附教师PASS；工具不能代替你判断报告作者，不能把手工搬来的教师结果当个人证据。第11篇经授权提供的教师原报告可随本人的判读交付，但必须明确来源。被拒绝时阅读报错、找到本人的泄漏记录并移除敏感值后重试；不要关闭检查或让AI绕过它。工具也不能保证识别所有秘密，仍需人工查看。

在文件管理器打开新目录，亲自核对：

1. 有源码、`frontend/package-lock.json`、`backend/pom.xml`、Maven Wrapper、迁移和fixtures。
2. `README.md`、`docs/HANDOFF.md`、`project-docs`、`.lesson-state.json`及本组 `evidence/ch11.md`、`ch12.md`存在；文档引用的真实报告也存在。
3. 显示隐藏文件后，没有上面排除的秘密和生成目录；实际证据不包含登录凭据。

Windows在新交付目录上右键“压缩为ZIP文件”（旧版为“发送到 → 压缩(zipped)文件夹”）；macOS右键“压缩…”。压缩的是 `app-handoff-日期时间`，不是整个 `campus-ai-lab`。

若文件被压缩到了错误层级，先打开ZIP查看，再重新生成正确交付；不要删除原长期工程来“清理”。

工具拒绝或文件缺失时，可把下面提示和**不含秘密值**的报错/文件名发给AI。预期得到安全的检查动作；含秘密的原文先在本机移除，不能为了排错再次泄漏：

## 第六步：在新目录复现，留下可回退的版本

把ZIP复制到桌面新建的 `campus-ai-review` 文件夹并解压。解压后进入真正含有 `backend/frontend/tools` 的那一层，用VS Code打开它。**不是在原app又跑一遍。**

先在原工程两个服务终端按 `Ctrl+C` 停止8091/5178；数据库由教师管理，不因换目录而清理。在**新目录的VS Code窗口**点“终端 → 新建终端”，确认当前目录是解压后的工程根，再按[第04篇第三步](04-安装工具与第一次改代码.md)为这个终端设置 `JAVA_HOME`。不能假定原窗口的临时设置会跟过来。然后照解压后的README依次执行doctor、锁定安装、init、check、build。新的init生成新本机账号，不能继续使用旧浏览器会话；教师另交接复现用独立schema与迁移，缺这一项就如实停在数据库交接，不擅自连回日常库。

启动新目录的两个服务：后端和前端各用一个终端，每个新终端都按第04篇第三步设置自己的 `JAVA_HOME`，再执行README中的启动命令。退出旧登录后用新副本账号登录。完成三项：设备台账正常读取；在教师给定的独立库里由管理员创建并分派一条本地演练，处理人按第09篇闭环并回读；换查看者确认不可写。分页14条数据只在教师另行准备后按第三步的停后端、交接配置、重启、登录顺序重做，空新库不能判分页回归通过。
