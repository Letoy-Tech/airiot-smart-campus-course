## 二、要从 materials/maven-wrapper 复制哪些文件到 backend

生成 `backend` 目录后，把下面四项原样复制到 `backend/` 根下，保持目录层级不变：

| 源路径（materials/maven-wrapper/…） | 复制到 | 说明 |
| --- | --- | --- |
| `mvnw` | `backend/mvnw` | macOS / Linux 启动脚本，复制后确认仍有可执行权限 |
| `mvnw.cmd` | `backend/mvnw.cmd` | Windows 启动脚本，macOS 上也一起复制，交付包才完整 |
| `.mvn/wrapper/maven-wrapper.jar` | `backend/.mvn/wrapper/maven-wrapper.jar` | 隐藏目录，复制时必须连同 `.mvn/wrapper/` 两级目录一起带过去 |
| `.mvn/wrapper/maven-wrapper.properties` | `backend/.mvn/wrapper/maven-wrapper.properties` | 决定下载哪个 Maven 版本，不要手改 |

注意事项：

- `.mvn` 是点开头的隐藏目录，用图形界面复制时容易漏掉；漏了它 `./mvnw` 会失败。复制完用 `ls -la backend` 和 `ls -la backend/.mvn/wrapper` 核对。
- `maven-wrapper.jar` 是二进制文件，不要用文本方式编辑或重新保存。
- 复制时要包含隐藏目录，可用：`cp -R materials/maven-wrapper/. backend/`（源路径末尾的 `/.` 表示连隐藏内容一起复制）。
- 第一次执行 `./mvnw` 会联网把 Maven 3.8.6 下载到本机用户目录，属于 wrapper 自身行为，不是让学生再装一个 Maven。课堂若网络受限，需要提前说明。
- `materials/maven-wrapper/` 只有启动工具，没有业务成品代码；不要从这里复制 Java 源码。

## 三、Java 必须使用 17

| 要求 | 怎么确认 |
| --- | --- |
| Java 版本是 17 | `java -version` 第一行含 `17.` |
| `JAVA_HOME` 指向 JDK 根目录 | `echo $JAVA_HOME` 输出以 `/Contents/Home` 结尾（macOS），**不是** `.../Contents/Home/bin` |
| PATH 里的 `java` 也是 17 | `which -a java` 的第一条要在 JDK 17 的 `bin` 下，且 `java -version` 为 17 |

为什么两处都要 17：`JAVA_HOME` 决定 Maven 与编译器用哪个 JDK，PATH 里的 `java` 决定你在终端直接敲 `java` 时用的是哪个；两者不一致时，容易出现“编译用 17、运行用 21”的怪问题，报错信息也会互相矛盾。

`JAVA_HOME` 的正确写法（macOS）：

```sh
# 正确：JDK 根目录
export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-17.jdk/Contents/Home

# 错误：指到 bin，Maven 会找不到 JDK
# export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-17.jdk/Contents/Home/bin
```

## 四、只在本终端临时切换（不改系统环境变量）

下面命令只对**当前这个终端窗口**生效，关掉窗口就恢复系统原来的版本；不改 `~/.zshrc`，不改系统设置，也不需要重启电脑。

### 4.1 Java 17

```sh
export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-17.jdk/Contents/Home
export PATH="$JAVA_HOME/bin:$PATH"
```

随后在同一个窗口里确认三件事：

```sh
echo $JAVA_HOME        # 应以 /Contents/Home 结尾
which java             # 应指向 jdk-17.jdk/.../bin/java
java -version          # 应显示 17.x
```

Windows（PowerShell，仅当前窗口）：

```powershell
$env:JAVA_HOME = "C:\Program Files\Java\jdk-17"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
```

### 4.2 Node 22

本机已安装 Node 22.21.1，但新开终端默认拿到的是别的版本（本次实测为 v26.3.0）。在同一个 B 窗口临时前置已安装的 22，不改全局默认：

```sh
export PATH="/Users/learner/.nvm/versions/node/v22.21.1/bin:$PATH"
```

随后确认两项：

```sh
node --version         # 应显示 v22.21.1
which node             # 应指向 /Users/learner/.nvm/versions/node/v22.21.1/bin/node
```

注意：

- 只改当前窗口的 PATH；不要执行 `nvm alias default`、不要改 `~/.nvm` 默认版本、不要改系统环境变量。
- 路径写死为已安装目录，因此不依赖 nvm 是否加载；若该目录被删或升级，用 `ls /Users/learner/.nvm/versions/node/` 重新确认实际版本目录。
- Windows 若使用 nvm-windows，对应做法是 `nvm use 22`；不使用 nvm 时，把 Node 22 安装目录的 `bin` 前置到当前窗口的 `Path`，同样不要改系统变量。

### 4.3 两项一起确认

Java 和 Node 是**两条独立检查**，通过一项不代表另一项也对。在 B 窗口按顺序执行后，一次性确认：

```sh
echo $JAVA_HOME        # 以 /Contents/Home 结尾
java -version          # 17.x
node --version         # v22.21.1
```

以上命令由学生自己在终端执行；本文不代为修改环境变量，也不代为运行。

## 五、两个终端各做什么

| 终端标题 | 位置 | 命令 | 作用 |
| --- | --- | --- | --- |
| A-页面 | 项目根 `campus-lab/` | `node tools/serve.mjs` | 只公开 `frontend`，浏览器打开 `http://127.0.0.1:5188`；`/api/*` 转发到 `127.0.0.1:8098` |
| B-后端 | `campus-lab/backend/` | macOS `sh ./mvnw spring-boot:run`；Windows PowerShell `.\mvnw.cmd spring-boot:run` | 启动 Spring Boot，监听 `127.0.0.1:8098` |

约定：

- **每开一个新终端，两项检查都要重做一遍**：`java -version` 必须是 17，`node --version` 必须是 v22.21.1（本课程预期 22）。第四节的两个 `export` 只对执行过它的那个窗口有效，新窗口会退回系统默认版本，这不是环境坏了，而是临时设置没有继承。
- 新终端检查顺序建议：先 `echo $JAVA_HOME` 与 `java -version`，再 `node --version`；两项都通过才执行启动命令。任一项不符就回到第四节补一次 `export`，不要靠猜。
- A 窗口只跑页面，B 窗口只跑后端，两边都不要混着敲命令；第三个临时终端留给第 08 课起的 Docker Compose。三个窗口各自都要检查 Node 22（A/C 需要 Node，B 需要 Java 17 与 Node 22）。
- 改了 HTML / CSS / JS 只需保存并刷新浏览器；改了 Java 只在 B 窗口重启后端（先 `Ctrl+C`，再重新执行上面的启动命令）；只有改了 `tools/serve.mjs` 才重启 A 窗口。
- “AI 回复完了”和“终端里的服务还在跑”是两件事：AI 不会替学生启动常驻服务，学生也不要因为 AI 停止输出就去关终端。
- 端口被占用时先确认是不是自己上一课的进程，按 README 停止自己的服务；不要杀掉不明进程。
