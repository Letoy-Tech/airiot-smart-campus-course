# 先准备，再做第一张页面

这条主线只用一个工程：桌面 `campus-ai-lab/app`。前端业务页面逐站增加；认证、请求、数据库和完整后端服务由教师提供可读源码。你会让CodeBuddy 写页面，也会读和修改后端业务规则。参考源码是失败时的对照，不是你的完成记录。

## 先装工具，再复制工程

先从 [CodeBuddy官方下载](https://www.codebuddy.cn/downloads/) 选择独立 IDE：Windows选对应Windows版本；Mac按“关于本机”中的Apple芯片或Intel选择。安装后按屏幕提示登录账号。Node 22.21.1、JDK 17及选做Git的安装细节见[工具安装步骤](../walkthroughs/index.html#part-04)；只看安装部分，不必另外安装VS Code。回来复制本页的project-journey/app，不复制旧student-project。

1. 完整解压教学包，打开 `resources/project-journey`。
2. 把其中的 `app` 复制到桌面 `campus-ai-lab`。若已有同名作业，保留它，新建 `campus-ai-lab-v12`；不要覆盖。
3. 在 CodeBuddy IDE 点“文件 → 打开文件夹”，选择刚复制的 `app`。左边应直接看到 frontend、tools、lesson-bundles；backend会在第02站加入。
4. 顶部点“终端 → 新建终端”。后面所有命令默认在这里执行，逐行粘贴、按回车、等结束。

```sh
node --version
node -p "process.cwd()"
```

预期Node为22.21.1，当前目录以app结尾；第01站只需Node，Java到第02站再核对。找不到命令：安装后完全退出再打开CodeBuddy IDE；仍失败让教师看第一条错误。

## Java只设置当前终端

macOS：

```sh
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
export PATH="$JAVA_HOME/bin:$PATH"
java -version
```

Windows PowerShell（默认Temurin安装位置）：

```powershell
$courseJdks = @(Get-ChildItem "C:\Program Files\Eclipse Adoptium" -Directory | Where-Object Name -Like "jdk-17*")
if ($courseJdks.Count -ne 1) { throw "请教师确认唯一JDK17根目录" }
$env:JAVA_HOME = $courseJdks[0].FullName
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
java -version
```

每个新终端都要同时设置JAVA_HOME和PATH；JAVA_HOME指JDK根目录，不是bin。只改当前终端，不改全局shell。第02站begin后可用`node tools/course.mjs doctor-env`检查；它会拒绝“JAVA_HOME=17但PATH仍为Java21”。详细配置与交付复现见[当前终端与独立服务](../resources/project-journey/app/docs/01-跨平台启动.md)。

## 第一次启动

```sh
npm --prefix frontend ci
```

Windows遇到npm.ps1限制时，把npm改成npm.cmd。不要改系统策略。5178端口被占用时，先检查自己之前的终端，不结束未知进程。

第01站只启动前端：

```sh
npm --prefix frontend run dev
```

看到本地地址后，在浏览器打开 http://127.0.0.1:5178 。这个终端保持运行；要停，在这个终端按Ctrl+C。教程在浏览器中阅读，代码和AI在CodeBuddy IDE中操作，运行结果在上述本地程序地址查看。

## 第02站才启动后端

先运行第02站begin加入后端文件，再另开终端，同时设置JAVA_HOME与PATH，单独构建后端。此时前端业务页尚待实现，不先跑会编译前端的完整build：

```sh
node tools/course.mjs doctor-env
node tools/course.mjs init
node tools/course.mjs build-backend
node tools/course.mjs backend
```

后端保持运行。登录密码在本机 `.private/accounts.json`，用编辑器查看，不复制给AI。第03站起让教师按数据库交接单准备本组库；停掉first-chain后用下面命令启动：

```sh
node tools/course.mjs backend-db
```

数据库配置和迁移由教师确认；学生不需要安装MySQL。出现连接错误时，先检查本组配置和网络，不能改连原平台数据库。

## 第一次和 CodeBuddy 协作

1. 确认IDE打开的是自己的app。右侧打开CodeBuddy对话；若你进入的是Agents首页，先选择“编程模式”。
2. 打开模式选择，选 **Ask**。先发送：“只读取CODEBUDDY.md和journey-state.json，告诉我现在第几站，先不要改文件。”预期它引用本工程的实际文件；找不到就先检查打开的文件夹。
3. 对话输入框输入 `@`，选“Files & Folders/文件与文件夹”，输入本页目标文件名，点选它。看到文件引用后，再发送本页提示词。不要引用整个电脑目录。
4. 讲清需求后切 **Craft**，让它改本次文件。复杂的多文件任务用 **Plan**，先读计划，确认只涉及本次目标再执行。
5. 完成后打开本次变更/差异，逐个点文件名。新增/删除的行是什么？是否只改了本次文件？按“保存全部”，再在终端运行本页的verify。AI写“完成”不代表程序通过。
6. 报错就在同一对话贴第一条错误，让它先定位再改。改完重跑刚才失败的命令。

菜单名称可能随IDE版本变化；课堂先由教师统一安装版本并演示入口。模型选择使用学校允许、账号实际可用的模型，课前记录其名称；本教程不假定每个账号都有Qwen3，也不要求学生购买API。没有可用额度时先让教师选择可用路线；若明确采用参考救援，记录“AI未执行/参考复用”，不能冒充AI生成，不自动购买额度或复用其他项目Key。

[官方概述：Ask/Craft/Plan与文件引用](https://www.codebuddy.cn/docs/ide/User-guide/Overview) · [官方项目规则](https://www.codebuddy.cn/docs/ide/User-guide/Rules) · [官方结果查看](https://www.codebuddy.cn/docs/ide/User-guide/Agent-Mode/Results)。核对日期：2026-10-20。另有2026-10-20的CodeBuddy内置DeepSeek学生实做记录；它对应V1.2.0，不代替当前修订版、每名学生或Qwen接入的验收。

## 保留自己的改动

每站开始前，工具检查前站是否构建通过，并保护已改文件。看到冲突先停止，先保留当前文件和IDE变更；只有明确选择参考救援后才让CodeBuddy读对应参考与备份，并记录复用范围。不要让它删除状态文件或用reset跳过检查。

参考源码是对照。用了哪些、自己写了哪些，都在evidence里记一行。`.private`中的账号和数据库密码不交给AI，CODEBUDDY.md是行为约定，不是阻止AI读取文件的安全隔离。

## 模型路线先记录，不猜账号能力

学校先选账号实际可用的模型。在CodeBuddy模型列表选择内置路线后，用不含秘密的一句需求测试是否真正返回；记录IDE版本、界面模型名、服务路线、响应/错误、可见积分与Tokens。界面没显示的上游model ID或地域写“未显示”，积分不换算现金或百炼账单。2026-10-20学生实做用了内置Deepseek-V4.1-Flash，未请求百炼Qwen；这不是每个账号都有同模型的承诺。

使用百炼Qwen或其他自定义模型是教师可选配置：[CodeBuddy自定义模型说明](https://www.codebuddy.cn/docs/ide/Features/models)要求兼容接口的完整请求地址；[百炼接口说明](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)须核对地域、端点、实际model和该账号权限。IDE登录成功不等于百炼模型已配置或调用成功。由教师在受限的本机用户配置中设置本课程独立凭据，不放app/.codebuddy、不写VITE_*、不发送聊天截图；不能借用其他业务Key或替学生购买充值。未实际调用则如实保留未验证。

本工程默认无.git。可用CodeBuddy本次变更、文件diff和逐站记录审查；只有已建立自己的Git仓库才运行git命令。不要让模型为了通过检查新建/删除临时测试、升级依赖或调用不存在的npm test；实际脚本名是test:unit。
