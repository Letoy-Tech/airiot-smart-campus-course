# AI 编程课程大纲

## 一 课程定位

课程名称为“AI 编程——以智慧校园平台重建为例”。面向学过一门编程语言、尚无完整项目经验的学生，课内 48 学时。学生使用通义等国内网页聊天工具，以 Qwen3 系列为模型案例，由自己完成文件编辑、命令执行、结果核验和版本提交。

课程要培养的是借助 AI 完成软件工程任务的能力。平台本身不要求接入聊天机器人、训练大模型或部署推理服务。学生要能说清系统解决什么问题、数据从哪里来、业务规则为何这样设计、生成的代码如何验证，以及别人怎样接手。

参考对象是现有智慧校园系统，采用 Vue 3 与 Java Spring Boot 的前后端结构。教学作品保留核心业务和工程约束，学生可自行设计 UI、布局和视觉风格。参考系统不作为全量复制任务，也不以代码相似度评分。

## 二 课程完成后的能力

| 能力 | 可观察表现 | 主要证据 |
| --- | --- | --- |
| 需求分析 | 将“设备出问题后有人处理”转成角色、场景、规则与验收标准 | 需求基线、用例、追踪表 |
| 软件设计 | 说明界面、业务服务、数据库和外部数据源的职责 | 架构图、数据模型、接口合同 |
| AI 协作 | 限定一次任务的文件和规则，识别生成结果中的错误 | 任务卡、修改前后差异、核验记录 |
| 代码构造 | 完成设备、监测、权限及事件闭环的业务实现 | 分阶段代码与运行演示 |
| 质量保障 | 主动验证失败、越权、冲突和回滚，而不仅测试成功页面 | 自动化与人工测试证据 |
| 工程交付 | 让同学按文档复现运行，并完成一次受控变更 | 交付包、交接记录、答辩 |

## 三 48 学时结构

各章按“概念与问题 1 学时、项目实践 2 学时、核验与接力 1 学时”组织，共 12×4=48 学时。具体课次可以拆为两次 2 学时；此处不把学时换算为分钟。安装检查安排在开课准备阶段，第 04 章仍预留环境排障和版本管理时间。

| 章 | 三个模块 | 关键工程制品 |
| --- | --- | --- |
| 01 | 生命周期与项目边界；网页 AI 的小任务协作；证据与交接 | AI 任务卡、个人基线练习 |
| 02 | 场景与角色；需求、验收与范围；任务分解及风险 | 需求规格、迭代计划 |
| 03 | 分层与数据源边界；数据模型、状态及接口；设计评审 | 架构、ER 图、API 合同 |
| 04 | 环境与依赖；最小前后端贯通；Git 提交及恢复 | 可复现基线、运行记录 |
| 05 | 后端分层与校验；设备与空间映射；接口测试 | 读接口、本地映射接口 |
| 06 | 信息结构与原型；设备列表、筛选与详情；UI 状态验证 | 自主 UI、组件和交互 |
| 07 | 时间、单位与数据质量；最新值与历史图表；异常与刷新 | 监测页面、原始样本表 |
| 08 | 认证与授权；三角色及对象范围；越权与撤权测试 | 权限矩阵、拒绝证据 |
| 09 | 事件状态机；分派、处理、恢复核实及关闭；版本冲突 | 演练事件闭环 |
| 10 | 设备责任关系；责任登记与自动分派；时间线及追溯 | 责任模块、变更记录 |
| 11 | 独立测试设计；接口、并发与回滚测试；缺陷修复回归 | 测试报告、缺陷单 |
| 12 | 构建与交付；变更维护及复现；个人答辩与复盘 | 发布基线、交付说明 |

## 四 必修作品与进阶作品

基础作品必须能在没有 AIRIOT 账号、没有模型 API Key 的环境中完成。数据来自显式标识的教学模拟组件；事件与责任登记写入学生自己的数据库。

**必修业务：**设备列表与筛选、空间映射、最新采集值与一类历史曲线、三角色权限、演练事件闭环、设备责任登记、相关时间线及交付文档。概览由这些数据汇总而来；能源展示仅作为已有电压或功率点的视图，不新增费用计算。原始报警保留只读合同和教师参考组件，其页面扩展及真实接入作为选做，不新增必修作业。

**教师提供的基础：**依赖冻结的工程骨架、认证底层、最小账户数据、模拟数据组件、数据库环境与测试入口。学生需要阅读基础组件的边界，亲自补充校园业务授权和拒绝测试；提供基础并不等于提供全部业务答案。

**进阶选做：**真实 AIRIOT 只读适配、更多图表与页面、复杂查询、自动化持续集成、隔离部署与恢复，以及对网页 AI 与编码工具的比较。进阶不占必修 48 学时，不以付费账号、服务器或硬件作为获得高基础成绩的条件。

通用用户管理后台、复杂权限配置台、完整审计运营台、远端设备控制和外部通知不要求学生从零重建。它们可作为参考组件或后续课程内容。

## 五 项目推进方式

采用短迭代：每次提出一个可检查的变化，学生先给出自己的理解，再请 AI 提供方案，完成局部代码、运行、评审和提交。网页 AI 不读取本地仓库，学生负责把准确的文件和运行证据提供给它。

建议两人一组，轮换“实现者”和“审查者”，双方都要完成可归属的代码与核验记录。允许独立完成；团队规模不影响必修范围。每位学生保留个人 AI 使用记录并单独答辩。

| 里程碑 | 截止章节 | 完成条件 |
| --- | --- | --- |
| M1 定义项目 | 03 | 需求、模型、接口和验收能相互对应 |
| M2 设备可见 | 06 | 教学数据通过后端进入自主设计的设备界面 |
| M3 数据可信 | 08 | 历史与异常状态明确，三角色权限有效 |
| M4 业务闭环 | 10 | 演练事件、责任人和时间线完成持久化流程 |
| M5 可交付 | 12 | 测试与复现通过，学生可解释并修改自己的作品 |

## 六 学时负担与降级方法

48 学时的可行性依赖教师先完成并验证脚手架。若要求学生同时从零学习 Java、Vue、SQL、认证框架、部署和 AIRIOT，课程负担会超过当前设计。

课堂落后时，先压缩装饰动画、额外图表、通用后台和进阶接入；保留设备读取、后端授权、事件关闭规则、版本冲突、测试和交接。提供章节检查点供学生定位差异，使用救援检查点须记录使用原因，再独立解释和补做关键改动。不能用整套成品覆盖作业来冒充完成过程。

课后安排以巩固、阅读和整理证据为主。核心评分项目应能在课内完成；若试讲显示需要大量额外编码时间，应缩减功能或增加教师模板，不能把超载静默转移给学生。

## 七 成果与后续编写

每组交付源代码、依赖锁定文件、运行说明、需求和设计、测试报告、交接文件；每人交付代表性 AI 协作记录、对生成内容的纠错实例和答辩结果。评分见 [考核与验收](04-考核与验收.md)。

本阶段先完成全课程大纲和分模块设计。随后依次制作教学工程、扩写正文与实验、实操核验和审校；完成后再转为包含课次目标、教学活动、时间分配及形成性评价的教案。详细关卡见 [编写进度](05-编写进度与教案转换.md)。
