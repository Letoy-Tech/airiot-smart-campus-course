# 第09段：补好关闭规则，亲手完成一条演练事件

本段把“登记了一件事”走到“有证据地结束它”。你要修改后端的一小段关闭判断，然后在页面完成创建、分派、开始、记录、模拟恢复、独立核实、关闭。全部是**本地教学演练**，不改变真实设备或上游报警。

继续桌面 `campus-ai-lab/app`。教师已经提供登录、数据库表、七类动作、事务和页面；你补 `requireClosable` 中的业务判断。事务就是“事件主记录和它的时间线一起保存，任何一步失败一起撤销”。本章不重写事务框架。

## 第3步：只替换C09，并用现有测试核对

在原文件仅选中BEGIN与END之间的 `throw new ApiFailure(501, "TODO_C09");`，替换成以下代码。两条标记、方法签名和外面的括号全部保留。

```java
        if (!"IN_PROGRESS".equals(c.state)
                || timeline.stream().noneMatch(e -> "NOTE".equals(e.action))
                || !"DEMO".equals(c.sourceType)
                || !"LOCAL_DEMO".equals(c.sourceScope)
                || !"RECOVERED".equals(c.sourceState)
                || !"DEMO_RECOVERED".equals(c.sourceRawStatus)
                || c.sourceRecoveredAt == null
                || c.sourceRecoveredAt < c.occurredAt
                || !"PASS".equals(c.sourceCheckOutcome)
                || c.sourceVerifiedAt == null
                || c.sourceVerifiedAt < c.sourceRecoveredAt) throw ApiFailure.state();
```

`noneMatch`在这里表示“没有任何一条NOTE”。`||`从左到右判断，因此先排除null，后面才比较时间；时间相等符合条件，不能误写成必须大于。

Ctrl+S保存。**先看后端终端：若还在输出日志，按Ctrl+C，等输入提示符恢复。** 即使先前停过，只要中途又启动，就要再次停下；不能一边运行JAR一边用build覆盖它。在这个已停止后端的 `app` 终端依次执行：

```text
node tools/course.mjs build
node tools/course.mjs backend-db
```

只有第一条完成才执行第二条。build包含Java普通测试和前端构建，应无编译错误；`CloseRulesTest`中完整条件放行、逐项缺条件拒绝。普通测试可能跳过需要专用MySQL的用例，不能因此声称数据库回滚已验证。第二条应明确启动teacher-db、端口8091。若前端未运行，另一个 `app` 终端执行 `node tools/course.mjs frontend`。

若报错，先给网页AI发下面提示，再分条贴首条错误和保存后的 `OperationsService.java` 全文，不贴数据库配置：

```text
我只替换了C09并保存，build失败。请先定位下一条实际错误：是Java括号/
类型、CloseRulesTest规则失败，还是环境问题。只修C09必要内容，不删测试、
不改预期为全成功、不去掉事务或授权。请给完整块内替换代码和复查命令。
```

记录实际构建结果。页面若仍返回TODO_C09，先确认旧后端确已Ctrl+C停止、build成功、新进程用backend-db启动；只保存Java不会自动更新正在运行的JAR。

如果误在后端运行中构建，随后出现类加载错误、`ClassNotFound` 或CSRF请求500，先停止本人旧后端，再重新build；构建成功后才启动backend-db并重新登录。保留原错误，不删除依赖、改权限或反复点登录来掩盖启动顺序问题。其他500原因仍需按实际日志判断，不能一概归于这个情况。

## 第4步：管理员创建并分派一条真实本地事件

打开 `http://127.0.0.1:5178/#cases`。重启后端会使旧会话失效，需要重新登录。按第08段的方法，用本机 `admin` 账号登录；密码只在本机输入。

1. 点 **“事件工作台”**。在 **“本地场景演练”** 的“场景”下拉框选 **“温度巡查”**，点一次 **“触发本地演练”**，等返回后再继续。不要连点。
2. 右侧详情看 **“当前记录”**，复制实际ID到账本，把它称为E1；E1不是要输入程序的字符串。核对 `LOCAL_DEMO · 模拟事件`、**“演练源”**、版本和处置时间线。

## 第6步：专门证明“缺NOTE不能关闭”

按钮灰色只证明页面拦截，下面直接请求后端。另建一条E2，不改已经关闭的E1。全程用admin即可；管理员仍受关闭规则约束。

1. 触发另一条温度巡查，记E2实际ID；分派给A，填写开始说明并点 **“开始处理”**。管理员可处理该事件。
2. **故意不点“提交处理记录”**。点“恢复演练源”，再点“服务端核实恢复”，确认PASS。此时只缺NOTE，其余关闭条件应满足；“开始处理”那条不是NOTE。
3. 先把E2“当前记录”的完整ID保存到账本。按[第08段第5步](08-登录权限与失败排查.md)，在**5178应用标签**右键“检查”→Console，点底部 `>` 输入行；回[第05段第5步](05-后端空间与设备接口.md)复制完整 `courseWrite` 定义，粘贴后按Enter。输入 `typeof courseWrite` 应得到 `"function"`。再整段粘贴下方代码并按一次Enter；浏览器弹框中从账本粘贴E2实际ID，点“确定”，不输入字母E2。取消或留空应停止，不产生关闭请求。

```js
var id09 = prompt('粘贴本次缺NOTE事件的实际ID');
if (!id09) throw new Error('未填写ID，停止实验');
var path09 = '/api/campus/alarm-cases/' + encodeURIComponent(id09);
var before09 = await fetch(path09, {credentials:'same-origin'}).then(r=>r.json());
if (before09.code!==0) throw new Error('读取失败，停止实验');
var c09 = before09.data;
if (c09.state!=='IN_PROGRESS' || c09.sourceType!=='DEMO' || c09.sourceScope!=='LOCAL_DEMO' ||
    c09.sourceState!=='RECOVERED' || c09.sourceRawStatus!=='DEMO_RECOVERED' ||
    c09.sourceRecoveredAt===null || c09.sourceRecoveredAt<c09.occurredAt ||
    c09.sourceCheckOutcome!=='PASS' || c09.sourceVerifiedAt===null ||
    c09.sourceVerifiedAt<c09.sourceRecoveredAt || c09.timeline.some(x=>x.action==='NOTE')) {
  throw new Error('前提不符，请回到第6步核对');
}
var denied09 = await courseWrite(path09+'/close', 'POST', {
  disposition:'第09段反例：其余条件满足但缺NOTE', expectedVersion:before09.data.version
});
var after09 = await fetch(path09, {credentials:'same-origin'}).then(r=>r.json());
console.log({id:id09, status:denied09.status, message:denied09.message,
  readSucceeded:after09.code===0, unchanged:JSON.stringify(before09.data)===JSON.stringify(after09.data)});
```

预期 `409 / STATE_CONFLICT`，回读成功、详情完全不变；不是 `VERSION_CONFLICT`，也不是403。若其他条件不符，不能把结果归功于NOTE检查。页面仍提示“至少填写一条处理记录”。

展开输出对象，将 `id/status/message/readSucceeded/unchanged` 保存到账本；只有 `undefined` 不算结果。提示“前提不符”就核对本步前两项；函数未定义就补定义。刷新后函数与 `id09/before09` 等变量需要重新建立，不能只选代码末尾运行。结果不明先只读取同一ID，不重发关闭，也不把补了NOTE后的成功覆盖这次反例。

本步无代码修改。把脱敏输出写入账本，再发AI：

```text
我用admin对另一个IN_PROGRESS、已恢复、核实PASS且没有NOTE的事件请求关闭，
结论非空，版本取自刚读取的详情。下一条是实际结果。请判断是否只改变了
NOTE这一条件；若是403、VERSION_CONFLICT或前提不符，不算关闭门槛证明。
不要建议加入NOTE后把刚才失败改写成通过，也不要删requireClosable。
```
