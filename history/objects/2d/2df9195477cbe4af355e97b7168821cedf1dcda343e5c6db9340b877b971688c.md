# 第07课：看着页面，做出第一个后端

前六课已经有了一套能点击的网页。这节课让电脑上再运行一个 Java 程序，让网页可以向它提问。我们先让它回答“我已经启动”，下一课再让它读取设备。

本课4学时，共180分钟。五步建议用时：30、30、40、40、40分钟。

你继续打开自己的 `campus-lab`，不要新建另一套前端。今天还不需要 MySQL 和 Redis。屏幕上的设备仍来自练习文件，演练仍是浏览器演示。

## 第1步：对着九个菜单，说清楚要保存什么

**现在在哪：** CodeBuddy 打开 `campus-lab`。终端 A-页面仍在运行 `node tools/serve.mjs`；浏览器打开 `http://127.0.0.1:5188`。依次点击九个菜单，特别看看“演练事件”刷新前后有什么变化。

**发给 CodeBuddy：**

```text
请阅读当前 frontend、materials/约定卡.md和第06课的notes/06-前端需要的数据.md，
在已有整理上补齐我们已经做出的网页。
这一步只新建 docs/页面需要的数据.md，不修改页面，不生成后端。
按概览、设备、空间、能源、历史、原始报警、演练事件、设备责任、管理九个菜单写一张表：
1. 学生在页面上能看见或填写什么；
2. 现在从 mock-campus.json、内存还是 localStorage 取得；
3. 将来需要后端读取，还是需要保存修改；
4. 对应约定卡中的哪个接口。
再用生活中的例子解释：MySQL像长期保存记录的档案柜；
Redis在本课程只保存有过期时间的登录凭条。
不要把缓存、会话、数据库三个词当同一件事；不要声称已连接数据库。
最后列出本课只做 GET /api/health，其他接口留待后续课。
```

**等 AI 完成并保存：** 等它回复结束，打开新文件。请同伴指着“设备责任”说出“显示什么、修改什么、谁来保存”。看不懂的一行，当场让 AI 改成你能复述的话。

**亲自操作：** 打开第06课已经关闭的本地演练事件，核对它的处置记录和时间线，再刷新，确认仍能读到。回到表格找到该记录的存放位置。关闭的事件不能继续修改，本步只查看，不运行新的终端命令。

**应该看见：** 表格承认目前的演示数据来源。MySQL 一栏有设备、空间、读数、历史、报警、账号、责任、事件和审计；Redis 一栏只有短时登录。原始报警只查看，不能被当作本地事件关闭。

**没对上时，只发这段修复提示：**

```text
请只修订 docs/页面需要的数据.md。
我实际操作的页面是【菜单名】，操作后看到【结果】。
请重新对照当前代码写明它现在从哪里取数，不把计划中的后端写成已完成。
```

**下一步：** 你能说清“目前存在浏览器里的数据”和“以后要放进 MySQL 的记录”后，再检查 Java。

## 第2步：准备后端终端，确认它用的是 Java 17

**现在在哪：** 新建一个终端，命名为 **B-后端**。当前目录应为 `campus-lab`。A 继续运行，不在 A 中输入新命令。

**发给 CodeBuddy：**

```text
这一步只检查后端准备条件，不创建业务代码。
请检查当前工程有没有 materials/maven-wrapper，并告诉我里面哪些文件要复制到 backend。
在 docs/后端启动笔记.md 写明：Java使用17；JAVA_HOME指向JDK根目录；
PATH中的java也必须是17；A窗口跑页面，B窗口跑后端。
不要修改系统环境变量，不安装软件，不替我启动常驻服务。
如果缺少Java17，明确告诉我缺了什么，先不要继续生成后端。
```

**等 AI 完成并保存：** 等回复结束。它说“检查完毕”只代表回答完了，接下来还要由你执行下面的命令。

**亲自操作：** 在 B 中按自己的系统执行一组。

macOS，工作目录为 `campus-lab`：

```sh
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
export PATH="$JAVA_HOME/bin:$PATH"
java -version
node --version
pwd
```

Windows PowerShell，工作目录为 `campus-lab`；以下按课前安装的 Temurin 17 查找：

```powershell
$courseJdks = @(Get-ChildItem "C:\Program Files\Eclipse Adoptium" -Directory | Where-Object Name -Like "jdk-17*")
if ($courseJdks.Count -ne 1) { throw "请老师确认本机JDK17目录后再继续" }
$env:JAVA_HOME = $courseJdks[0].FullName
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
java -version
node --version
Get-Location
```

**应该看见：** Java 主版本是 `17`，Node 主版本是 `22`，当前目录最后一层是 `campus-lab`。若显示两个 JDK 安装目录，先请老师确认用哪个，不随意取第一个。以后新开后端终端，要在新窗口重新设置这两项环境变量。

**失败时，只发这段修复提示：**

```text
我还停在Java环境检查。操作系统是【Windows或macOS】；
java -version显示【版本】，当前目录最后一层是【目录名】。
请只帮助我让当前终端使用已安装的Java17，不改全局设置，不继续创建后端。
```

**下一步：** Java 17 和目录都确认后，生成最小后端。

## 第3步：让 AI 只做一个“启动成功”接口

**现在在哪：** CodeBuddy 仍打开 `campus-lab`。B 还没有后端进程。

**发给 CodeBuddy：**

```text
请在当前工程新建 backend，完成最小Java后端。
使用Java17、Spring Boot3.4.2、Maven，包名edu.campus.v2。
把 materials/maven-wrapper 中的Maven启动工具复制到backend，保留隐藏的.mvn目录。
只加入Spring Web和测试依赖，不加入MySQL、Redis，不复制任何完整教师业务代码。
服务只监听127.0.0.1:8098。
实现 GET /api/health，返回：
{"code":0,"message":"ok","data":{"status":"UP"}}
增加一个不需要数据库的接口测试，检查status确实为UP。
把启动类、控制器和application.properties的作用各用一句话写到docs/后端启动笔记.md。
你可以运行会结束的测试；不要替我启动spring-boot:run。
不要修改frontend，不实现其他接口。
```

**等 AI 完成并保存：** 等它回复完成，查看 `backend`。至少应有 `pom.xml`、`mvnw`、`mvnw.cmd`、`.mvn`、`src/main`、`src/test`。确认本步没有突然多出设备、登录、事件等完整业务。

**亲自操作：** B 先进入后端目录，再运行测试。

macOS，起始目录为 `campus-lab`：

```sh
cd backend
sh ./mvnw test
```

Windows PowerShell，起始目录为 `campus-lab`：

```powershell
Set-Location backend
.\mvnw.cmd test
```

**应该看见：** 首次可能下载依赖，下载完成后显示 `BUILD SUCCESS`；测试统计里至少有刚生成的健康接口测试。只有“没有测试可运行”不算这个检查完成。

**失败时，只发这段修复提示：**

```text
我在backend运行Maven测试失败。第一段错误是【复制相关错误，去掉本机隐私】。
请只修复本课的最小健康接口和对应测试，不加入数据库、不删除测试、不跳过测试。
修好后告诉我重新运行哪条已有命令，不启动常驻服务。
```

**下一步：** 测试通过后，让后端真正运行起来。

## 第4步：启动 B，再从网页地址读它的回答

**现在在哪：** B 的工作目录是 `campus-lab/backend`。A 保持运行。

**发给 CodeBuddy：**

```text
请核对tools/serve.mjs与刚完成的后端是否符合约定：
页面服务在127.0.0.1:5188；/api请求转发到127.0.0.1:8098，保留/api路径。
它只能公开frontend，不能公开项目根、backend或.env。
如果已经正确，不改文件；如果有遗漏，只修复这个转发。
不要启动页面或后端服务。告诉我本次是否修改了serve.mjs。
```

**等 AI 完成并保存：** 若它修改了 `serve.mjs`，仅在 A 按一次 Ctrl+C，然后在 A、`campus-lab` 根目录重新运行 `node tools/serve.mjs`。没有修改就保持 A 原样运行。

**亲自操作：** 在 B 启动后端。

macOS，工作目录为 `campus-lab/backend`：

```sh
sh ./mvnw spring-boot:run
```

Windows PowerShell，工作目录为 `campus-lab/backend`：

```powershell
.\mvnw.cmd spring-boot:run
```

看到启动日志后，在浏览器新标签打开 `http://127.0.0.1:5188/api/health`。

**应该看见：** 浏览器显示 `code` 为 `0`、`status` 为 `UP`。B 没有回到输入提示符是正常的：这个程序正在等网页请求，保持窗口开着。

**失败时，只发这段修复提示：**

```text
我已在B启动最小后端，浏览器访问5188端口的/api/health时看到【现象】。
B最后几行不含隐私的日志是【日志】。
请检查8098监听、/api路径与页面转发，只修复本步链路。
如果端口被占用，先报告，不结束未知进程。
```

**下一步：** 看到真实 `UP` 后，给网页加一个让普通人看得懂的连接状态。

## 第5步：在网页上看见后端在线，再亲手验证断开

**现在在哪：** 回到原来的校园网页标签。A、B 都保持运行。

**发给 CodeBuddy：**

```text
请在现有网页顶部增加一个小区域“后端连接”，带“检查连接”按钮。
在frontend/data-service.js增加checkHealth()，向同源/api/health发请求。
点击后先显示“正在检查”；code为0且data.status为UP才显示“后端已连接”；
请求失败则显示“暂时连不上后端”，不要显示成成功。
5秒没有响应就结束等待并提示重试。
保留现有九个菜单和全部浏览器演示功能；不把设备数据切到后端。
不要启动服务。只说明修改的文件和我要点击的按钮。
```

**等 AI 完成并保存：** 等回复结束，保存后刷新校园网页。HTML、CSS、JS 修改无需重启 B。

**亲自操作：**

1. 点击“检查连接”，看到“后端已连接”。
2. 只在 B 按 Ctrl+C，回到网页再次点击“检查连接”，看到连接失败提示。
3. 在 B、`backend` 目录重新执行本课第4步对应系统的启动命令。
4. 等启动日志出现，再点“检查连接”，应恢复成功。

**应该看见：** 页面能区分后端真的运行和停止。设备仍标为浏览器演示；后端在线还不代表已经有数据库。

**失败时，只发这段修复提示：**

```text
后端停止后，网页的连接提示仍是【实际显示】。
请只修复checkHealth和连接状态：每次点击都实际请求、清除上次结果、
失败明确提示、允许再次检查。不要修改设备模拟数据或其他页面。
```

**下一步：** 在 `docs/后端启动笔记.md` 写下你实际看到的三次结果。下课可分别在 A、B 按 Ctrl+C；下一课从已有工程继续，为设备增加长期保存的位置。
