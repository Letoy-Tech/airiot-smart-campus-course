# 第09课：用 Redis 记住短时登录

设备已经存在 MySQL 里。今天再加一件事：后端要知道“现在是谁在访问”。登录成功后，Redis 暂时保存登录凭条；设备和业务记录仍保存在 MySQL。

本课4学时，共180分钟。六步建议用时：25、30、40、35、30、20分钟。

继续使用原 `campus-lab`，保留第08课的 `.env`，不用再运行 `setup-env.mjs`。打开 Docker Desktop，等引擎运行，再按下面顺序恢复。

1. **C-工具，项目根：** 执行 `docker compose up -d mysql`，再执行 `docker compose ps`，等 MySQL 显示 `healthy`。Redis 还要在本课第1步生成配置，现在不要求它已存在。
2. **A-页面，项目根：** 若上次已停止，执行 `node tools/serve.mjs`，浏览器打开 `http://127.0.0.1:5188`；已有 A 在运行就继续用它。
3. **B-后端：** 若旧后端仍在运行，先在原 B 按 Ctrl+C。新 B 先按[第07课第2步](07-看着页面做第一个后端.md#第2步准备后端终端确认它用的是-java-17)设置本窗口的 Java 17 与已安装的 Node 22，分别运行 `java -version`、`node --version`。从项目根进入 `backend`：macOS 用 `cd backend`，Windows PowerShell 用 `Set-Location backend`；已经在该目录就不重复进入。暂时不启动 B，先完成本课修改。

## 第1步：启动只属于本课程的 Redis

**现在在哪：** CodeBuddy 打开项目根的 `compose.yaml`。C 的目录是 `campus-lab`，B 已停止。

**发给 CodeBuddy：**

```text
请在现有compose.yaml加入Redis7.4服务redis。
不设置固定container_name，容器名称由Compose按项目名生成。
项目名仍是campus-v2，只映射127.0.0.1:23502到容器6379；
密码引用.env里的REDIS_PASSWORD，不读取或输出真实值。
Redis在本课程只保存短时登录，明确关闭RDB与AOF持久化，
这样课程redis进程重新启动后登录凭条会消失。
增加使用本机配置检查可用性的healthcheck，检查日志不能打印口令。
不要声称变量占位会让普通compose config或docker inspect整体输出无口令；
环境变量仍可能被展开，结构检查不能输出配置值，也不能展示或分享含口令的结果。
保留原MySQL服务与命名卷不变。不要替我启动服务，不运行down -v。
```

**等 AI 完成并保存：** 看到新增 `redis` 服务，确认原 MySQL 配置没有被删除。

**亲自操作：** C、`campus-lab` 根目录，两种系统相同：

```text
docker compose up -d redis
docker compose ps
```

**应该看见：** MySQL、Redis 都运行，Redis 最终显示 `healthy`，本机端口分别是 `23501`、`23502`。Redis 还没有登录记录，因为登录接口尚未完成。

**失败时，只发这段修复提示：**

```text
课程Redis启动后docker compose ps显示【状态】，
不含口令的错误是【错误】。
请只检查Redis服务、23502端口和健康检查，不输出.env，不修改MySQL数据卷。
```

**下一步：** 两个服务都健康后，先在 MySQL 建立三个练习账号。

## 第2步：建立三个有不同职责的账号

**现在在哪：** B 保持停止，CodeBuddy 打开 `backend`。

**发给 CodeBuddy：**

```text
请给现有后端增加spring-security-crypto，用BCrypt保存密码摘要。
新增V2迁移建立users表，不改已执行的V1。
在本地课程启动时，若账号尚不存在，创建admin、manager、viewer，
角色依次为ADMIN、MANAGER、VIEWER，初始密码从DEMO_PASSWORD配置读取。
三个账号共用这份本地练习初始密码，只适用于本机课程。
只保存BCrypt摘要，不在SQL、日志、接口、回复中输出明文或摘要。
账号已存在时不重置密码；缺少配置要说明缺项，不能使用写死的默认密码。
先做账号建立和密码校验的测试，不做前端登录，不启动服务。
```

**等 AI 完成并保存：** 查看新增 `V2` 文件与账号初始化代码。它们应使用配置名，而不是出现你的真实口令。

**亲自操作：** B、`campus-lab/backend`，先测试，成功后启动。

| 系统 | 先测试 | 再启动 |
| --- | --- | --- |
| macOS | `sh ./mvnw test` | `sh ./mvnw spring-boot:run` |
| Windows PowerShell | `.\mvnw.cmd test` | `.\mvnw.cmd spring-boot:run` |

浏览器检查 `http://127.0.0.1:5188/api/health`；A 未启动时，在 A、项目根运行 `node tools/serve.mjs`。

**应该看见：** 后端正常启动，测试包含正确密码能通过、错误密码不能通过。日志可以说账号准备完成，但不会出现密码。本步还没有登录按钮可用。

**失败时，只发这段修复提示：**

```text
账号准备这一步失败，相关错误是【已去掉私密内容的错误】。
请只修复V2、配置读取或BCrypt校验，不重建数据库，不重置已有用户，
不要让我把.env或密码贴给你。
```

**下一步：** 停止 B 后生成登录接口，让账号真正获得短时登录凭条。

## 第3步：让后端签发和检查登录凭条

**现在在哪：** 在 B 按 Ctrl+C。MySQL 和 Redis 继续运行。

**发给 CodeBuddy：**

```text
请按materials/约定卡.md加入Spring Data Redis并完成登录接口。
Redis连接127.0.0.1:23502，密码使用REDIS_PASSWORD占位。
POST /api/login接收username/password，校验MySQL账号后，
使用数据库查到的规范username建立会话和返回用户，不把输入大小写当成另一个身份；
用安全随机数生成登录token，在Redis以campus:v2:session:前缀保存会话，
过期时间1800秒，返回token及user:{username,role}，不返回密码摘要。
GET /api/me读取Authorization: Bearer token并返回当前用户；
POST /api/logout删除当前会话。
除/api/health和/api/login外，/api下的请求都必须检查会话。
未登录或过期返回401；已登录但无权操作返回403；
Redis不可用返回清楚的503，不放行，也不伪造登录成功。
不要在请求日志打印密码、Authorization或token。
增加登录失败、缺令牌、失效令牌和退出后不能继续访问的测试；
若数据库忽略账号大小写，验证MANAGER登录后响应和会话都使用数据库中的manager身份。
不要修改前端，不启动服务。
```

**等 AI 完成并保存：** 阅读 AI 的接口说明，确认这次保护了上一课公开的设备接口。

**亲自操作：** B、`backend` 目录再次执行本课第2步对应系统的“测试→启动”。启动成功后，在浏览器新标签直接打开 `http://127.0.0.1:5188/api/devices`。

**应该看见：** 直接打开地址会收到“请先登录”或同义错误，浏览器网络面板中状态是 `401`。这是本步的正确结果。健康地址仍可读取；前端设备页要等下一步接上登录才恢复。

**失败时，只发这段修复提示：**

```text
加入登录检查后，直接访问/api/devices的实际结果是【结果】。
请只检查保护范围与会话校验：health/login公开，其余/api需要有效Redis会话。
不要把设备接口重新设为公开来消除错误。
```

**下一步：** 后端已经会认人，再把网页上的“角色演示”改成真实登录。

## 第4步：保留原页面，加上真正的登录与退出

**现在在哪：** A、B、两个容器都在运行。CodeBuddy 打开 `frontend`。

**发给 CodeBuddy：**

```text
请给现有页面增加登录表单：用户名、密码、登录按钮和可读错误。
页面顶部提供“数据方式”：浏览器演示、连接后端。
首次由学生选择“连接后端”，随后显示登录表单。
可以在localStorage保存这一个模式偏好，刷新后仍停在连接后端；
不能把模式偏好当作身份，也不能保存密码、token或用户角色来冒充登录。
登录调用POST /api/login，密码只用于本次请求；成功后清空密码输入框。
token只保存在data-service.js的内存变量，不能写localStorage/sessionStorage/URL；
后续真实API请求带Authorization: Bearer token。
登录成功后调用/api/me显示账号与角色，再重新读取设备。
增加退出按钮，调用/api/logout，随后清除内存token和已登录用户的页面数据。
刷新页面后需要重新登录，这是本课约定，不自动从浏览器恢复token。
“连接后端”模式移除能假装已登录的演示角色切换；
选择“浏览器演示”时仍须明确标注演示身份，不能与真实登录混用。
未接后端的功能仍标“浏览器演示”。
401回到登录并清除旧内容，403显示无权访问；不把失败写成成功。
保留九个菜单，不重做布局，不启动服务。
```

**等 AI 完成并保存：** 保存后刷新校园网页，在顶部“数据方式”选择 **“连接后端”**。这时应看见登录表单。以后整页刷新会保留“连接后端”的选择，但登录凭条已清空，所以仍要重新登录。

**亲自操作：**

1. 确认顶部数据方式是“连接后端”。在 CodeBuddy **本机编辑器**打开自己的 `.env`，找到 `DEMO_PASSWORD`，只在本机查看。
2. 浏览器输入用户名 `admin`，手动填入该密码并登录。不要把 `.env` 或密码发给 AI。
3. 点击“设备”，确认16台设备重新出现。
4. 点击退出，应回到登录。再登录一次，然后刷新整个网页，应再次要求登录。

**应该看见：** 登录区显示真实账号 `admin`、角色 `ADMIN`；设备页显示后端来源。刷新要求重登是设计好的流程，不是丢失了 MySQL 数据。

**失败时，只发这段修复提示：**

```text
我在登录页操作【登录/退出/刷新】后看到【现象】。
请检查同源/api请求、内存token、/api/me和401清理，
不要让我发送密码，不把token改存到localStorage，也不要绕过后端认证。
```

**下一步：** 用同一个登录表单切换三个账号，看看职责说明是否正确。

## 第5步：用三个账号核对“谁能做什么”

**现在在哪：** 浏览器保持运行。本步只核对登录身份与已完成的设备读取。空间、责任、事件的真实写入将在后面两课完成。

**发给 CodeBuddy：**

```text
请在管理菜单中增加一张易懂的职责表，并明确哪些动作尚待后续课接通：
ADMIN可登记空间/责任、建立演练、分派、模拟恢复，并可处理事件；
MANAGER只处理已经分派给自己的事件；
VIEWER只看资料。
职责说明使用/api/me实际返回的角色，不能相信浏览器自己传来的角色名。
本课三个账号都能读取设备；尚未实现的真实写入显示“下一课接通”或“浏览器演示”，
不显示成已经通过后端权限检查。不要新增其他业务接口，不启动服务。
```

**等 AI 完成并保存：** 刷新后重新登录。不要因为前端隐藏了按钮，就在记录里写“后端权限全部通过”。

**亲自操作：** 依次用 `admin`、`manager`、`viewer` 登录；每次先退出上一个账号。三个账号均使用本机课程初始密码。进入“管理”看职责，再进入“设备”看列表。

**应该看见：** 三次身份分别是 `ADMIN`、`MANAGER`、`VIEWER`，三个账号都能读设备。旧用户的用户名、错误或详情不会残留到下一个账号的页面。

**失败时，只发这段修复提示：**

```text
切换账号后，页面还残留【上一账号的内容】。
请只修复退出和重新登录时的状态清理，身份以/api/me为准，
不通过修改后台角色或放宽权限来解决。
```

**下一步：** 重启 Redis 一次，看见“短时登录”和“长期资料”的区别。

```text
MySQL使用独立命名卷，设备记录不随Redis重启而删除。
核对前端收到401会清除已登录内容、显示重新登录，而不是自动换回演示角色。
若代码已经正确，不修改业务；不要替我重启服务。
```

```text
以及401后页面是否清理。不要清空MySQL，不打印token。
```
