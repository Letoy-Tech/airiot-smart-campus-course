# 页面需要的数据（第11课末当前实现）

本文逐项对照已经做出来的九个菜单，只写当前代码的实际行为：页面实际调用哪个接口、MySQL 保存什么、Redis 保存什么、失败时怎么处理。早期课次的分析快照已经合并进本文，不再保留“后端只有两个接口”之类的旧说法。

## 一、三条数据来源，不要混着说

| 来源 | 本课程实际保存/提供什么 | 不保存什么 |
| --- | --- | --- |
| **本机 MySQL**（课程容器 `campus_course`，Flyway V1–V4） | 空间、设备、账号、点位、历史样本、原始报警、设备责任、演练事件与时间线、审计 | 登录令牌、页面筛选条件、演示身份 |
| **本机 Redis** | 只保存登录会话：`campus:v2:session:<token>` → `{username, role}`，TTL 1800 秒 | 设备、空间、责任、事件、审计等任何业务记录 |
| **公开练习数据** `materials/mock-campus.json` → `frontend/mock-data.js` | 浏览器演示模式下的设备、空间、点位、历史、报警；V1/V3 迁移初始化 MySQL 也来自这份样本 | 不写回、不落盘、不代替后端失败结果 |
| **浏览器 `localStorage`** | 只保存数据方式偏好 `campus-v2-data-mode`（`backend` / `demo`） | 不保存身份令牌，不保存空间、责任、事件、审计等业务数据 |

要点：

- 登录令牌只存在 `data-service.js` 的内存变量里；刷新页面即丢失，需要重新登录。身份只来自 `POST /api/login` 与 `GET /api/me` 的返回。
- `campus-v2-demo` 已不再读写。浏览器演示的空间位置、责任只在本次页面内存里，刷新回到公开练习数据；演练事件与审计在演示模式下不显示。
- 连接后端后，读取失败只显示错误，**不会静默改用 mock，也不会回退旧的 localStorage 审计**。
- 所有数据仍为 `TEACHING_MOCK`、`simulated=true`：不控制真实设备、不发外部通知、不连接 AIRIOT。

## 二、九个菜单逐项对照

| 菜单 | 连接后端时实际调用的接口 | 读取的 MySQL 内容 | 写入的 MySQL 内容 |
| --- | --- | --- | --- |
| 概览 dashboard | `GET /api/overview` | `devices`、`spaces`、`points`、`history_samples`、`alarms` | 无（只读） |
| 设备 devices | `GET /api/devices`、`GET /api/spaces`；打开详情再读 `GET /api/owners`、`GET /api/overview` | `devices`、`spaces`、`owners`、`points` | 无（只读） |
| 空间 spaces | `GET /api/spaces`、`GET /api/devices`；保存 `PUT /api/spaces/{id}` | `spaces`、`devices` | `spaces.building`、`spaces.floor`；同事务写一条 `audit`（`space.update`） |
| 能源 energy | `GET /api/overview`；每次“比较历史”再读一次同一接口 | `devices`、`points`、`history_samples` | 无（只读） |
| 历史 history | `GET /api/overview` | `devices`、`history_samples` | 无（只读） |
| 原始报警 alarms | `GET /api/overview` | `devices`、`alarms` | 无（只读，不提供确认/关闭/控制） |
| 演练事件 cases | `GET /api/cases`；创建 `POST /api/cases`；动作 `POST /api/cases/{id}/actions` | `cases`、`case_timeline`、`devices`、`owners`、`users` | `cases`（状态/处理人/版本/结论等）、`case_timeline`、`audit`（`case.create` / `case.*`），同一事务 |
| 设备责任 owners | `GET /api/owners`、`GET /api/devices`；保存 `PUT /api/owners/{deviceId}` | `owners`、`devices`、`users`（校验负责人账号） | `owners.username`、`owners.note`、`owners.version`、`owners.updated_at`；同事务写 `audit`（`owner.save`） |
| 管理 admin | `GET /api/integration`（三种角色）；`GET /api/audit`（仅 ADMIN） | 审计接口读 `audit`；接入状态是后端常量，不读表 | 无（只读） |

补充说明：

1. **概览、能源、历史、原始报警**都复用 `GET /api/overview` 这一份读数集合：概览算计数、能源看当前读数与比较曲线、历史看 `history`、报警看 `alarms`。四个页面都不写数据库。
2. **设备详情**不是单独接口：基本信息来自设备列表的 `GET /api/devices`，空间名称 `GET /api/spaces`，负责人 `GET /api/owners`，点位读数 `GET /api/overview`。每次打开详情都会重新读，避免显示修改前的旧副本。
3. **空间保存**：只提交 `{building, floor}`，管理员角色由后端会话判断；成功后前端再独立 `GET /api/spaces` 回读，刷新页面后仍以 MySQL 为准。浏览器演示只改内存，不写 localStorage。
4. **责任保存**：提交 `{username, note, expectedVersion}`，没有记录时版本为 0；成功后独立 `GET /api/owners` 回读。版本落后返回 409，前端只回读并让学生重新决定，不自动重发。浏览器演示同样只改内存。
5. **演练事件**：`POST /api/cases` 仅 ADMIN，请求体只接受 `deviceId` 与 `message`；六个动作中 `assign`、`recover` 仅 ADMIN，`start`、`note`、`verify`、`close` 要求 ADMIN 或本事件的 manager。每次动作都带 `expectedVersion`；409 后只回读，不自动重试。列表提供“重新读取事件”按钮，失败保留上次成功列表并标明。
6. **管理页**：接入状态固定为 `source=TEACHING_MOCK`、`simulated=true`、`controlEnabled=false`、`notificationsEnabled=false`，不伪造 AIRIOT；审计列表由 `audit` 表读出，仅 ADMIN 可读，浏览器演示不显示旧 localStorage 审计。
7. **账号口令**：`users` 表只保存 BCrypt 摘要，不保存明文；演示账号在启动时按需创建，已存在不重置。

## 三、登录与 Redis 的分工

| 接口 | 作用 | MySQL | Redis |
| --- | --- | --- | --- |
| `POST /api/login` | 校验用户名与口令，签发令牌 | 读 `users`（`username`、`password_hash`、`role`、`enabled`） | 写 `campus:v2:session:<token>` → `{username, role}`，TTL 1800 秒 |
| `GET /api/me` | 用当前令牌读身份 | 不读 | 读会话键；键不存在即 401 |
| `POST /api/logout` | 退出 | 不写 | 删除会话键 |

Redis 只负责“你现在是谁”的短期凭条：课程 Redis 关闭 RDB/AOF，重启后会话全部失效，但 MySQL 里的业务数据不受影响。页面不会把 Redis 说成数据库，也不会把业务数据写进 Redis。

## 四、接口与权限一览

| 接口 | 权限 | 说明 |
| --- | --- | --- |
| `GET /api/health` | 公开 | 只证明后端已启动，不读数据库 |
| `POST /api/login` | 公开 | 失败统一返回 401，不区分“用户不存在/口令错误” |
| `GET /api/me`、`POST /api/logout` | 需登录 | 身份与令牌来自会话 |
| `GET /api/devices` | 需登录 | 三种角色可读 |
| `GET /api/spaces` | 需登录 | 三种角色可读 |
| `PUT /api/spaces/{id}` | 仅 ADMIN | `{building,floor}` |
| `GET /api/owners` | 需登录 | 三种角色可读 |
| `PUT /api/owners/{deviceId}` | 仅 ADMIN | `{username,note,expectedVersion}`，409 表示版本落后 |
| `GET /api/overview` | 需登录 | `{spaces,devices,points,history,alarms}` |
| `GET /api/cases` | 需登录 | 三种角色可读 |
| `POST /api/cases` | 仅 ADMIN | `{deviceId,message}`；处理人取自 `owners` |
| `POST /api/cases/{id}/actions` | ADMIN 或 MANAGER | `assign/recover` 仅 ADMIN；其余动作限 ADMIN 或本事件 manager；VIEWER 403 |
| `GET /api/audit` | 仅 ADMIN | 审计列表；MANAGER/VIEWER 403 |
| `GET /api/integration` | 需登录 | 三种角色可读；返回教学模拟常量 |

约定：`/api` 下除 `/api/health` 与 `/api/login` 外都要 `Authorization: Bearer <token>`；角色一律以会话里的身份为准，不读请求体里的 `role`、`username` 冒充值。

## 五、失败时不做什么

- 不把失败说成成功：接口失败就显示错误，不拿 mock、旧 localStorage 或上一次读数冒充本次结果。
- 已有成功数据时保留并标“上次成功结果”；首次失败提供错误与重试。
- 401 清掉内存身份与受保护内容，回到登录；403 清掉无权查看的内容；409 只回读，由学生重新决定。
- 切换账号或数据方式后，较早发出的请求即使后返回也不会覆盖新页面；各页有会话代次与“最后一次请求”保护。
- 不提供设备控制、报警确认/关闭、外部通知等超出约定卡的写操作。
