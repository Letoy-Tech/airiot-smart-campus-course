# 第 12 章 构建交付变更与答辩

你把工程打成压缩包交给同学，对方解压后问：“哪个目录运行？数据库怎么准备？这个配置值从哪里来？为什么页面只能在你的电脑打开？”这些问题往往暴露出开发时没有写下来的条件。软件交付不仅是代码离开作者的电脑，还要让接手者在明确环境里重现相同的核心行为。

本章先记录含 C12 待完成块的起点 A，完成这一项小变更并形成通过本组检查的基线 B，再让同伴从干净目录复现 B，最后用个人答辩解释实现和证据。起点 A 的预期失败不是交付验收结果。完整课程仍是 48 学时，本章三个模块按 1＋2＋1 学时安排。公网发布、域名、真实 AIRIOT 账号和模型 API 都不是课程完成条件。

本章配套完整教学参考与逐章学生起点已经提供；正文图、JSON和版本账本仍为教学示意，不能充当实际结果。`lab_verified=false`保留课堂未实测状态；教师工程的本机验证与学生本人实验分别记录，物理Windows、真实课堂与真实AIRIOT不据此宣称通过。

## 进入条件与学习目标

应已拥有第 11 章按层级记录的测试与缺陷证据。真实 MySQL 并发或回滚仍未完成时，可以整理交付材料，但完整验收应保留缺口。教师须准备干净复现环境、冻结版本的依赖和工具说明、隔离数据库与种子、启动停止入口及交付检查模板；已确认学生自带Windows/macOS电脑、教师提供数据库；课程不需要Redis；完整业务已有独立MySQL测试入口，学校组库与物理Windows仍需开课前核对。

完成后，你应能说明源码、构建产物、运行实例和业务验收的区别，让同伴依据说明完成核心流程，分析一项小变更的影响并做回归，还能独立解释一次 AI 建议的取舍。交付清晰并非承诺没有缺陷，而是让接手者知道当前可用范围、证据和下一步。

## 模块一 记录起点、完成 C12 并形成基线 B（1 学时）

### 1.1 四个阶段不能互相替代

源码修改完成，只说明文件变了；构建成功，说明在某个环境中形成了产物；服务启动，说明某个实例在运行；业务验收，才说明选定流程符合规则。图 12-01 把四阶段及相应证据分开，防止“已经生成 dist”被写成“系统已经可用”。

可复现不必承诺构建文件逐字节永远一致；某些产物会嵌入构建时间等信息。基础要求是输入版本、依赖、配置和数据来源明确，别人能得到满足同一合同的行为。文件哈希可以识别“这一次交付的这份产物”，不能单独证明业务正确，也不能把两个不同时间的包哈希不同直接解释成缺陷。

### 1.2 用清单让隐含条件变得可见

教师参考工程根为 `resources/campus-ai-course/`，逐章学生副本为 `resources/student-chapters/chXX/`，下有 frontend、backend、docs、fixtures、evidence。下面是交付组织示例；docs下个人需求及evidence由学生按实际建立，其他目录对照现有副本。

```text
campus-ai-course/
  frontend/          # 源码、package.json、依赖锁文件
  backend/           # 源码、pom.xml、wrapper、迁移
  fixtures/          # 虚构教学数据与种子说明
  docs/              # 需求、接口、运行、变更、交接
  evidence/          # 脱敏的实际检查与缺陷记录
  README.md          # 从这里开始复现
```

运行说明应回答：适用的操作系统和工具版本、从哪里安装依赖、怎样确认独立数据库、怎样导入教学种子、怎样启动前后端、访问地址和端口、怎样停止本组进程、失败时看哪里。它不应要求接手者去翻聊天历史寻找一个遗漏的环境变量。

配置示例仅保留字段说明和占位符，真实教学口令通过教师规定的渠道提供。会话 token、API Key、受限账户文件、真实学生信息不进入交付。日志和截图也要审查，不能只检查源码。锁文件、数据库迁移和种子版本属于必要输入，不应与临时缓存一起被省略；运行生成目录和本机依赖不作为复现的唯一依据。

建议在交付说明中写下以下字段。尖括号是待填写项，不是范例成绩。

```text
源码标识：<实际提交标识；无 Git 时为文件清单与哈希>
依赖与资源版本：<实际锁文件、教师资源包和种子版本>
适用环境：<实际验证过的 OS、JDK、Node、MySQL 等>
数据来源：TEACHING_MOCK；对象 simulated=true
演练范围：DEMO/LOCAL_DEMO；远端控制与外部通知关闭
已验证：<分层列出日期、命令、结果与证据路径>
尚未验证或失败：<具体项目、影响、下一步>
接手入口：<运行说明、测试矩阵、已知问题文件>
```

### 1.3 构建命令要与实际资源对应

package scripts与Maven wrapper已随资源提供。下表在指定的学生工程目录执行，**不能在教材文稿目录执行**；当章局部任务未完成时先记录预期失败，不复制教师通过记录。无需购买模型 API，也不需要安装 AI 编码 CLI；这里的终端只是学生运行自己工程的普通开发终端。

| 执行目录 | 命令 | 所要检查的内容 |
| --- | --- | --- |
| frontend | `npm ci` | 按已冻结锁文件安装依赖 |
| frontend | `npm run type-check` | TypeScript 与组件类型 |
| frontend | `npm run test:unit -- --run` | 已编写的单元与组件用例 |
| frontend | `npm run build` | 生成前端生产产物 |
| backend | `./mvnw test` | Maven 配置中纳入的测试 |
| backend | `./mvnw package` | 构建后端包及其配置的检查 |

Windows 使用冻结环境说明中的 wrapper，如相应的 `mvnw.cmd`，路径与执行方式须实际验证。不能只把命令中的斜杠替换，就声称支持另一个系统。跨平台统一入口是学生工程根的`node tools/course.mjs check`和`build`；真实MySQL另由教师执行`node backend/tools/test-mysql.mjs test`，普通Maven测试不自动接数据库，不能写成并发回滚已通过。

保存执行目录、命令、开始结束时间、退出结果与产物位置。若构建含时间或版本信息，应同时记录。一次失败后修改代码，需要保留失败与修复记录，再记录新产物；不能把早期日志中的版本文字手工改成新版本。

### 1.4 用 C12 学习受控变更

本章固定变更为“事件列表按处置状态筛选，刷新后保留已选状态”。教师已提供页面、请求和 URL 校验；学生仅补 `frontend/src/domain/course.ts` 的 `STUDENT_TODO_C12`，不另加筛选需求，也不重写预置的请求隔离逻辑。先用起点 A 预测一个失败，再做最小改动。

先写一张变更单，明确用户问题、验收条件、影响文件和证据。现有列表合同已经支持 state，因此通常无需修改数据库。本例固定一项教学 UI 设计：URL 只持久化合法的 state，分页 skip 仅在当前页面会话中保存；任何 state 变化，包括切回“全部”，都先将 skip 置 0。刷新时恢复 state，但分页回到首页，URL 中遗留的 skip 不采用。这不改变后端分页接口。图 12-02 展示先分析后修改的路线。

![接收筛选需求后写验收条件，核对现有合同与影响范围，保存基线，再修改页面与测试；通过受影响检查和浏览器验证后更新交付说明，失败则保留证据继续修复。](../illustrations/ch12-02-controlled-change.png)

*图 12-02　小变更的影响分析与验证流程。教学示意，非运行证据。*

例子复用既有 state 参数；合同或数据库确需变化时，必须先更新对应约定和测试。

[可编辑图源：ch12-02-controlled-change.mmd](../figure-sources/ch12-02-controlled-change.mmd) · [SVG 版式源](../figure-sources/layouts/ch12-02-controlled-change.svg)

| 验收条件 | 对应实现与检查 |
| --- | --- |
| 从任意页改变 state | 先设 skip=0，再按新 state 请求；从后续页切到少量记录状态也能显示第一页 |
| 选择 IN_PROGRESS 只显示相应事件 | 请求使用既有 state；对照 API 结果与页面 |
| 刷新后仍选 IN_PROGRESS | 从经过校验的 URL 恢复 state，固定 skip=0 后请求；不恢复旧页码 |
| 选择“全部” | 不发送 state 筛选，同时 skip=0 |
| URL 含未知状态 | 提示并回到“全部”、skip=0；直接非法 API 请求仍被后端拒绝 |
| 请求失败或快速切换 | 不把旧结果标为新筛选成功；最终显示与当前选择一致 |

学生先在已有调用中指出路由查询、筛选组件、请求参数和相关测试，再只修改 C12。已有请求序号负责隔离晚到的旧响应；阅读并核验它，不把整套竞态机制列为本章新增实现。

本学时先做针对性单元/组件回归并预测以下浏览器结果；个人浏览器验证在模块二构建启动后执行，教师投影只记观察。可照做的小例子：教师课前按[第12章操作单的分页准备](../resources/campus-ai-course/docs/12-交付变更与答辩操作单.md#教师课前准备可执行的分页演示数据)在独立空白演示库准备14条事件：NEW 12条、ASSIGNED 2条、IN_PROGRESS 0条。页面每页10条；从“全部”的第二页切到 ASSIGNED，检查请求 skip=0 且显示2条；切到 IN_PROGRESS，确认成功空结果；切到 NEW 的第二页再刷新，保留 NEW 但回到 skip=0。三种分布覆盖跨页、少量与空结果，不把4条/limit=2的API规格误当本页夹具。

实现后执行类型检查、相关列表与参数测试，再在浏览器验证选择、分页重置、刷新、清除、快速切换和请求失败。后端授权及版本更新逻辑应保持原有规则；如果实际改动扩展到公共请求封装，还要相应增加回归范围。测试多少取决于影响，不因变更看起来小就完全不测，也不无条件重跑所有无关检查。

形成待交付基线 B：记录 C12 差异、针对性回归和遗留项；模块二在 B 上执行完整检查、构建和同伴复现，不能用 A 的截图证明 B。新报告链接旧报告作为历史依据，但每项当前结论要能指向对应的代码与执行时间。

## 模块二 交付复现与第一轮展示（2 学时）

### 2.1 让同伴从基线 B 的说明开始

前15分钟核对 B 的 README、锁文件和无秘密清单，执行 `node tools/course.mjs check` 与 `node tools/course.mjs build`，保存结果和源码标识，再打包。教师课前准备依赖缓存与独立库；若现场安装或构建超时，保留故障并登记补做，不删检查以追赶进度。起点 A 保留用于比较，不是已通过的救援版本。

接着30分钟，同伴只依据 B 的说明完成最小复现：

1. 在新的目录取交付包；记录复现者、操作系统和源码标识，不覆盖其他作业。
2. 按 README 检查工具和端口、安装锁定依赖，执行本副本初始化。教师提供独立教学库并执行约定迁移；目标不明时先停止，不沿用作者的密码文件。
3. 执行约定检查与构建并启动本组服务，记录命令、退出状态和失败原文。作者可以补说明，不能在背后代跑后只留下成功截图。
4. 核对来源标记及实际目录数量，复现 C12 的分页变化和刷新，再抽查一个事件或责任关键路径及对应角色拒绝。第09—11章的其余证据引用原记录；未重跑项目注明本次未重跑，不要求30分钟重做整套平台验收。
5. 按说明停止本人进程，提交复现问题单。作者修复后保留新版本和受影响检查，不能手工改旧日志中的版本。

完整目录应实际返回四空间、十六模拟设备、二十八采集点；若仅一空间两设备，先核对是否误用第04章 first-chain。`source=TEACHING_MOCK` 与 `simulated=true` 继续显示，真实 AIRIOT 不参与本次交付。分页演示数据由教师另行准备，不是原始设备夹具自带事件。

本模块最后45分钟安排前9组，每组5分钟展示与问答。未展示组按同一验收表记录观察，不能替代自己的个人回答。

### 2.2 回退代码和恢复数据是两件事（阅读与故障判断）

本次筛选变更不改 schema。起点 A 特意留有 C12 缺口，恢复 A 只能回到已知未完成状态，不能作为交付成功。若需救援，由教师提供已核验且兼容当前库的参考快照，并注明教师提供；学生仍须补交自己的差异与解释。任何旧版本与当前数据库的兼容性都须核对，不能凭“版本更旧”推定安全。图 12-03 将代码与数据两条路径分开，避免把删除数据库当成回退方法。

## 模块三 演示、个人答辩与复盘（1 学时）

### 3.1 用可解释的因果关系讲解作品

本模块前30分钟安排后6组，每组5分钟；最后15分钟每人完成退出题、标明未验证项并提交交接。与模块二合计覆盖15组，两位成员各解释一个判断；不能让伙伴代答全部问题。

小组演示可以协作，个人理解必须可区分。每位学生独立承担一段代码讲解或故障定位，说明一次请求如何从页面经过 API、服务校验、数据库事务再回到时间线。教师可以改变一个输入，让学生先预测结果，再指出实现位置；不以背诵文件名代替理解。

例如展示责任更新请求时，学生应解释 expectedVersion 来自刚读取的责任记录，为什么不接受事件版本；两请求竞争时，行锁如何协调、旧版本为什么冲突；失败后输入为何保留。展示关闭动作时，应解释来源恢复、独立核实、NOTE 与结论各自的作用，以及管理员为何仍不能绕过业务门槛。

演示失败时先保留证据，指出失败层次：未构建、进程未启动、接口不可达、授权拒绝还是业务规则不满足。现场不能为了完成演示临时删除权限或把失败响应改成成功。能准确解释失败和下一步，同样属于工程能力；但解释不能替代本来要求的实际验收。

### 3.2 让网页 AI 帮助查漏与准备解释

将当前版本、交付清单和实际结果分块贴入通义等网页工具，Qwen3 作为模型案例，不要求 API、CLI 或固定付费档位。发送前移除日志中的口令和令牌。以下提示把 AI 限定在影响分析和材料审查内。

```text
这是智慧校园教学项目的交付清单、合同和实际检查结果：[粘贴]。
本次变更为事件列表按状态筛选并在刷新后保留选择。
请先指出材料中的遗漏与矛盾，并分析页面、接口、测试和文档影响。
只使用既有合同，不增加公网部署、远端控制、通知或模型 API。
把源码修改、构建、运行、业务验收与未执行项分别描述。
再出三道需要结合实际代码回答的答辩题，先不给答案。
你无法访问本机，未看到我的实际证据时不得声称已验证。
```

学生先独立回答，再要求 AI 按合同指出逻辑缺口。例如 AI 建议“把所有异常都转为空数组以便演示”，应拒绝：空结果与读取失败语义不同，会掩盖服务不可用。个人记录包含原建议、自己的判断、实际修改与证据，不按提示词长度或生成代码量评分。没有遇到真实 AI 错误时使用教师缺陷样例，不伪造一段对话。

### 3.3 验收表与常见交付故障

| 检查项 | 可以支持结论的实际证据 | 本稿状态 |
| --- | --- | --- |
| 输入完整 | 源码标识、锁文件、迁移、种子及无秘密配置样例 | 待执行 |
| 构建 | 对应版本的命令、退出状态、产物与标识 | 待执行 |
| 复现 AC12 | 同伴在干净目录和独立库的操作记录及问题单 | 待执行 |

| 质量缺口 | 第 11 章并发、事件回滚、责任回滚的实际证据或阻塞说明 | 待执行 |
| 变更维护 | A/B 差异、影响分析、受影响回归与文档更新 | 待执行 |

“作者电脑能跑、同伴不能跑”，优先检查漏记的环境变量、锁文件、种子与工具版本。构建成功但页面打不开，分别查启动入口、访问地址、代理、静态资源 base 和路由，不直接重写业务逻辑。页面只有空数据，区分未导入种子、查询失败与真实空结果。验收报告比代码旧，按影响补做检查，不修改历史日期冒充新结果。停止脚本误伤其他组进程则属于范围错误，应修正专属进程识别，不以强制结束全部同名进程解决。

## 课后练习

1. 前端 dist 已生成，能否写“校园系统验收通过”？
2. 状态筛选复用既有 state 参数，为什么还需要影响分析？
3. 当前代码通过测试，但交付包漏了迁移脚本，会发生什么？
4. 回退到旧代码是否必然恢复旧数据？
5. 同伴只复现了 ADMIN 闭环，如何写结论？

进阶可在另行批准的隔离环境学习发布与恢复，或完成 AIRIOT 只读适配；不作为基础满分的付费或硬件门槛。个人复盘写一个误判、证据怎样改变判断、实际修复及下次会提前检查什么，比泛泛写“学会了团队合作”更有用。
