# 04 安装工具，亲手改两段代码，看到第一张设备表

前面 11 份设计文件在桌面 `campus-ai-lab/docs`。从这里开始，我们建立旁边的 `app` 文件夹，直到交付都使用它。不要每章复制一整套新工程。

本章完成后，你会在浏览器看到两台模拟设备，一台“在线”、一台“未知”。你亲手补的是“从响应取出设备”和“把状态翻译成中文”两处；登录、页面外壳、请求保护、服务器框架由教师提供。**这是有教师起点的项目实践，不要求初学者从零写认证和数据库框架。**

本章不需要数据库。第一次下载工具和依赖可能超过一节课，教师应课前组织环境准备。后面的截图是参考工程的作者演示，自己的电脑是否成功，要按步骤确认。

## 第一步：准备编辑器、Node、Java 和 Git

“编辑器”用来打开和保存代码，“终端”用来输入命令。Node 运行前端工具，Java 运行后端，Git 记录代码版本。你暂时只需装好它们，不必先学会所有原理。

### Windows 电脑

1. 点开始菜单→设置→系统→系统信息，查看“系统类型”。通常为 x64；ARM 电脑选择 ARM64，不要选 x86。
2. 打开 [VS Code 官方下载](https://code.visualstudio.com/download)，选择 Windows 对应安装包。下载完成后双击，按安装程序完成安装，再从开始菜单打开 Visual Studio Code。它是本地编辑器，不是浏览器中的 vscode.dev。
3. 打开 [Node 22.21.1 官方归档](https://nodejs.org/en/download/archive/v22.21.1)，在 Installer Packages 中选对应 `x64.msi` 或 `arm64.msi`。双击下载文件，按安装程序安装；保持加入 PATH 的选项。PATH 可以理解为“终端在哪里找程序”。
4. 打开 [Temurin JDK 官方下载](https://adoptium.net/temurin/releases/?version=17)，选版本 17、Windows、你的架构、JDK、MSI。安装时启用添加 PATH 和设置 JAVA_HOME 的选项（如安装器提供）。记下安装目录，后面还会检查。
5. 打开 [Git 官方安装入口](https://git-scm.com/downloads/)，进入 Windows 下载，安装对应版本；命令行集成使用安装器推荐选项。课堂使用本地 Git，不要求注册 GitHub。
6. 安装完成后，关闭再重新打开 VS Code，让它读到新的环境变量。

### macOS 电脑

1. 点左上角苹果菜单→关于本机，查看“芯片/处理器”。Apple 芯片选 ARM64/aarch64；Intel 选 x64。
2. 从 [VS Code 官方下载](https://code.visualstudio.com/download) 下载 Mac Universal，解压后把 Visual Studio Code 拖入“应用程序”，再打开。
3. 从 [Node 22.21.1 官方归档](https://nodejs.org/en/download/archive/v22.21.1) 下载 `node-v22.21.1.pkg`，双击并完成安装。
4. 从 [Temurin JDK 官方下载](https://adoptium.net/temurin/releases/?version=17) 选择 17、macOS、对应架构、JDK、PKG，双击完成安装。
5. 打开“终端”输入 `git --version`。若系统提示安装命令行开发工具，按系统提示完成，再重新运行；已显示版本则不用重复安装。其他安装方式见 [Git 官方入口](https://git-scm.com/downloads/)。

上面是官方入口与本课冻结版本，核对日期 2026-10-19；网页排版可能变化。本课使用 Node 22.21.1 和 JDK 17，先不要跟随网页推荐改成其他大版本。

**预期：**电脑上能打开 VS Code。还没打开项目、没运行程序是正常的。

**遇到下载失败：**先把失败网址和浏览器显示的错误告诉教师，请教师提供核对来源和版本的安装包；不要让 AI 给你随机下载站、修改系统安全策略。可以向 AI 发：

```text
我在准备智慧校园课堂工程，需要本地VS Code、Node22.21.1、JDK17和Git。
我会下一条贴系统类型、失败的官方网址和错误文字，不含账号密码。
请先只判断问题发生在下载、安装还是版本识别，给一个最小排查动作。
不要推荐不明下载站，不要让我删现有项目、关闭安全保护或升级项目依赖。
```

## 第二步：把教学起点复制成自己的 app

1. 先解压本教学包。Windows 对 ZIP 右键→“全部解压”；macOS 双击 ZIP。**不要直接在 ZIP 预览窗口里编辑。**
2. 打开解压后的 `AI编程_智慧校园_48学时`，再打开 `resources`，找到 `student-project` 文件夹。
3. 复制整个 `student-project`，粘贴到桌面 `campus-ai-lab`，把副本重命名为 `app`。Windows 选中副本按 F2；macOS 选中按 Return。若已存在自己的 `app`，继续使用它，不覆盖。
4. 双击 `app`，应看到 `backend`、`frontend`、`fixtures`、`tools`、`docs`、`evidence`、`package.json`。如果只看到另一个 `student-project` 文件夹，说明多套了一层，请把真正含这些文件的目录作为 app。
5. 在 VS Code 菜单点“File/文件”→“Open Folder/打开文件夹”，选桌面 `campus-ai-lab/app`。如出现工作区信任提示，确认这是教师发放的本地课程副本后再信任。

```tree
桌面/campus-ai-lab/
├── docs/                  前面11份需求设计文件
└── app/                   从现在起一直编辑这一份
    ├── backend/           Java后端
    ├── frontend/          Vue前端
    ├── tools/             课程命令
    ├── docs/              工程说明与测试断言
    └── evidence/          你本人的运行记录
```

**预期：**VS Code 左侧文件树顶层是 `APP`，里面直接有 `frontend` 和 `backend`。此时不选择 `system` 或 `campus-ai-course`，那不是你的作业目录。

**找不到文件：**不要新建一堆同名空文件。返回解压目录，检查是否复制了完整 `resources/student-project`。给 AI 发：

```text
我正在打开教师发放的student-project副本，目标是桌面campus-ai-lab/app。
我下一条只贴VS Code左侧顶层目录名与其下一层文件名，不贴.private内容。
预期直接看到backend、frontend、tools、fixtures和package.json。
请判断我是否多套一层文件夹，并只告诉我应在“打开文件夹”中选哪一层。
不要让我创建缺失源码或从头生成工程。
```

## 第三步：在正确位置打开终端，逐行检查工具

1. 在 VS Code 顶部选“Terminal/终端”→“New Terminal/新建终端”。下方出现输入区域。Windows 选择 PowerShell；macOS 通常是 zsh。
2. 每次只复制下面**一行**，在终端粘贴后按 Enter，等这一行结束再执行下一行。不要复制代码框的语言名称或反引号。

```sh
node --version
java -version
git --version
node -p "process.cwd()"
```

**预期：**Node 为 `v22.21.1`；Java 第一行含 `17`（小版本可不同）；Git 有版本号；最后一行的目录以 `campus-ai-lab/app` 或 Windows 的 `campus-ai-lab\app` 结尾。Java 的版本文字有时显示在错误输出通道，但仅打印版本不是启动失败。

路径不对时，关闭当前终端，用“打开文件夹”重新选 `app`，再新建终端。命令找不到时，先彻底退出并重新打开 VS Code，再重试；仍失败把对应一条错误交给教师，不要改代码。

### 让后端找到同一个 JDK 17

macOS 在当前终端执行：

```sh
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
```

Windows 如果安装器已设置好，可以先执行 `$env:JAVA_HOME` 查看。若为空，按本课默认 Temurin 安装位置执行以下三行：

```powershell
$courseJdk = Get-ChildItem "C:\Program Files\Eclipse Adoptium" -Directory | Where-Object Name -Like "jdk-17*" | Select-Object -First 1
if (-not $courseJdk) { throw "没有找到默认位置的JDK17，请教师确认安装目录" }
$env:JAVA_HOME = $courseJdk.FullName
```

这些命令只设置当前终端。若你改过安装位置，请在资源管理器中打开该 JDK 文件夹，复制地址栏中那个**直接包含 bin 的文件夹路径**；在终端输入 `$env:JAVA_HOME = "`，粘贴该路径，再输入末尾的 `"`，按 Enter。不要把 `bin` 或 `java.exe` 当成 JAVA_HOME。

然后在 Windows/macOS 都执行：

```sh
node tools/course.mjs doctor
```

预期包含“文件与两个端口检查通过”。如果 8091 或 5178 已占用，先看是否自己的上一次终端仍在运行，回那个终端按 Ctrl+C。不要结束不认识的进程。已经启动服务器时不要再用 doctor 判断业务是否正常，因为它要求端口空闲。

### 给 AI 的环境排查提示

```text
我在campus-ai-lab/app工程根执行doctor，要求Node22（至少22.12）、JDK17、JAVA_HOME，端口8091/5178。
我下一条贴node版本、java版本、当前目录、doctor错误原文，不含私人配置。
请先指出哪一个前提不满足，再只给一条适合我当前系统的排查命令。
不能改业务代码、绕过版本检查、杀未知进程或连接学校生产库。
执行结果由我再贴给你，你不要声称已经修好。
```

## 第四步：装依赖、生成本地账号、记录起点

在 `app` 的终端逐行执行：

```sh
npm --prefix frontend ci
node tools/course.mjs init
node tools/chapter.mjs prepare 04
```

Windows 如果第一行提示 `npm.ps1` 无法运行，改用 `npm.cmd --prefix frontend ci`，不必修改全局执行策略。`ci` 按锁文件安装依赖，第一次需要联网。停在下载时先等命令结束；如果出现 `npm ERR`，保留最后一段错误，不改用随机升级命令。

`init` 预期显示已生成 `.private/accounts.json` 或“已存在，保留原内容”。该文件里的四个账号密码是你的本机秘密，之后只在本机查看和登录，不能粘给网页 AI。`prepare 04` 显示 A/B 已是起点或已准备，**不是测试通过**。同时生成的 `.lesson-state.json` 只记录已准备的章节，不含密码；保留它并一起提交，工具才能在重复准备同一章时保留你的代码。

在 VS Code 左侧打开 `.gitignore`，确认排除 `.private`、`.runtime`、`node_modules`、`target`、`dist`、`.lesson-backups`。本课 Git 不上传到网络。在终端先执行：

```sh
git rev-parse --show-toplevel
```

新副本提示 `not a git repository` 是正常现象。若输出正是 app，沿用已有仓库；若输出父目录，先请教师检查，不在父仓库里乱提交。新副本再执行：

```sh
git init
git config --local user.name "Student01"
git config --local user.email "student01@example.invalid"
git add -- .gitignore .nvmrc .lesson-state.json package.json README.md backend frontend fixtures tools docs evidence
git diff --cached --name-only
```

核对列出的文件没有 `.private`、密码、依赖或日志后执行：

```sh
git commit -m "chore: record teacher-provided starting point"
```

这里的姓名邮箱是课堂本地示例，可换自己的教学代号。这次提交的含义是“记录教师起点”，不能当作本人已完成平台。

如果安装、初始化或提交停住，先保留终端错误；在同一 AI 会话发下面提示，再贴运行目录、失败命令及第一段错误。不要贴账号文件。

```text
我在桌面campus-ai-lab/app完成第04章起点准备。接下来提供实际目录、失败
命令及第一段无秘密错误。请先判断是依赖下载、初始化还是Git问题，每次只
给一个核对动作。不要升级依赖、删除锁文件、重建账号、清理仓库或绕过防护。
暂存清单若含.private或密码，先让我停止提交，不把“已生成”说成测试通过。
```

## 第五步：把两个真实源文件交给 AI

先不要让 AI 生成整个项目。我们只改两个小函数。

![编辑源文件到保存并运行的操作链：快速打开文件、复制上下文、只替换标记内部、保存、运行针对性测试](figures/10-编辑到验证.svg)

图 04-1：网页 AI 只负责给建议，VS Code 中的保存和终端中的执行由你完成。

1. 在 VS Code 按 Windows `Ctrl+P` / macOS `Command+P`，输入 `frontend/src/api/campus.ts`，按 Enter。
2. 点击代码文字区域，按全选、复制快捷键。**这一步只复制这个 `.ts` 源文件，不是整个工程，更不是 `.private`。**
3. 切到 AI 网页，在项目对话先发下面的提示，再把刚才复制的文件全文作为下一条消息发送。

```text
我们进入智慧校园项目第04步。我会下一条提供frontend/src/api/campus.ts全文。
请先阅读，暂时不要改。这个文件中STUDENT_TODO_A_BEGIN到STUDENT_TODO_A_END之间是任务A。
目标：extractFirstRead先判断业务code，非0抛ApiError；等于0时返回同一响应的items和observedAt。
validateDeviceResponse已由教师检查数据形状，不要删除它；不重写请求封装和认证。
收到文件后先解释这个函数的输入和输出，等我说“给任务A代码”再输出。
```

4. 回 VS Code，用快速打开输入 `frontend/src/views/FirstDeviceRead.vue`。复制全文，先向 AI 发“下面是任务 B 的 FirstDeviceRead.vue 全文，请先阅读”，再发送文件内容。
5. 不认识输入输出也没关系，要求 AI 把下面规则解释一遍：设备响应中的 `online` 可以是 `true`、`false`、`null`，分别显示在线、离线、未知。未知不是离线。

**预期：**AI 能指出 A 是响应解包，B 是状态文字。若它没有收到文件，却声称看过本地磁盘，发：

```text
网页不能读取我的本机目录。只使用我刚贴出的两份文件，请指出各自的TODO开始与结束标记。
如果没有收到全文就明确告诉我缺哪一份，不要猜行号、字段或自行生成新工程。
```

## 第六步：改任务 A，保存，再改任务 B

### A：响应成功才取出设备

发给 AI：

```text
给任务A代码。只输出替换frontend/src/api/campus.ts中
STUDENT_TODO_A_BEGIN和STUDENT_TODO_A_END两行之间的代码，不包含标记行、不改函数签名。
response.code !== 0时抛new ApiError，保留HTTP200和实际业务code；否则返回
{ items: response.data.items, observedAt: response.data.observedAt }。
不补造列表、时间或默认成功，不改其他函数。代码后用两句说明正常和失败输入。
```

合格的代码示例是：

```typescript
  if (response.code !== 0) throw new ApiError('设备读取未成功，请核对业务响应。', 200, response.code)
  return { items: response.data.items, observedAt: response.data.observedAt }
```

回到 `campus.ts`，按查找快捷键（Windows `Ctrl+F` / macOS `Command+F`），搜索 `STUDENT_TODO_A_BEGIN`。找到后按 Esc 关闭搜索框。

**只选中 BEGIN 下一行至 END 上一行**，当前应该是抛出 `TODO-A` 错误的一行。用 AI 给出的两行替换。保留 BEGIN、END 两行、外面的函数大括号和 import。按 Windows `Ctrl+S` / macOS `Command+S` 保存，文件标签的小圆点消失表示保存完成。

### B：把三个值分别变成中文

发给 AI：

```text
现在只给任务B代码，替换FirstDeviceRead.vue中STUDENT_TODO_B_BEGIN与END之间。
value严格等于true返回“在线”，严格等于false返回“离线”，等于null返回“未知”。
其余非法输入抛ApiError，沿用文件已有import。不能用value ? '在线' : '离线'，
不能用String(value)猜结果，不改template和其他脚本。只给标记内部代码，再解释null分支。
```

合格示例：

```typescript
  if (value === true) return '在线'
  if (value === false) return '离线'
  if (value === null) return '未知'
  throw new ApiError('online 不符合 boolean | null 合同。')
```

按同样方法打开 `FirstDeviceRead.vue`，搜索 B 的 BEGIN，仅替换标记内部原来的 `void value` 和返回“待完成”两行，保存。

**如果粘贴后整片变红：**先看是否把三个反引号也粘了进去，或删掉函数大括号。立刻撤销一次（Ctrl+Z / Command+Z），重新按边界替换。不要全选整个 `.vue` 文件后只粘四行函数体。

## 第七步：先用测试查两段代码，再构建

“测试”就是程序自动给函数喂几个输入，再核对输出。它不能替你确认真实课堂电脑、数据库或硬件。

在 `app` 终端运行：

```sh
npm --prefix frontend run test:unit -- --run src/tests/http.test.ts src/tests/first-device-view.test.ts
npm --prefix frontend run type-check
```

Windows 有脚本策略限制时将开头 `npm` 改为 `npm.cmd`。第一个命令结束后应该显示指定文件的用例通过，不应有红色 FAIL；第二个命令结束且没有类型错误。相关用例包括“200 与非零业务码仍是失败”“成功空数组仍保留后端观察时间”“非法字符串不能冒充 Boolean 或合法未知”。不要死记总数，读失败用例的名字。

若失败，先复制**失败用例名称、Expected/Received 和报错行**，不复制账号配置。然后发送：

```text
我只修改了任务A/B，接下来分两条贴修改后的函数和真实失败输出。
请先把失败用例翻译成白话，再指出输入、预期与我的实际输出哪个不同。
只修改对应标记内部；不要删测试、改断言预期、关闭类型检查或返回硬编码通过。
给出完整替换块和需要重跑的同一个命令。没有实际运行就不能写“已通过”。
```

示例：`null` 的预期是“未知”，实际“离线”，说明把 null 合并进了 false 分支；补上严格判断后，再跑上面同一个命令。**示例不等于你已经失败或通过。**

两项通过后执行：

```sh
node tools/course.mjs build
```

预期 Java 出现 `BUILD SUCCESS`，前端构建完成，生成 `backend/target/campus-ai-course-0.1.0.jar` 和 `frontend/dist`。下载失败先修依赖/网络；Java 测试失败先读失败名。不要删测试来凑构建成功。

## 第八步：开两个终端，登录并看真实结果

### 第一次打开 Network 看响应

在 Chrome/Edge 的网页空白处右键→“检查/Inspect”，开发者工具上方点“Network/网络”（看不到可点 `»`）。在筛选框输入 `devices`，然后回页面点“重新读取”。点新出现的 `devices` 行，打开“Response/响应”标签。找 `code: 0`、`data.items` 两项和 `observedAt`。

## 第九步：亲手制造一次读取失败，再恢复
