# V1.1.0 完整手把手教程与交付验收

本轮针对“内容空洞、缺少操作和案例”的反馈，补完第04—12篇，与第00—03篇连成一条连续主线。学生从构思与设计进入同一份app，逐步补代码、定位故障、测试、写运行说明并生成源码交付目录。

## 交付内容

- 00—12共13篇手把手讲义；后9篇共59个主步骤，包含具体操作、可复制AI提示、预期结果及错误处理。提示可用于本步正常协作或遇错追问，不要求每次新开会话。

- 连续学生起点 resources/student-project，只复制一次；每章只准备当前局部任务，已开始章节不会重新挖空。新手主线不再逐章切换整套工程。
- 源码交付工具，排除私人配置、依赖、构建与运行资料，保留设计文件、学习记录和章节状态；人工核对后由学生压缩，不执行发布。
- 新增12次课授课衔接。已有正式Word/PDF教案保留，没有逐字改写为新操作讲义；课堂具体操作以新主线为准。

## 三轮互审修正的卡点

1. 切换数据库配置后必须停止旧后端、重启并重新登录；配置文件不会让运行中的服务自动换库。
2. 新开终端要设置该终端的JAVA_HOME，不能假设另一个终端的设置会传过来。
3. 新建校区后在“新建楼栋→所属校区”下拉核对；没有独立校区列表，不重复创建来凑映射行。
4. 第11篇明确“成功HTTP”和“成功业务码”之后仍可能出现前端判断故障，记录实际失败而不是只展示绿色测试。
5. 第12篇分页数据前提是独立14条演示库，未就绪记环境阻塞，不清空前章作品凑数量。
6. 复制按钮区分命令、源码、提示和示例；代码仍由学生在指定文件保存，不将AI回答下载成同名源码覆盖工程。

## 验证边界

网页AI提示与回答样例由作者编写；没有登录千问实际逐条执行所有提示。未进行Windows实机试跑、真实学生独立跟做、学校数据库连通测试或48学时课堂计时。教师需按授课衔接先试教；不能把作者PASS记录写成学生个人完成。

新增文件为V1.1.0。V1.0.2及更早ZIP不覆盖，旧证据对应当时版本。历史Markdown里的原系统源码路径是作者来源线索，不是学生运行所需文件；新主线的工程和合同均在本包内。
