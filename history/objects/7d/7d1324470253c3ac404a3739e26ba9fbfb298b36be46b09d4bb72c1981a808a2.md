# 第08章 · 权限撤销与竞态操作单

4学时，模块按1＋2＋1；建议45＋90＋45分钟。每章只补`C08`一个业务块，其他实现由教师提供；UI允许自主调整。

## 进入本章与共同命令

使用教师发放的 `student-chapters/ch08/` 独立目录，保留上一章作品，不覆盖历史。每章起点只留当前任务块，其他章实现由教师预置；不得把预置代码写成本人从零实现。课前按[启动说明](01-跨平台启动.md)核对Node22.21.1、JDK17、JAVA_HOME与锁文件；第05章起采用教师分组MySQL，按[数据库交接单](02-教师数据库交接单.md)落实本组配置和迁移，密码不进入网页AI或Git。

以下命令在当前章节工程根目录执行，Windows/macOS相同。前端依赖尚未安装时先运行`npm --prefix frontend ci`（PowerShell可用`npm.cmd`）。

```text
node tools/course.mjs doctor
node tools/course.mjs init
```

未补块前需要的页面/响应观察使用教师投影或脱敏样例，个人实际记录在补块后重做。先阅读模块一并填写预测，按模块二补本章代码块；然后执行`node tools/course.mjs build`。build会运行Java普通测试，C07起点质量测试失败是未完成任务的信号，不能删测试。C11无代码块，可直接build。教师显式执行本组授权迁移后，在两个终端分别启动`node tools/course.mjs backend-db`与`node tools/course.mjs frontend`；浏览器进入`http://127.0.0.1:5178/#locations`。后端first-chain入口只供第04章，不能用它的501或两设备结果验收本章完整业务。不要重复启动占用8091/5178的进程。

每份新副本必须init；登录使用该副本本机生成的密码，组数据库仍保存角色/启用状态。不要混用上章密码或为修登录删除旧库身份。修改Java后停止本组后端、重新build并启动；修改前端通常由Vite更新，但失败快照实验保持页面不刷新、不靠热更新造故障。未补本章任务时，对应检查失败属于起点；填好后运行：

```text
node tools/course.mjs check
```

`check`包含的普通测试不自动等于MySQL集成通过；数据库实际检查另按第11章执行。真实结果填写本章任务单，文中“预期”不当作已发生的记录。

### 模块一：角色与对象分开（1学时）

1. 画四身份三角色：ADMIN、MANAGER A、MANAGER B、VIEWER；A/B不是两个角色。读取均可，空间与责任等管理写仅ADMIN。
2. 先预测`true`、`false`、`null`、`"true"`、`"false"`、1的能力结果。只有第一项授予入口；字符串非空不能当Boolean true。
3. 说明“能处理事件”还要核对当前assignee；本章以空间管理验证角色，第09章再用真实事件验证本人范围。

### 模块二：补严格映射，执行拒绝（2学时）

4. 在course.ts找C08，保留输入类型，只写严格判断。前端入口受能力影响，后端仍对每次请求判断当前角色，不能以隐藏按钮代替授权。
5. 先以VIEWER读取devices和locations，预期200；在该身份自身合法会话中提交格式正确的校园创建请求，预期403。再ADMIN提交正常对照。不要把缺少CSRF的403误当角色授权证据；使用[第05章本地请求小工具](05-空间关系保存操作单.md#本地直接请求小工具拒绝实验)，先在VIEWER会话发合法校园创建，再换ADMIN正常对照；工具仅输出业务响应，不能输出会话凭据。
6. 教师确认仅本组schema并在私密database.json显式开启`allowAccountAdministration:true`，先记录原角色集合。在工程根执行`node backend/tools/account-admin.mjs admin --roles CAMPUS_VIEWER`，沿原ADMIN会话验证读取200、管理写403；随后执行`node backend/tools/account-admin.mjs admin --roles ADMIN,CAMPUS_VIEWER`恢复本课程初始集合。若课前改过集合，恢复实际原值。账户禁用另测：`node backend/tools/account-admin.mjs manager-a --enabled false`，结束用同命令`true`恢复；不能用禁用代替撤权。工具不操作学校账号，不开放HTTP改角色入口。
7. 阅读并运行可控竞态测试：截留旧管理员响应→切到VIEWER→先接收VIEWER→释放旧响应，管理能力不得回来；同一身份两请求先发者后返回，最后界面保留后发请求。成功、失败、finally均须核对epoch与序号，取消只是辅助手段。
8. 日志只保留逻辑身份、请求次序、状态码和业务数据，不复制Cookie、CSRF值或密码。测试工具的可控门闩不是公开业务接口；浏览器若无故障入口，就使用自动化测试证据，不假称手工点过。

### 模块三：证据层级与接力（1学时）

9. 分开记录按钮可见、直接请求403、数据前后不变三种证据；字段校验失败与权限失败分开。
10. 完成check并把当前角色路径、C08差异、两类竞态结果及本人范围待执行表交给第09章。先完成角色与过时响应两项，不扩展通用账户后台。

## 验收与停点

| 验收 | 可见依据 |
| --- | --- |
| AC05授权 | VIEWER合法请求403、ADMIN同条件成功；CSRF前提明确 |
| AC05当前资格 | 专用撤权夹具保留读取资格，恢复步骤与结果单列 |
| AC11竞态 | 跨身份和同身份次序可控，旧成功/失败/finally不写回 |
| 学生贡献 | C08严格比较与每人一个反例；安全底层标注教师预置 |

常见故障：所有写都403先分清CSRF与角色；切换后旧数据出现查epoch/序号；仅截图按钮不能判数据未写。实际撤权须采用隔离测试入口，不开公开调试后门。
