可操作材料

Windows/macOS 共用启动路径

先在教师参考目录跑通，再生成学生工作目录。以下命令均从当前拷贝的工程根目录执行：教师用campus-ai-course/，学生用自己的student-workspace/，不要切回教师参考目录，路径带空格时用双引号。Windows用PowerShell，macOS用终端。不要在原平台system/执行本页命令。

一次性准备

安装Node22和JDK17；本资源验证基线为Node22.21.1。需要Git。Maven由项目wrapper下载固定版本，不必额外安装全局Maven。第一次安装依赖需要网络；完整离线机房须由教师另行准备并验证依赖缓存，本资料包不捆绑JDK、Node或node_modules。

node --version
java -version
git --version
node tools/course.mjs doctor

doctor检查Node22、JDK17、文件和8091/5178两个端口；不检查教师数据库，也不证明全部实验可运行。运行前必须设置JAVA_HOME到JDK17根目录，让doctor与Maven Wrapper使用同一JDK；不要设成bin目录。Windows PowerShell示例：$env:JAVA_HOME = "C:\你的JDK17根目录"；macOS示例：export JAVA_HOME="/你的JDK17根目录"。替换为自己的已安装路径，两个启动终端都应设置。示例只修改当前终端环境。

若在Windows PowerShell中npm脚本受策略限制，使用npm.cmd。本项目的node tools/course.mjs ...内部会选择对应平台入口，无需修改全局脚本执行策略。

在根目录安装前端依赖并构建：

npm --prefix frontend ci
node tools/course.mjs init
node tools/course.mjs build

Windows可将第一行替换为npm.cmd --prefix frontend ci。init为admin、manager-a、manager-b、viewer生成不同随机密码，仅写入.private/accounts.json；用本机编辑器查看。重复执行保留原密码，不打印密码。不要将该文件粘贴给网页AI。

教师参考工程可以接着运行node tools/course.mjs check；学生起点未填TODO时，其中前端6项任务检查失败是预期。先按第04章操作单补全，再执行check；不要靠关闭测试得到通过。

开两个终端

终端A，从工程根目录启动后端：

node tools/course.mjs backend

终端B，从同一工程根目录启动前端：

node tools/course.mjs frontend

浏览器打开http://127.0.0.1:5178，用本地账号文件中的用户名和密码登录。全程使用127.0.0.1，避免在localhost与127.0.0.1之间混用会话。后端仅监听127.0.0.1:8091，前端代理/api；浏览器不直连数据库。

预期：页面明确写教学模拟和固定教学时钟；两设备分别在线、未知。首次链路不会出现“离线”设备；第06章使用full夹具完成页面三态检查。

修改与停止

前端源码保存后由Vite刷新。后端源码修改后先停止终端A中的进程，再重新build与启动，不能拿旧JAR验证新代码。两个终端分别按Ctrl+C结束各自进程。脚本发现端口被占用会退出，不自动杀进程或修改端口。

第一次下载较慢并不等于代码失败。先记录失败命令和最后一段不含密码的错误，再交给网页AI分析；禁止让模型通过关闭认证、禁用CSRF或更换真实平台地址“解决”问题。

第04章 · 两处修改，验证一次完整读取

本单对应原正文的4学时（1+2+1），不自行换算分钟。教师先在参考工程完成安装和预检，再生成学生工作目录；学生课内修改两个任务块。安装依赖与账号初始化安排课前，不把所有环境下载算进模块二。

起点和停点

起点：student-workspace/已含前后端、登录基础、固定夹具与两处待填任务。第一条链路使用一空间、两设备，数据来自后端读文件，而非浏览器硬编码数组。学生电脑不连接数据库。

停点：登录成功；两设备显示“在线/未知”；屏蔽设备GET后显示失败并保留已有快照；取消屏蔽后重新读取；提交一份脱敏证据与局部Git提交。第06章才验收完整页面三态和自主筛选。

模块一：预测与基线（1学时）

  1. 按启动说明检查工具、目录和两个端口，保存自己的版本输出。不要抄教师验证记录。
  2. 阅读fixtures/selectors.json与fixtures/catalog.json，预测teaching_env_01和teaching_energy_01的online值及显示文字。
  3. 在自己的学生目录按正文步骤初始化Git；先检查.gitignore，本地密码、target、dist、node_modules均不提交。记录当前两个TODO尚未完成。
  4. 浏览器登录后应看到TODO-A待完成信息。此时认证与接口可能已正常，缺的是学生解包任务；先看Network，再判断错误层次。

保持已成功读取的页面不刷新。在Chromium开发者工具中打开命令菜单（Windows Ctrl+Shift+P；macOS Command+Shift+P），搜索Show Network request blocking，打开请求屏蔽面板并启用；新增匹配*127.0.0.1:5178/api/campus/devices*的屏蔽规则。只屏蔽设备GET，不屏蔽登录/空间。点击页面“重新读取”，应出现网络失败并保留旧记录和最后成功时间。取消规则后再次点击，确认恢复。浏览器界面名称以教师预检为准；不要改源码、刷新页面或重启服务来替代这个同会话失败实验。

O01 · 第01章：AI 说完成了，怎样判断

任务：编写设备在线标签函数。输入只能是 true / false / null，分别显示“在线 / 离线 / 未知”。请网页 AI 先给例子，再给实现。

待评回复：

function onlineLabel(online) {
  return online ? '在线' : '离线';
}
// 已覆盖三种状态，可以直接上线。

你的检查：列出三行输入与预期；指出哪个输入能推翻结论。“可以直接上线”的依据是否存在？不要把代码语法合法当成需求满足。

交付：三行测试表、一条修订后的任务提示和 AI 使用记录。若未访问网页，模型栏填“离线构造材料”，不要填 Qwen3。

O02 · 第02章：需求能否验收

任务：把“方便老师管理设备”改写为一条可验收的用户故事。第一版只要求按设备名称关键词筛选；在线状态组合筛选是第06章任务。

待评回复：系统应采用先进技术，界面美观，检索快速，支持各种设备，让所有教师高效管理校园。该需求优先级最高，预计一天完成。

你的检查：它有没有规定使用者、数据范围、关键词为空、匹配和无匹配的结果？“一天”依据什么？重写一条故事和三个观察结果，暂不发明性能指标或教学日历。

交付：故事、三个 Given/When/Then、依赖于设备接口的一项任务；不把“各种设备”展开成新的必修功能。

O03 · 第03—04章：HTTP 成功不等于业务成功

已知输入：网络层已经确认 HTTP 200、JSON 对象和字段基本形状。业务层收到：

{"code":40001,"message":"读取失败","data":null}

待评回复：

function unwrap(payload) {
  return payload.data || { items: [], observedAt: 0 };
}

你的检查：界面会把失败显示成什么？使用 code:0 且 data.items:[] 的正常空列表做对照；再设计一个非零 code 但带旧数据的反例。网络层、业务层分别承担哪项检查？

交付：正常、失败各一条预期与实际记录；失败不能伪装成“没有设备”。

O04 · 第07章：缺失值和有效零

合同：有采样时间而数值缺失，用 null 保留断点；不制造未采样的时刻，不丢弃有效零。

[{"time":1000,"value":0},{"time":2000,"value":null},{"time":3000,"value":1.2},{"time":4000,"value":0.8}]

待评回复：

const samples = raw.filter(item => item.value).map(item => [item.time, item.value]);

你的检查：原始样本数、有效数值数、零值数各是多少？返回的序列丢了什么？图表是否还能解释缺失？先在纸上算，再用语言控制台验证。

交付：4个原始时刻的转换表，禁止只凭一条平滑曲线宣告正确。

O05 · 第08章：按钮隐藏后的接口

合同：只有管理员可以修改设备责任；管理人员只能处理分派给本人的事件。后端作最终判断。

待评回复：

Vue 里把 canAdmin 为 false 的按钮隐藏。
所有登录者都能调用 PUT /campus/device-owners/{deviceId}，
因为不显示按钮就不会发请求。

你的检查：写出同一合法请求由管理员和查看者分别调用的预期；先由查看者用初始版本提交并确认拒绝、数据不变，再由管理员用相同版本提交；或每例独立重置到相同初始状态。除身份外不改变请求体和版本，不能在管理员已写入后拿旧版本当权限反例。怎样同时证明拒绝状态与数据无副作用？本卡是测试设计，不授权向原平台发送写请求。

交付：两行角色对照、主记录和时间线的前后检查项。待独立教学写接口实现后再执行。

O06 · 第09—11章：冲突后自动重试

合同：两个用户都读取版本 3；A 的合法写入提交为版本 4。B 携带旧版本 3 应得到 409，保留输入、回读记录，由人确认下一步。

待评回复：

遇到409就读取最新版本，把旧请求的expectedVersion换成新版本，
一直重试到成功。用户不需要知道发生过冲突。

你的检查：哪个人的判断被绕过？B 是否已经看过 A 的变更？设计一个“B保留输入但不自动提交”的界面过程。说明为什么先返回400并不能证明事务回滚。

交付：一次并发时间线草图和一次回读确认过程；数据库测试完成前只标“预期”，不能标“已通过”。
