# Windows/macOS 共用启动路径

先在教师参考目录跑通，再生成学生工作目录。以下命令均从当前拷贝的工程根目录执行：教师用`campus-ai-course/`，学生用自己的`student-workspace/`，不要切回教师参考目录，路径带空格时用双引号。Windows用PowerShell，macOS用终端。不要在原平台`system/`执行本页命令。

## 一次性准备

安装Node22和JDK17；本资源验证基线为Node22.21.1。需要Git。Maven由项目wrapper下载固定版本，不必额外安装全局Maven。第一次安装依赖需要网络；完整离线机房须由教师另行准备并验证依赖缓存，本资料包不捆绑JDK、Node或node_modules。

```text
node --version
java -version
git --version
node tools/course.mjs doctor
```

doctor检查Node22、JDK17、文件和8091/5178两个端口；不检查教师数据库，也不证明全部实验可运行。运行前必须设置`JAVA_HOME`到JDK17根目录，让doctor与Maven Wrapper使用同一JDK；不要设成bin目录。Windows PowerShell示例：`$env:JAVA_HOME = "C:\你的JDK17根目录"`；macOS示例：`export JAVA_HOME="/你的JDK17根目录"`。替换为自己的已安装路径，两个启动终端都应设置。示例只修改当前终端环境。

若在Windows PowerShell中`npm`脚本受策略限制，使用`npm.cmd`。本项目的`node tools/course.mjs ...`内部会选择对应平台入口，无需修改全局脚本执行策略。

在根目录安装前端依赖并构建：

```text
npm --prefix frontend ci
node tools/course.mjs init
node tools/course.mjs build
```

Windows可将第一行替换为`npm.cmd --prefix frontend ci`。`init`为admin、manager-a、manager-b、viewer生成不同随机密码，仅写入`.private/accounts.json`；用本机编辑器查看。重复执行保留原密码，不打印密码。不要将该文件粘贴给网页AI。

教师参考工程可以接着运行`node tools/course.mjs check`；学生起点未填TODO时，其中前端6项任务检查失败是预期。先按第04章操作单补全，再执行check；不要靠关闭测试得到通过。

## 开两个终端

终端A，从工程根目录启动后端：

```text
node tools/course.mjs backend
```

终端B，从同一工程根目录启动前端：

```text
node tools/course.mjs frontend
```

浏览器打开`http://127.0.0.1:5178`，用本地账号文件中的用户名和密码登录。全程使用127.0.0.1，避免在localhost与127.0.0.1之间混用会话。后端仅监听127.0.0.1:8091，前端代理`/api`；浏览器不直连数据库。

预期：页面明确写教学模拟和固定教学时钟；两设备分别在线、未知。首次链路不会出现“离线”设备；第06章使用full夹具完成页面三态检查。

## 修改与停止

前端源码保存后由Vite刷新。后端源码修改后先停止终端A中的进程，再重新build与启动，不能拿旧JAR验证新代码。两个终端分别按Ctrl+C结束各自进程。脚本发现端口被占用会退出，不自动杀进程或修改端口。

第一次下载较慢并不等于代码失败。先记录失败命令和最后一段不含密码的错误，再交给网页AI分析；禁止让模型通过关闭认证、禁用CSRF或更换真实平台地址“解决”问题。

## 故障定位表

| 现象 | 先看哪里 | 处理和证据 |
| --- | --- | --- |
| doctor提示Node/JDK不符 | node/java版本和JAVA_HOME | 调整本机工具路径后再预检 |
| wrapper或npm下载失败 | 网络、代理、教师依赖缓存 | 记录包名与下载错误，不随意升级依赖 |
| 登录失败 | 自己的accounts.json、当前后端启动目录 | 核对账号，不反复猜密码 |
| 403且提示CSRF | Network中csrf、login、下一次csrf的顺序 | 保留保护并排查token/session，不关闭CSRF |
| 页面报无法读取 | 后端终端、浏览器Network的HTTP与业务code | 首次失败显示错误；已有数据时应标记旧快照 |
| Java进程启动但页面404 | 前端地址是否5178、是否已启动Vite | 本轮JAR不捆绑前端静态页面 |
| 端口已占用 | 本机已有进程及其所属项目 | 核实后手动停止自己的进程，不能随意结束其他项目 |

Windows命令已按平台设计，但仅当Windows实机完成以上流程并留下记录后，才能把该环境标为通过。macOS本次实际结果与浏览器证据另见evidence。
