# 到100%，要拿出什么

终点是本课程的**智慧校园业务模块**：查设备、看数据、维护本地位置、演练处置和责任追踪。页面外观可不同，真实AIRIOT仍选做。百分比是教学检查点，不是工作量统计。

前端页面逐站编写，认证、数据库访问和完整Java后端作为教师公共服务复用；教程带读和检查其中的业务规则。原平台的通用用户、组织、角色配置后台没有在这套教学工程中重新实现，不能把本课程“完成”说成原仓库所有功能逐项1:1。

| 验收项 | 实际做一次 | 通过的样子 |
| --- | --- | --- |
| 设备与空间 | 读取完整目录 | 4空间、16设备、28点来自响应 |
| 台账与详情 | 组合筛选、卡片/表格、点详情 | 16→4→1→0→清空16；详情ID一致 |
| 最新点值 | 从详情选点 | 值、质量、采样时间齐全，可进历史 |
| 本地位置 | 建校园、楼栋、绑定、刷新 | 独立回读仍在，错误引用不能写入 |
| 概览 | 点空间/类型统计 | 台账筛选相同，质量矩阵能追到设备 |
| 能源 | kW与V切换 | 四空间可比，只比同单位，不换算电费 |
| 历史与比较 | 三个范围、多设备、局部失败 | null断开，0保留；失败设备标旧快照和时间 |
| 原始报警 | 正常、空、失败、翻页 | 原始状态等级保留，total正确，全部只读 |
| 角色权限 | admin/manager/viewer分别操作 | 前端入口与后端拒绝规则一致 |
| 演练前半程 | 触发、分派、开始、NOTE | 时间线和版本变化，不能办理别人的任务 |
| 演练关闭 | 恢复、核实、结论、关闭 | 缺条件拒绝，关闭后只读 |
| 责任登记 | A→B，前后各触发事件 | 旧事件不改，新事件跟B，责任时间线可查 |
| 并发冲突 | 两窗口改事件及责任 | 一次成功，旧版本409；保留输入，不自动重放 |
| 筛选与分页 | 换状态、换处理人、翻页 | 换条件回首页，total与列表一致 |
| 接入与审计 | 未配置、模拟历史审计、查看者请求 | 状态如实，管理员只读审计，控制关闭 |
| 刷新失败 | 各读取页失败/重试/离开 | 无重叠轮询，旧值有标记，离页停止 |
| 事务 | 教师独立_test库执行回滚用例 | 主记录和时间线要么同时成功，要么都回滚 |
| 交付 | 同伴解压到新目录运行 | 不借用作者隐藏文件，能走完一件事 |

每项记录“操作、实际结果、证据路径”。没做的写未做，失败的写失败。教师核对必修项后签名，才称课程项目完成。

## 第12站的具体命令

先停止正在运行的后端（回到它的终端按Ctrl+C），设置当前终端JAVA_HOME。在app逐行执行：

```sh
node tools/course.mjs check
node tools/course.mjs build
node tools/progress.mjs verify
node tools/hand-in.mjs
```

`check`检查夹具、普通后端测试、前端类型和单测；普通后端测试中的数据库项目若显示SKIPPED，仍需教师在专用测试库验证。`build`生成本地构建物，不会部署。`verify`只记录当前源码的前端构建结果，不自动签业务验收。

`hand-in`会输出新的交付目录。打开它检查README与源码；Windows右键该目录→压缩为ZIP，macOS右键→压缩。不要直接压缩正在开发的app，因为其中可能包含私密配置和依赖。

同伴：完整解压→用CodeBuddy打开交付工程→设置JDK17与Node22→安装前端依赖→生成自己的本机账号→由教师配置其独立课程库并迁移→build→backend-db→另终端frontend。首次接手不要执行begin或apply去替换交付源码。最后从查设备走到关闭一件本地演练，记录真实失败和修复。
