# 第 02 课：把设备放进台账

本课 4 学时，共 180 分钟。继续使用第 01 课的 `campus-lab`，完成一张能搜索、能筛选、能查看详情的设备表。概览中的三张卡片也会得到数值。

开始前，打开 CodeBuddy 中原来的 `campus-lab`。如果浏览器已经能打开页面，不要重复启动服务；如果打不开且终端 A 已结束，在根目录的 **A-页面** 终端运行 `node tools/serve.mjs`，再打开 `http://127.0.0.1:5188`。本课始终让终端 A 继续运行。

练习资料 `materials/mock-campus.json` 已经准备好。它只有公开的模拟数据，没有真实校园连接和密码。今天要把这份资料用到页面里，不需要启动 Java 或数据库。

## 第 1 步：把练习数据放进自己的前端

**现在在哪：**CodeBuddy 文件区，先点开 `materials/mock-campus.json`。不用逐字看完，找到 `spaces`、`devices`、`points` 三处：它们分别是空间、设备、设备读数。

在 Craft 对话框发送：

```prompt
继续 campus-lab，只完成第02课第1步。先读 materials/约定卡.md 和 materials/mock-campus.json。
创建 frontend/mock-data.js，将公开 JSON 完整转换成可导入的 JavaScript 数据，导出名为 mockCampus。不要编造、删减或修改练习数据。
创建 frontend/data-service.js，导出异步方法 getOverview()、getDevices()、getSpaces()。getOverview返回包含spaces、devices、points、history、alarms的完整练习数据；另两个方法分别返回devices、spaces。每次返回独立副本，页面不要直接改原始mockCampus。
app.js以后统一从data-service取业务数据，不直接导入mock-data。保留现有外观和菜单。在概览底部增加一句“数据方式：浏览器演示（教学模拟）”，读取成功后显示练习数据的设备、空间、点位数量；暂不改上面的三张卡片。
不要请求后端，不把materials整个目录开放到浏览器，不安装依赖。保存文件，不启动服务，不继续下一步。
```

**等到什么：**等 AI 保存并回复完成。左边应新增 `mock-data.js`、`data-service.js`。确认文件位于 `frontend`，然后刷新浏览器。

**自己点看：**打开“概览”，读底部那一句。

**应该看到：**“浏览器演示（教学模拟）”，以及 **16 台设备、4 个空间、28 个点位**。这三个数量是从练习数据数出来的；上方卡片暂时仍是“尚未载入”。

**如果数量不对或页面空白：**只发下面这段，并补充实际显示的数量：

```prompt
第02课第1步预期从公开练习JSON读到16台设备、4个空间、28个点位，实际结果不一致。我将补上看到的内容。请核对JSON转换、模块导入和返回的数据，修复本步问题。不要把16、4、28硬写成显示结果，不修改练习JSON，也不要引入后端。
```

三个数量正确后，进入第 2 步。

## 第 2 步：先让 16 台设备全部出现

**现在在哪：**CodeBuddy 对话框。只处理“设备”菜单中的内容。

```prompt
继续现有项目，只完成第02课第2步。用data-service.js的getDevices和getSpaces，在“设备”页面显示设备表。
每行有编号、设备名称、类型、空间、在线情况和“查看”按钮。编号使用原始d01到d16，空间通过spaceId对应实际空间名称。
类型显示为中文：environment环境、energy能源、facility设施、lighting照明。
online严格为true显示“在线”，严格为false显示“离线”，null显示“未知”。不要把未知当离线。
读取时显示“正在读取设备”；读取失败显示错误和重试按钮；没有设备时显示“没有设备”。这三种情况分开。
保留九个菜单和已有概览。保存文件，不启动服务；本步“查看”按钮可以先不打开详情。
```

**等到什么：**等 AI 修改保存完成。浏览器刷新，点击“设备”。

**自己点看：**看表格底部是否写出当前数量，向下滚动到最后一行。

**应该看到：**16 行设备，编号覆盖 `d01` 到 `d16`；每行有空间名称和中文类型；未知状态写“未知”。“查看”按钮暂时未接上详情，在本步是允许的。

**如果少了设备或未知变成离线：**单独发送：

```prompt
第02课第2步设备表有问题，我将补上少了哪一行或哪一行状态不对。请从getDevices返回值到表格逐项核对，只修复本步的列表显示。保留原始设备ID；online=null必须是未知，不能替换成false。不要重写其他页面。
```

列表正确后，进入第 3 步。

## 第 3 步：加搜索和筛选，找到想看的设备

**现在在哪：**CodeBuddy 对话框。继续修改刚才的设备页，不要另建一张设备页。

```prompt
只完成第02课第3步，在现有设备表上方增加：
名称或编号搜索框、类型下拉框、空间下拉框、在线情况下拉框，以及“清空筛选”按钮。
多个条件一起起作用。搜索前去掉首尾空格；类型和空间使用稳定ID，不用行号。在线筛选有全部、在线、离线、未知。
显示“当前显示X台 / 全部16台”，全部数量也必须根据数据计算，不能写死。
无匹配时显示“没有符合条件的设备”，保留筛选条件和清空按钮。清空后显示全部设备。
不要改动数据，不加入分页或新依赖。保留第2步的加载和失败提示。保存文件，不启动服务。
```

**等到什么：**等 AI 回复完成，刷新浏览器，打开设备页。

**自己点看：**

1. 类型选择“能源”，应剩下 4 台。
2. 在搜索框输入表格里某台能源设备的完整编号，应只剩那一台。
3. 把搜索内容改为 `找不到的设备`，应没有匹配。
4. 点“清空筛选”，应恢复全部 16 台。

**应该看到：**表格和“当前显示”数量一起变化。空结果不会把整个页面清空，清空按钮还在。

**如果多个条件互相覆盖：**单独发送：

```prompt
第02课第3步筛选没有同时生效。我将描述先选什么、再输入什么、实际剩下几台。请只修复设备页的组合筛选和清空按钮，保留加载、错误与空结果提示。不要删除已有筛选项，也不要改练习数据。
```

四个动作都成功后，进入第 4 步。

## 第 4 步：点“查看”，看到同一台设备的读数

**现在在哪：**CodeBuddy 对话框。我们把第 2 步留下的“查看”按钮接上。

```prompt
只完成第02课第4步。继续现有设备页，让每行“查看”按钮打开该台设备的详情区域。按设备原始id查找，不能默认打开第一台。
详情显示编号、名称、类型、空间、在线情况。使用getOverview中的points，筛出deviceId等于本设备id的读数，列出tagId、value、unit、采样时间time、quality。
value为null显示“缺失”，数字0显示“0”；time为null显示“无采样时间”。quality显示中文：fresh正常、stale较旧、missing缺失、invalid无效。保留原字段含义，不把较旧数据写成刚采集。
添加“收起详情”按钮，收起后设备表的筛选条件仍在。本课先不加历史按钮。
保留前面全部功能，保存文件，不启动服务。
```

**等到什么：**等 AI 保存完成，刷新浏览器。

**自己点看：**先选“能源”，打开其中第二行的“查看”。核对详情编号是否等于刚才点击的那行；再收起详情。

**应该看到：**你点哪台就显示哪台；能源设备显示功率 `power` 和电压 `voltage` 两项；收起后能源筛选仍然保留。再选一台环境设备，应能看到温度和湿度。

**如果总是打开第一台：**单独发送：

```prompt
第02课第4步详情与点击的行不一致。我将给出点击行的设备ID和详情显示的ID。请只修复“查看”按钮传递设备ID和详情查找过程，不用数组位置猜设备。保留筛选条件和null、0的区别。
```

详情能对应正确设备后，进入第 5 步。

**等到什么：**等 AI 保存并回复完成。浏览器刷新。
