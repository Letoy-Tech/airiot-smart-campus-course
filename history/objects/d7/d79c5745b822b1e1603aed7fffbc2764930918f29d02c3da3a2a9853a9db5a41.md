# 第07章 实时监测、历史与数据质量

状态：`DESIGNED`｜4 学时（1＋2＋1）｜分模块设计稿，尚未完成配套实验验证。

## 进入条件与学习目标

第06章可按设备进入详情。教师须先制作并验证带可控时钟的 `TeachingMockProvider`、历史样本、错误注入和图表骨架；目前均为待制作教学资源。模拟数据实时刷新不等于真实硬件接入。

完成后，学生能解释值、单位、采样时间、查询时间和质量；实现最新值与原始历史展示；验证零、未知、过期、部分失败及刷新失败，避免图表掩盖数据问题。

## 模块一：认识数据的证据（1 学时）

概念：`value=0` 是有效读数，`null` 表示未知；`observedAt` 是查询观察时间，不能替代点的采样 `time`。质量分为 `fresh/stale/missing/invalid`，由后端依据共享合同判定。来源 `TEACHING_MOCK/AIRIOT` 和 `simulated` 分别说明数据通道与对象性质。

学生手算六个样本的显示结果：有效零、正常值、缺失值、过期值、无效时间和未来时间。讨论 V、kW 与 kWh 的差别：现有数据只支持电压和功率展示，没有累计电量就不能生成费用或节能率。产出数据字典补充及样本判断表。

## 模块二：把最新值和历史连起来（2 学时）

概念：图表是原始样本的表达；空数据不补零，缺失不插值。多个异步查询应各自保留结果和失败状态，避免一个失败清空全部面板。

最小实验步骤：

1. 在未来准备好的教学工程中核对 `/campus/overview` 和 `/campus/history` 合同，统一 epoch 毫秒。
2. 实现或补齐后端质量映射，使用教师样本验证四种质量，不让前端随意猜测在线状态。
3. 在设备详情展示最新点值、单位、采样时间、质量及来源；未知显示明确文字，有效零照常显示。
4. 提供15分钟与1小时历史选择；只查询该设备的合法点，响应保存 `from/to/observedAt/truncated/issues`。
5. 用教师图表骨架画一条曲线，并提供原始样本表；核对首末时间和零值，空历史显示为空。
6. 增加页面内定时刷新，等待一次请求结束再安排下一次；离页停止。刷新失败保留上次成功结果和时间，并显示错误。
7. 注入过期、缺失、接口失败和截断响应，逐项记录页面行为。模拟时钟变化由教学工具控制，不修改系统时间。

产出最新值组件、单点历史视图、刷新逻辑及四类质量证据。查询间隔由教学合同固定，不能每组自行高频请求。

## 模块三：用故障验证展示诚实（1 学时）

概念：验收要判断界面有没有准确表达证据的局限。两人互查：一人选故障样本，一人仅看页面判断发生了什么，再回查网络响应。检查历史截断是否提示、接口失败是否被误报为空，以及旧数据是否仍冒充最新。产出缺陷清单与修正后的对照记录。

```text

约束：时间为 epoch 毫秒；null 不补零；有效零必须保留；原始样本不插值；stale 保留数值并标明过期；source 与 simulated 分别显示。V/kW 不能转成 kWh、费用或节能率。

先指出两份响应的差异，再给小步修改和六项可人工执行的测试。对未知图表库 API 说明需核对工程版本，不凭空编造方法。
```

## 人工检查点与验收表

学生需逐项解释一条历史样本如何成为图上的点，并指出刷新失败后保留的是哪次数据。教师重点检查样本数量、时间单位和失效状态。以下结果须在实验中实际执行。

| 验收项 | 预期 | 证据 |
| --- | --- | --- |
| 零与未知 | 零可见，null 不变零 | 响应及页面 |
| 质量与时间 | 四类质量及采样时间正确 | 固定样本对照 |
| 原始历史 | 点数、时间、单位与样本一致 | 图表及样本表 |
| 失败与截断 | 明示限制，旧数据带最后成功时间 | 故障注入记录 |
| 刷新生命周期 | 无重叠请求，离页不再轮询 | 网络请求记录 |

## 常见错误与定位

- 时间落在1970年：核对秒与毫秒，不用随意乘除修补不明来源。
- 曲线突然落零：检查空值默认值和图表数据转换。
- 有值却质量错误：检查可控时钟、采样时间和后端过期阈值。
- 离页仍请求：检查组件清理和定时任务注册，勿只隐藏界面。
- 概览数量达标但有缺失：区分期望数、返回设备数与有效点数。
