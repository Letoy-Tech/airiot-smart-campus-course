## 第 6 步：亲自走遍九个菜单，为后端准备清单

**现在在哪：**CodeBuddy 对话框。这一步只整理当前前端，不开始生成 Java。

```prompt
只完成第06课第6步。检查当前九个菜单的入口是否接到了实际页面，保持所有业务读写通过data-service.js：
概览、设备、空间、能源、历史、原始报警、演练事件、设备责任、管理。
仅修复遗漏的菜单调用、跨页ID传递或保存后的重新读取，不重写已经完成的页面。
创建notes/06-前端需要的数据.md，按上述九个菜单各写一行：页面显示什么、目前从哪里读、会保存什么、以后哪些事情需要后端检查。如实写当前数据来自公开模拟JSON或浏览器保存，不能写成已接数据库。
不创建backend，不安装MySQL或Redis，不启动服务。完成后列出我需要亲自点击的检查，不代替我报告浏览器通过。
```

**等到什么：**等 AI 保存完成，打开新清单，看看九个菜单是否各有一行。随后浏览器刷新。

**自己点看：**按下面顺序完成一次完整检查。每行做完才勾选，不只看 AI 的回复。

| 菜单 | 亲手检查什么 | 本次应看到什么 |
| --- | --- | --- |
| 概览 | 查看三张数量卡，点能源类型 | 16 台、4 空间、28 点位；进入原设备表 |
| 设备 | 找 d03，再找 d05 | d03 在线未知、温度缺失；d05 功率为 0 |
| 空间 | 查看本组修改的位置，再进设备 | 位置保存；设备属于同一空间 |
| 能源 | 切功率、电压，做一次历史比较 | 只有四台能源设备；单位和数据一起变 |
| 历史 | 从 d05 功率进入 | 同一设备和点位；0 保留，缺失断线 |
| 原始报警 | 搜索再清空，查看设备 | 原状态、等级保留；没有处理按钮 |
| 演练事件 | 打开已关闭事件，再刷新 | 关闭结果、记录和时间线保留 |
| 设备责任 | 查第 03 课的 d01 | manager 和备注保留 |
| 管理 | 管理员查看说明和操作记录 | 模拟标识清楚；真实设备控制与通知未启用 |

**应该看到：**九个菜单都有本课以前实际完成的内容，入口能互相连接；刷新后，空间、责任和演练记录仍在。管理页明确说明当前仍是浏览器演示。

**如果某一行没通过：**只选一行发下面的修复提示，别一次把整张表丢给 AI 重做：

```prompt
第06课第6步有一项没有通过。我将写出菜单名、点击步骤、预期结果和实际结果。请先读取相关现有文件，只修复这条链路并保存，保留其他八个菜单和已有浏览器记录。不生成后端，不重写整个项目。完成后让我重复同一组点击。
```

在 `notes/06-前端需要的数据.md` 后面补上自己的实际结果：哪些通过、哪一项仍未通过、是否借助 AI 修复过。保存一张九个菜单都能辨认的页面截图，以及一张已关闭演练的详情截图。

**接下来：**前端这一轮完成，进入第 07 课。我们将对着这九个已经做出的页面，一项项分析需要后端提供哪些数据，再从一个最小 Java 接口开始。仍然使用同一个 `campus-lab`，不换项目，也不直接导入一套完整后端答案。
