# 页面需要的数据

本文对着已经做出来的九个菜单，逐项写清三件事：页面上有什么、这些内容现在从哪里来、将来要哪个后端接口。
只描述现状与计划，不修改页面，也不生成后端。

## 一、先说清现状

- 当前前端有三类数据来源，不要混着说：
  1. **本机后端 MySQL**：只有设备台账与设备详情里的**设备基本信息**（编号、名称、类别、`spaceId`、在线情况、模拟标记），来自同源 `GET /api/devices`，读的是 `campus_course.devices` 表（Flyway V1 建表并由教学样本初始化）。
  2. **公开练习数据** `materials/mock-campus.json`（由 `frontend/mock-data.js` 载入）：概览、能源、历史、原始报警、演练事件、责任页的设备名称，以及设备详情里的点位读数与历史样本。
  3. **浏览器 `localStorage` 的 `campus-v2-demo`**：空间位置、责任登记、演练事件、演示审计。
- 另有一小部分只存在**内存**里：顶部“演示身份”选择、`data-service.js` 里缓存的空间列表、各页当次读入的读数集合。刷新页面即丢失或回到默认值。
- 没有连接 Redis，也没有真实登录；除设备基本信息外，页面仍是“浏览器演示（教学模拟）”。
- 设备详情里的点位读数、历史、责任，以及空间、能源、历史、报警、事件、管理页，都到第 10–11 课才接后端。
- 所有条目仍为 `TEACHING_MOCK`；不控制实际设备、不发外部通知、不计算累计电量或电费。
- 后端目前只有两个接口：`GET /api/health`（第 07 课）与 `GET /api/devices`（第 08 课，本课暂不校验登录）。

补充几点，避免误读：

- 表中“保存”只指写入浏览器 `localStorage` 的 `campus-v2-demo`，它不是数据库，换台电脑、换浏览器、清缓存就看不到。
- 当前审计只覆盖浏览器里成功的空间修改、责任登记和演练事件动作（含创建）；旧记录没有审计时不补造。
- 前端的角色开关只隐藏按钮和做演示数据层检查；它不是权限保护，真正校验在后端。
- 页面刷新后身份回到管理员；演练事件、空间位置、责任登记不会自动消失，因为它们在 `localStorage` 里，而不是在内存里。

## 三、MySQL 与 Redis 在本课程里各管什么（生活例子）

- **MySQL 像长期保存记录的档案柜。** 设备台账、空间位置、点位与历史、报警、账号、责任登记、演练事件、审计，都属于“明年还要查到”的正式记录，要放进档案柜，按编号归档、允许很多人查同一份、断电也不丢。第 08 课起逐步接入这个档案柜，目前只放进设备和空间两张表，页面只用到了设备基本信息。
- **Redis 在本课程只保存有过期时间的登录凭条。** 登录成功后后端发一张凭条（令牌），放在 `campus:v2:session:` 前缀下，1800 秒后自动作废；凭条过期或 `docker compose restart redis` 之后，就要重新登录。它不存放设备、空间、事件这些业务记录，第 09 课才加入。
- **`localStorage` 像自己桌上的一张便利贴。** 只在这台电脑这个浏览器里有效，别人看不到，清掉浏览器数据就没了。现在页面上的“保存成功”说的是它。
- **`materials/mock-campus.json` 像印刷好的练习册样本。** 只读，全班拿到的是同一份，不会因为你点了几下就改变。
- **内存像写在白板上。** 演示身份、缓存的空间列表、当前页读到的读数，刷新一次就擦掉了，只能重新写。

**缓存、会话、数据库不是同一件事**，不要把它们说成同一个东西：

- **缓存**是同一份数据的临时副本，目的是少读几次、快一点；丢了可以重建，不算数据丢失。本课内存里缓存的概览、历史数据就是这种。
- **会话**回答“你现在是谁”，是一张短期凭条；过期就得重新登录，它不负责保存业务记录。
- **数据库**是正式台账，写进去就该长期存在；丢了就是真的丢数据，要靠事务、备份和权限来保护。

因此正确的说法是：设备基本信息已经是 MySQL 里的记录；空间位置、责任、事件、审计仍在 `localStorage`，点位、历史、报警和其余页面仍用练习 JSON 与内存；Redis 与登录要到第 09 课。每种来源都要按实际说，不能一句“已经连上数据库”盖住还没接的部分。

## 四、后端接口：已完成与计划

第 07 课的后端只有一个健康接口，用来证明“服务起来了”；第 08 课新增一个只读的设备接口：

| 课次 | 路径 | 说明 | 页面影响 |
| --- | --- | --- | --- |
| 07 | `GET /api/health` | 公开，不需要登录、不读数据库，返回 `data.status="UP"`，外层仍为 `{code:0,message:"ok",data:...}` | 顶部“检查连接” |
| 08 | `GET /api/devices` | 用 JdbcTemplate 从 MySQL `devices` 表按 `id` 排序读取；`online` 未知返回 JSON `null`，`simulated` 为 `true`；本课暂不校验登录 | 设备页与详情里的设备基本信息 |

第 08 课数据库侧实情：Flyway `V1` 只建了 `spaces`、`devices` 两张表，并用教学样本写入 4 个空间、16 台设备（`d03` 的 `online` 为 NULL）；迁移只在该数据库第一次使用时执行一次，之后启动只校验。约定卡里说的“MySQL 保存点位、历史、报警”，以及 `GET /api/overview` 读数集合，本课都还没有做。

尚未实现，页面继续显示“浏览器演示（教学模拟）”：

| 课次 | 接口 | 页面影响 |
| --- | --- | --- |
