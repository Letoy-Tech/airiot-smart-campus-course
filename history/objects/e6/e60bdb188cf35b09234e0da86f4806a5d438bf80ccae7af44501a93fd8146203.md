# 第12课：把作品交到新目录，让别人照说明启动

今天完成最后一件事：把你的源码放到一个没有旧配置的新目录，照说明重新启动，再走一遍主要操作。亲手做完，才知道说明有没有漏步骤。

本课4学时，共180分钟。五步建议用时：30、35、50、40、25分钟。

本课仍是本机教学交付，不安排公网发布。建议两人交换“读说明”和“操作电脑”的角色。同一台电脑的新目录重做，与另一台 Windows 或 macOS 电脑真正接手，是不同的结果，记录时写清楚。

**重新开课：** 用 CodeBuddy 打开原 `campus-lab`，新建 C-工具，确认当前位置是原工程根目录。前两步整理说明、导出源码，不需要重启 A、B 或数据库；保留原 `.env`，不要在原工程重新生成口令。到第3步再检查并停止仍在运行的旧服务，然后只启动新目录的独立环境。新目录的 Java 设置、配置生成和启动命令都在第3步给出。

## 第1步：把启动说明写成别人照着就能做的顺序

```text
写明教学模拟、实际已测和未测内容；不要读取或写入口令，不编造通过结果。
把notes中已有的前六课公开文字笔记按课次合并到docs/本组实做记录.md的“前端实做”小节，

只处理我确认可交付的文字，不复制个人截图、聊天记录或账号资料。
```

**等 AI 完成并保存：** 请同伴从第一行读到登录步骤。遇到“进入后端目录”却没有写目录名、“启动服务”却没说哪个窗口，就把这一处补清楚。

**亲自操作：** 在 CodeBuddy 左侧文件树逐个找到 README 提到的文件：配置生成工具、Compose 文件、后端 Maven 启动文件、页面服务工具、公开练习材料。缺文件时先补齐，不立即导出。再打开 `docs/本组实做记录.md`，对照 `notes` 的原笔记，确认前六课已有的实际结果也带进来了；没有做过或没有记录的仍如实保留。

**应该看见：** 说明从安装前提开始，能回答“在哪个窗口、哪个目录、输入什么、什么时候等、什么时候继续”。正文没有把“AI 已生成代码”写成“服务已经在运行”。

**失败时，只发这段修复提示：**

```text
同伴读README到【原句】时不知道下一步怎样操作。
请只把这一段改成：当前窗口、目录、完整命令、预期结果、失败后该做什么。
按现有工程写，不添加未实现的命令或编造已通过记录。
```

**下一步：** 说明可以照着执行后，导出一份不含本机配置的源码。

## 第2步：导出源码，亲自看清楚带走了什么

**现在在哪：** C-工具的工作目录是原 `campus-lab`。A、B 暂时可以继续运行。

**发给 CodeBuddy：**

```text
请生成tools/export-source.mjs，使用Node自带功能，不增加打包依赖。
接受--out参数，只允许输出到本项目.runtime下；输出目录已存在就拒绝覆盖。
按白名单复制frontend、backend/src、backend/pom.xml、Maven wrapper和.mvn、
公开tools、公开materials、compose.yaml、根.env.example、.gitignore、README.md、docs。
所有层级排除.env及.env.*变体（仅保留根.env.example）、.private、.runtime、
.codebuddy、node_modules、target、日志、个人截图和凭据。
检查源路径和输出路径的每一级父目录（含项目根及其更高祖先），拒绝符号链接；只检查路径元数据，不读取上级目录内容。
不读取上级目录，不带完整教师参考。
工具可以在本机读取.env的值仅作泄漏检查，不显示这些值；
如果待导出的文本包含本机口令就停止并仅报告文件名。
文件过大、识别为二进制或读取失败时，不能跳过泄漏检查后继续复制。
输出一份文件清单和每个文件的SHA256，便于接手人确认复制完整。
不要替我运行导出，不把导出成功写成新目录运行成功。
```

**等 AI 完成并保存：** 查看导出工具，确认白名单只包含本项目公开源码与文档。自己的个人资料若放进 `docs`，先移到不导出的个人目录。

**亲自操作：** C、原 `campus-lab` 根目录，两种系统相同：

```text
node tools/export-source.mjs --out .runtime/hand-in-v1/campus-lab
```

用文件管理器打开 `.runtime/hand-in-v1/campus-lab`，显示隐藏文件，检查有 `.env.example` 和 `backend/.mvn`，但没有 `.env`、`target`、`node_modules`。

**应该看见：** 导出目录中有可读源码、启动工具、公开材料和文件清单。看不到你的本机密码，也没有一次旧运行产生的数据库文件。若需要重新导出修订版，把输出改成 `.runtime/hand-in-v2/campus-lab`，不覆盖第一次结果。

**失败时，只发这段修复提示：**

```text
源码导出在【阶段】失败，固定错误是【不含口令的提示】。
请只修复白名单、路径处理或泄漏检查；不要扩大到整个项目或上级目录，
不要忽略检查继续导出，也不要显示匹配到的口令。
```

**下一步：** 导出检查完成后，停止旧服务，再去新目录。

## 第3步：在新目录生成新配置，用独立数据库重新启动

**现在在哪：** 如果原来的 A、B 仍在运行，在各自原窗口按 Ctrl+C；上次下课已停的窗口无需再操作。C 仍在原 `campus-lab` 根目录。打开 Docker Desktop并等引擎运行，接下来查看、停止旧课程容器并启动新环境。

**发给 CodeBuddy：**

```text
请核对README与Compose的同机新目录步骤是否与当前工程一致，不替我执行。
旧项目用默认campus-v2停止；新项目所有Docker Compose命令使用-p campus-v2-handoff。
两个项目不能同时占用5188、8098、23501、23502。
新目录必须来自本次源码导出，不复制原.env，不连接原来的MySQL卷；
新.env只生成一次。相同交付目录再次检查时保留该.env与原项目名。
确认Compose的命名卷没有显式name和external；新卷名应以campus-v2-handoff_开头。
确认mysql/redis不设置固定container_name；已有固定名时仅移除该字段并同步README，其余配置保持原样。
不使用down -v、不删除任何数据库卷、不结束未知进程。
仅修上述命名隔离与README缺项，列出修改文件；不读取.env，不执行Compose或服务。
```

**等 AI 完成并保存：** 若 README 有修订，按第2步导出到新的输出目录；接下来使用最新导出。没有修订就使用 `hand-in-v1`。

**亲自操作，先停旧容器：** C、**原** `campus-lab` 根目录：

```text
docker compose stop
docker compose ps
```

在文件管理器里，先在原项目旁边新建一个确实不存在的空目录 **`campus-lab-handoff`**；若该名字已存在就停下核对，不覆盖或合并。再打开最新公开导出的 `campus-lab`，显示隐藏文件，复制里面全部内容（含 `.env.example`、`.gitignore` 和 `backend/.mvn`）到这个新空目录。

在 CodeBuddy 另开窗口，打开 `campus-lab-handoff`。为它新建 A-页面、B-后端、C-工具三个终端。新窗口不会继承旧终端的临时 PATH：三个终端先各自运行 `node --version`，确认是 22；不符时按第07课已记录的本机安装路径，只在当前终端前置已安装的 Node 22，不改全局默认。B 还需要下面的 Java 17 设置。以下 C 的工作目录都是**新目录根**：

```text
node tools/setup-env.mjs
docker compose -p campus-v2-handoff up -d
docker compose -p campus-v2-handoff ps
docker volume ls --filter label=com.docker.compose.project=campus-v2-handoff
```

等两个服务 `healthy`。最后一条命令只查看卷名：本次 MySQL 卷应以 `campus-v2-handoff_` 开头。若显示旧项目卷名，先在新 C、项目根运行 `docker compose -p campus-v2-handoff stop`，再修正 Compose 的卷声明，不继续使用旧卷。再在新 B 设置 Java 17：

macOS，新 B 从 `campus-lab-handoff` 根目录开始：

```sh
export JAVA_HOME="$(/usr/libexec/java_home -v 17)"
export PATH="$JAVA_HOME/bin:$PATH"
java -version
cd backend
sh ./mvnw test
sh ./mvnw spring-boot:run
```

Windows PowerShell，新 B 从 `campus-lab-handoff` 根目录开始：

```powershell
$courseJdks = @(Get-ChildItem "C:\Program Files\Eclipse Adoptium" -Directory | Where-Object Name -Like "jdk-17*")
if ($courseJdks.Count -ne 1) { throw "请老师确认本机JDK17目录后再继续" }
$env:JAVA_HOME = $courseJdks[0].FullName
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
java -version
Set-Location backend
.\mvnw.cmd test
.\mvnw.cmd spring-boot:run
```

测试失败先修，不继续启动。新 A、`campus-lab-handoff` 根目录，两种系统相同：

```text
node tools/serve.mjs
```

浏览器打开 `http://127.0.0.1:5188`，在“数据方式”选择 **“连接后端”**，手动使用**新目录** `.env` 中的 `DEMO_PASSWORD` 登录 `admin`。即使浏览器记住了上次模式，本步也亲眼确认一次。

**应该看见：** 初始16台设备已准备好，旧项目的个人事件、空间改动不会冒出来。这些是同一份源码重新建立的独立课程数据；登录用的是新配置。使用相同地址不代表仍在访问旧服务，所以要先停原 A、B 与原容器。

**失败时，只发这段修复提示：**

```text
我在新目录执行到【命令或登录】时出现【不含私密信息的错误】。
已停止旧项目A/B和默认Compose；新Compose项目名为campus-v2-handoff。
请检查新目录漏文件、端口、环境导入或项目名，不复制原.env、不删卷，
不要把连接旧服务当作新目录成功。
```

**下一步：** 新目录确实启动后，用它完成一件新事件。

## 第4步：照清单重做，确认交付的是能继续使用的作品

**发给 CodeBuddy：**

## 第5步：交出作品，亲口说明它是怎样做出来的

**现在在哪：** 仍在 `campus-lab-handoff` 窗口，接手操作已完成，实际结果已填写。本步先完成交付说明，再把两份文档同步回原工程，最后导出。

**发给 CodeBuddy：**

```text
请根据我已经填写的实际记录，整理docs/交付说明.md。
```

**等 AI 完成并保存：** 读一遍说明，把“已通过”逐项对照你的记录；未操作的项目写“未验证”。将新目录里的 `docs/交付说明.md` 和 `docs/本组实做记录.md` 都同步回原工程，确认原工程已经包含本次接手结果，再从原工程导出最终版本。最后打开最终导出里的这两份文档，确认不是同步前的旧内容。

**亲自操作：** 确认两份文档已同步，切回**原 CodeBuddy 窗口、原 C、原工程根目录 `campus-lab`**，运行：

**应该看见：** 源码、可照做的 README、交付说明和实际操作记录都在最终导出里；本机配置与口令留在自己的电脑。课程容器已停止，命名卷保留，不使用 `down -v` 删除成果。
